## Hardware and driver ownership

Read [docs/HARDWARE_AGNOSTIC_DRIVER_BOUNDARY.md](docs/HARDWARE_AGNOSTIC_DRIVER_BOUNDARY.md) for any hardware, driver, device, transport or registry work. Core sees opaque capability identifiers (`usb`, `serial.port` and others) and provides generic package/ELF loading, execution contexts, permissions, capability resolution, streams/events and lifecycle. Normal firmware MUST NOT own USB hardware discovery, chip/class/provider selection, physical sessions/transfers/streams, VBUS or silent fallback. Hardware-owning provider ELFs perform full controller/device communication, probe, arbitration, protocol and safe teardown; thin proxies to compiled-in drivers fail the architecture. An isolated bootstrap/recovery port may provide generic CPU/RTOS/storage primitives, never a production fallback. Port compatibility differs by CPU/ABI; compatible new hardware on a given port should need installed drivers/profiles, not firmware code changes. Use RiscRTE branding for framework/packages; CrossPoint for ebook subsystem and compatibility symbols only. Use execution-context-owned opaque, generation-safe handles; installing a manifest does not confer physical access.

## Versions, packages and releases

Every changed distributable application, driver, service or provider MUST bump its own manifest version strictly above its merge-base and latest published lineage in the same PR. Stable `id` identifies upgrade lineage; numeric version is separate from driver ABI/architecture/capability API. Never create `foo-v2` merely to hide an upgrade. Inspect source version and released baseline; report old -> new; match manifest/archive/catalog/installed identity/version. App edits require an `Apps/<name>.json` bump; drivers require their manifests. No unrelated bump for docs-only edits and no claimed automated validation until it exists and ran. Repair old `usb-cdc-acm` versus `usb-cdc-acm-v2` and hard-coded `0.1.0` builder via canonical ID, higher version, safe old-install migration/quiescence/rollback and automated prevention. Read [Apps/AGENTS.md](Apps/AGENTS.md) and [Drivers/AGENTS.md](Drivers/AGENTS.md) as applicable.

All normal release packages are single `.rte.zip` archives and generic catalog entries, with manifest/ELF/resources bundled; install into isolated `/Apps/<id>/`, `/Drivers/<id>/`, `/Services/<id>/`, `/Providers/<id>/` or proven equivalent. Minimal ZIP decoder bootstraps installation offline without ZIP service; ZIP service reuses audited primitives. Reject traversal, name collisions, bombs, corrupt hashes and unsafe replacements. Update launch/resource paths; historical loose sidecars are conversion inputs only.

Only on an **explicit** release request inspect [docs/RELEASING.md](docs/RELEASING.md), `.github/workflows/release.yml`, master/tags/versions/releases. Existing release request uses `[riscrte] version` in `platformio.ini` and `.github/release-request.json` with matching `v` tag. Never publish as a build shortcut. Preserve firmware output outside mutable `.pio`; versioned app `.bin` is OTA/SD at 0x10000 while merged `.bin` is USB at 0x0, never OTA. Qualify and lock final candidate assets **with the owner during the later release-qualification phase**, not after every intermediate commit.
