## Hardware and driver ownership

Read [docs/HARDWARE_AGNOSTIC_DRIVER_BOUNDARY.md](docs/HARDWARE_AGNOSTIC_DRIVER_BOUNDARY.md) before touching hardware, transport, registry, firmware or capability code. Generic RiscRTE core treats all capability identifiers including `usb` and `serial.port` as opaque data. Normal firmware must not perform USB/hardware discovery, chipset/provider selection, physical sessions/streams, transfers, rail power or fallback. Real independently installed ELFs own actual controller/device communication, discovery, state, arbitration, protocol and teardown, potentially consuming other providers' capabilities. Proxy ELFs forwarding to compiled-in hardware are not compliant. Core supplies only generic package/ELF loading, execution contexts, permissions, dependency resolution, streams/events and lifecycle. A minimal isolated bootstrap/recovery port may provide CPU/RTOS/storage primitives, never a silent production driver fallback. Different CPU/ABI can require a new port; compatible hardware on a given port must not require core source edits.

Use **RiscRTE** for runtime/framework/packages/releases. CrossPoint names only ebook-reader features and existing compatibility symbols; T5S3/EPD47 are hardware names; historic `T5*`/`native_*` paths may remain for ABI compatibility. Favor execution-context-owned opaque/generation-safe handles. Hardware permissions do not arise merely from installing an ELF.
