# I²C bus ELF: stable provider API and dependency-safe bootstrap cutover

**Normative, September 18, 2026; specification only.** This is the owner-authorized, narrowly scoped exception to [the hardware-agnostic boundary](HARDWARE_AGNOSTIC_DRIVER_BOUNDARY.md) for U1–U3. It supersedes the earlier proposal that every migrating device ELF could directly import a temporary firmware I²C API. The I²C ELF must exist as the bus provider from the beginning; only its internal bus implementation is transitional. This specification does not claim implementation or hardware qualification.

## Stable architecture from U1 onward

```text
USB host/class ELF ---> power/expander ELF ---requires---> I²C bus capability
Touch/RTC/gauge ELF --------------------------requires---> I²C bus capability
                                                    ^
                                             provides by I²C ELF
                                                    |
                             U1–U2: private, temporary firmware bus primitives
                             U3:    ELF-owned controller and transfer implementation
```

**One provider, one public contract.** The independently installed I²C bus/controller ELF publishes a versioned `i2c.bus` (or existing equivalent versioned bus capability) with bounded bus transactions, instance selection, concurrency/error handling, access control, and provider lifecycle. Other ELFs declare a requirement on that *provider capability*, never on `kernel.i2c`, `Wire`, a temporary firmware symbol, or an implementation-specific fallback. The bus ELF is the **only allowed production caller** of the temporary firmware I²C primitives. It owns the public bus capability, physical-bus policy, client mediation and admission throughout the migration. Its temporary firmware implementation delegates controller initialization and raw transfers only; the firmware cannot inspect client device identity, registers or protocol.

The word *proxy* is permitted **only** for this temporary bus ELF-to-platform implementation boundary. A peripheral ELF that forwards its register logic, power policy, device matching, or physical operation to firmware is still an invalid thin proxy. Firmware must not publish a competing production I²C provider; no alternate per-device firmware bridge may bypass the bus ELF. Generic registry, resolver, streams and package manager treat `i2c.bus` as an opaque dynamically published capability, not a built-in special case.

## Dependency and bootstrap invariants

A power or expander device on I²C may control downstream USB rails or other devices, creating a cycle if full bus activation depends on those downstream power ELFs. Inspect the **actual** T5 Pro board revision, pin routing, safe electrical defaults and power graph before concluding which dependencies are necessary. The I²C ELF's minimal startup may depend on CPU/RTOS/port primitives and verified boot-alive rails, but **must not depend on an I²C-controlled power ELF whose start requires the bus capability**. Resolve genuinely boot-critical pin/clock/controller setup in the narrow platform primitive without implementing peripheral device semantics. Describe the directed graph and fail safely on a real cycle; no speculative rail enables.

Keep one controller/bus owner at a time. During the transitional phase the port adapter owns raw controller calls under the I²C ELF's sole delegation; the bus ELF serializes transactions, owns client handles and mediates contention. No direct `Wire` access, concurrent second controller initialization, recursive dependency activation, transparent failover to firmware, persistent raw pointers into ELFs, or unbounded operations. Any early boot/recovery I²C use must be separately identified and quiesced before ordinary runtime bus ownership; it must not publish a second normal bus or serve installed device drivers.

## Narrow transitional implementation (U1–U2)

Place the temporary primitive in an explicitly named platform/port compatibility module, not in core registry, UI, package manager or USB code. Export it **exclusively to the installed I²C bus ELF's privileged import policy**, with a versioned ABI and an audited allowlist; reject it in power, expander, USB, touch, RTC, gauge, app and other ELF import tables. Its surface should be limited to bounded acquire/release/controller setup and combined address/write/read transactions with finite timeouts, explicit errors, buffer-length limits and safe cancellation/cleanup. Avoid exporting C++ objects, `Wire` globals or indefinite callbacks. The I²C ELF is responsible for mapping consumer transactions to these primitives, bus arbitration, per-client rights, lifecycle and device/instance generation; individual device ELFs retain their own register logic, probes and power-state policy.

Build/package/install the I²C bus ELF and make dependent power/expander and USB ELFs resolve its *normal* provided capability in U1. A missing, disabled, corrupt or failed bus ELF means its capability is absent and dependents fail closed; firmware must not rescue them. An existing already-built I²C ELF may be adapted rather than replaced, but inspect actual linked symbols/manifest/activation before claiming that it meets this contract. The U1 non-USB witness may consume the I²C ELF capability, **not the private firmware primitive**. Retain explicit logging/ledger of temporary ABI use, ownership and its U3 removal criteria. Do not delay U1 USB extraction until the I²C ELF fully implements controller hardware; creating this stable provider boundary is sufficient at this stage.

## Milestone gates

- **U1:** Streams, permissioned provider publication and lifecycle first; installable I²C bus ELF presents the stable public capability and is the **sole** temporary firmware I²C caller; dependent power/expander ELFs and the USB graph consume its capability. USB physical behavior remains in functional ELFs. Full bus-controller extraction is not a U1 gate. Test missing provider, import allowlist and noncyclic activation in software, with hardware proof deferred to owner qualification.
- **U2:** Independent package publishing retains the I²C bus package ID, capability and consumer ABI. Only its internal temporary port dependency remains; upstream package manifests contain no `kernel.i2c` dependency. No new per-device compatibility imports or separate bus installer.
- **U3:** Migrate remaining verified T5 Pro I²C client devices to the same bus capability. Change the **I²C bus ELF's internal implementation** to own controller initialization, pin/clock handling, transfers, arbitration, fault recovery and teardown via appropriate privileged CPU/OS primitives. Preserve its public capability ABI and consumer manifests wherever semantically compatible; **do not require rewriting already-migrated upstream device drivers**. If a provider ABI change is genuinely necessary, use a versioned additive interface and controlled migration, not hidden firmware coupling. Remove its temporary privileged firmware imports and delete/disable normal firmware I²C adapter entry points before U3 Work Complete. Boot-critical isolated recovery code, only if proven necessary, must not serve as a runtime provider/fallback.
- **U4:** Provisioning and the CAM use installed providers and minimal documented ROM/port boot functionality, never the T5-specific transitional firmware API. The one-image CAM proof is unchanged.

## Exclusive cutover procedure and acceptance

Before replacing the bus ELF's implementation, enumerate its consumers and check actual dependency order. Block new bus admissions, quiesce clients, drain or cancel in-flight transactions, revoke old-generation handles, ensure safe rails/pins, and release/deinitialize the temporary firmware controller **before** the ELF takes exclusive controller ownership. Rebind/restart clients through the unchanged provider capability with fresh generation-safe handles. Never run firmware and ELF controllers together; on failure, deny the bus and dependent devices or enter isolated recovery rather than silently restarting the old production adapter. Respect provider code-pinning/quarantine if teardown remains uncertain.

**U1 acceptance:** the I²C ELF is present and publishes the bus; USB/power/expander consumer ELFs have zero direct imports or calls to firmware I²C APIs; only the bus ELF delegates bounded transfers to the temporary adapter; disabling the bus ELF removes the production bus capability. Record the remaining private bridge and its eventual removal. **U3 acceptance:** the *same public bus capability* is backed exclusively by the hardware-owning I²C ELF, no normal firmware I²C implementation or privileged compatibility imports remain, prior client ELFs work without interface changes, and the old adapter never acts as fallback. Hardware verification remains owner-controlled.
