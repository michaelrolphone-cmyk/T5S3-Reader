# U1–U4 execution order — streams first; four milestones

**Normative sequencing; specification only.** Read [stream source audit/allocation](STREAM_PIPE_MILESTONE_ALLOCATION.md), [temporary I²C bootstrap and cutover](I2C_BOOTSTRAP_CUTOVER.md), [UI-optional headless boundary](HEADLESS_RUNTIME_AND_CAMERA_SERVICE_BOUNDARY.md), [U1 ELF verification performance](U1_ELF_LOAD_VERIFICATION_PERFORMANCE.md), [hardware boundary](HARDWARE_AGNOSTIC_DRIVER_BOUNDARY.md) and each milestone below. This dependency order overrides older U1 A–F execution ordering; the authorized temporary I²C exception overrides older requirements for immediate full I²C extraction; U4's one-image proof overrides earlier camera-streaming-service language. No U0, separate stream-release gate, interim hardware tests, UI-as-ELF conversion or automatic merge/release/flash. Actual code, builds and physical results are not established by these specs.

## U1 — finish streams first, then USB and packages

Starts only after owner merges PR #86 and initiates ONE new implementation PR from master. Inspect actual merged v1 byte/v2 record streams, pipes, App Store HTTP transfer, GNSS and `serial.port` implementations. **First implement generic hardware-owning installed-ELF byte/record producer and sink endpoints** in the single registry/capability system: execution-context ownership, generation, rights, cross-context open/connect, bounded buffer and deadlines, revocation, cancellation, safe quiescence and no blocking provider I/O under global stream mutex. Preserve existing stream ABI/callers; protected pipes must enforce downstream permission/purge or fail closed. Non-USB witness uses same mechanism where relevant. No full transform/tee/merge/camera/display/LoRa development now.

**Next:** physical USB/controller/host/class/power ELFs publish generic `serial.port` RX/TX streams; Serial Monitor and programmer consume them with independent baud/DTR/RTS control. **I²C is a root-bus cutover exception:** permit a minimal, explicit and bounded temporary firmware I²C port API for power/expander and other USB-supporting ELFs while dependencies are untangled, as specified in [I²C Bootstrap Cutover](I2C_BOOTSTRAP_CUTOVER.md). Do not make complete I²C-controller ELF takeover a U1 completion gate; a provisional I²C ELF may still be exercised. Firmware must not retain USB hardware/control/class logic, USB device-selection, stream processing or fallback. Record every temporary I²C caller and the U3 retirement plan. **Then:** same bounded streams feed four-kind manager and online/offline `.rte.zip` ingestion, verification, safe extraction/rollback; eliminate fixed driver downloads and special USB catalog, preserve prior App Store transfers. Other U1 work such as signing-only purge can proceed independently. Generic package recovery, streams and provider/service lifecycle must not intrinsically depend on a GUI callback; full conditional UI boot conversion remains U3.

**Mandatory U1 performance correction:** implement [ELF Load Verification Performance](U1_ELF_LOAD_VERIFICATION_PERFORMANCE.md). Do not SHA/MD5 hash installed ELFs during each ordinary button-driven launch, app list, version query, installed-provider discovery or capability lookup. The explicit interim bypass applies only to already-committed installed generations, **not** new download/stage/install, integrity verification, uncertain recovery or permission/ABI checks. Replace the bypass in U1 with a safe install-time verification receipt, coherent invalidation and fast inventory snapshot. Measure launch and inventory latency; U1 is not Work Complete while routine navigation requires whole-ELF hashing. **Yield:** working, responsive generic driver/stream/package architecture with USB device logic in ELFs and only the documented transitional I²C bus primitive remaining where actually needed.

## U2 — independent package sources, reusable streams and headless-eligible roles

After accepted U1 and owner advance: independent owner-controlled package GitHub repo/build/release, source management, updates, provenance, dependency planning and profile-aware system-vs-optional roles. Use U1 generic streams for catalog/ZIP transfer and the same transaction; no separate downloaders. Headless profiles need not select graphical Settings, springboard, display or touch as core. Carry the temporary I²C port ABI only as a declared, versioned transitional dependency for packages actually requiring it; no board-specific catalog or implicit permanent firmware bus provider. Do not implement first-run provisioning, I²C migration or GUI boot refactor in U2. **Yield:** independently shipped packages and profile-aware selection from generic sources.

## U3 — T5 Pro drivers, final I²C ownership, generic GNSS apps and optional firmware UI

After accepted U2 and owner advance: actual fitted T5 Pro display/touch/LoRa/GNSS/SD/power/etc hardware moves into real installable ELFs using U1 generic capabilities, byte/record/event/frame contracts and lifecycle. Migrate I²C-dependent peripherals first through the temporary API where needed, resolve verified power/bus dependency cycles, then transfer exclusive normal I²C controller ownership to its installable ELF and retire all normal-runtime firmware I²C entry points and callers before **U3 Work Complete**. Never run firmware and ELF controllers concurrently or silently fall back on failure; isolate any genuinely boot-critical recovery path. E-paper display uses bounded chunk/owned-frame semantics; LoRa preserves packet boundaries. GNSS UART, pins and rail ownership move out of `GpsKernelIo.cpp`; provider-produced `location.fix.v1` streams progress independently of app polling, and both GPS and GNSS diagnostic apps consume semantic `location.position` without `gps-nmea` hard-coding or `T5GpsApi` firmware dispatch. **UI stays compiled into firmware but initializes only on profiles with available display, and the generic scheduler/manager/services/idle do not depend on UI rendering or foreground app.** T5 Pro GUI continues to work with installed drivers. The actual ESP32-S3-CAM must flash/boot with no Pro or CAM peripheral drivers, no display/SD/UI requirement, stable observable headless idle and recovery. Optional one-way serial diagnostic output, no interactive console. No CAM drivers or provisioning in U3. **Yield:** GUI-capable Pro and stable driverless headless CAM using the same hardware-blind runtime/port architecture without a normal firmware I²C driver.

## U4 — provisioning and one real camera image

After accepted U3 and owner advance: implement declarative first-run/approved-reapply provisioning using the one ZIP package engine, actual verified board/profile and available bootstrap media, authorization and recoverable ledger. Install CAM-specific hardware-owning ELF drivers, activate generic `camera.*` capability, and run a small **headless one-frame capture diagnostic** using an actual output available on the owner's board. Write one real test image that can be retrieved or inspected. U1 stream/owned-frame rules keep memory, DMA, quiescence and file output safe. Existing GUI remains inactive on CAM; T5 Pro retains its GUI. Avoid assuming SD, network or particular sensor before actual board inventory. CAM provisioning must not depend on the retired T5 transitional I²C port. **Yield:** provisioned functional headless CAM proven by one image and a retained functional Pro.

**Not U4 gates:** always-on camera streaming service, multiple frames to an external client, network/Wi-Fi setup, service auto-start, browser dashboard, interactive serial shell or full UI-to-ELF extraction. These can be scoped separately if ever needed; a camera-streaming service remains an example future application, not a required proof. Tests and physical acceptance follow the owner-controlled three-step implementation workflow, never automatic milestone advancement.
