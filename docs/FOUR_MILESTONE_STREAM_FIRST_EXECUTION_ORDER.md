# U1–U4 execution order — streams first; four milestones

**Normative sequencing; specification only.** Read [stream audit/allocation](STREAM_PIPE_MILESTONE_ALLOCATION.md), [shared-chip and rail ownership](SHARED_CHIP_AND_RAIL_OWNERSHIP.md), [I²C bus ELF bootstrap](I2C_BOOTSTRAP_CUTOVER.md), [SPI/UART ELF bootstrap and cutover](SPI_UART_ELF_BOOTSTRAP_CUTOVER.md), [UI-optional headless boundary](HEADLESS_RUNTIME_AND_CAMERA_SERVICE_BOUNDARY.md), [ELF verification performance](U1_ELF_LOAD_VERIFICATION_PERFORMANCE.md), [hardware boundary](HARDWARE_AGNOSTIC_DRIVER_BOUNDARY.md) and each milestone. The shared ownership contract overrides any inventory/table that assigns a single chip, register file, expander output or rail to two independent physical owners. This order overrides older U1 A–F workstream ordering and language requiring immediate native bus ownership or letting peripheral ELFs import firmware bus APIs. Temporary *bus ELF internal* firmware primitives for I²C, SPI and physical UART do not authorize thin device proxy ELFs. U4's one-image proof overrides camera-streaming-service language. No U0, interim hardware tests, UI-as-ELF conversion or automatic merge/release/flash. Specifications do not establish implementation or hardware results.

## U1 — streams, stable I²C provider, USB and shared-chip VBUS, packages

After owner merges PR #86, start ONE implementation PR from current master. Inspect merged byte v1/record v2 streams, pipes, App Store HTTP, GNSS and `serial.port` code. **First complete generic installed-ELF producer/sink endpoints** in the single registry/capability system: execution-context ownership, generation, rights, cross-context connection, bounded buffers/deadlines, revocation/cancellation, quiescence and no unbounded provider I/O under a global stream mutex. Preserve ABI and callers. No optional transform/tee/merge/camera/display/LoRa expansion.

**Next establish the stable I²C bus provider** before converting dependent devices: install its ELF and publish normal versioned `i2c.bus`. The I²C ELF alone may privately delegate bounded raw controller setup/transfers to a temporary firmware port API. Device ELFs require the public bus capability, not firmware I²C imports. Verify noncyclic startup, single controller owner, finite I/O and fail-closed absence. Native controller ownership inside the same ELF belongs to U3.

**Assign actual shared hardware owners in the U1 USB/VBUS power graph, not just chip names.** Source identifies BQ25896 `0x6B` as the USB VBUS provider; its one chip-owning ELF arbitrates OTG versus charger functions and publishes `board.power.vbus` for the host to acquire before starting. It must not race a separate charger ELF owning BQ registers. If actual USB power needs PCA9535 `0x20` outputs, first install one PCA register-owner ELF with exclusive masked pin grants; other functions must later consume that same owner. TPS65185 `0x68` is an EPD-HV/VCOM component on the same I²C bus, **not automatically a USB VBUS prerequisite**. Require a verified dependency graph and safe absence without pulling unneeded display/TPS code into U1. Prevent duplicate register/address/output owners and unsafe shutdown; [shared-chip contract](SHARED_CHIP_AND_RAIL_OWNERSHIP.md) defines physical ownership, scoped capabilities and tests.

**Apply the same bus architecture to SPI/UART without unrelated U1 scope.** Establish versioned bus/provider ABI, import restrictions and reusable ELF/lifecycle primitives; if an actual U1 dependency requires either bus, install its bus ELF first and make it the sole importer of its narrow temporary firmware backend. Otherwise SPI/UART bus package creation, fitted-peripheral conversion and native takeover belong to U3. Hardware UART `uart.port` is different from USB CDC `serial.port`.

Physical USB/controller/host/class/power ELFs then publish generic `serial.port` RX/TX streams; Serial Monitor and programmer consume them with baud/DTR/RTS control. No firmware USB host/class/session/device logic, selection, stream processing or fallback. **Then** use the same bounded streams for four-kind online/offline `.rte.zip` installation, safe extraction/verification/rollback and generic catalog, removing fixed downloads and USB-only catalogs. Signing-only purge can proceed independently. Generic recovery, streams and provider/service lifecycle do not require GUI callbacks; full optional UI boot is U3.

**U1 performance:** [ELF Load Verification Performance](U1_ELF_LOAD_VERIFICATION_PERFORMANCE.md) bypasses repeated full hashing only for ordinary installed-generation launch/inventory, retains install/recovery/explicit integrity and requires generation-bound receipts plus coherent invalidation before Work Complete. Measure latency. **Yield:** responsive stream/package architecture, USB device implementation in ELFs, stable I²C ELF interface, an assigned single-owner USB power path, and no direct firmware bus coupling from peripheral ELFs.

## U2 — independent package sources and exclusive physical identities

After accepted U1 and owner direction: independent package repo/build/release, source management, updates, provenance, dependency planning and profile-aware roles. Reuse U1 streams and transactions. Preserve established bus package IDs, capabilities and consumer ABIs. Only bus ELFs may retain specifically allowed private temporary firmware backends. **Package/profile identities also distinguish physical chip, pin and shared-rail owner from capabilities:** publishing an additional feature cannot install a duplicate driver claiming the same chip/register file/output or rail. Generic admission enforces opaque exclusive resource claims without embedding board register maps in core. No second downloader, premature controller extraction, provisioning or GUI refactor. **Yield:** independent packages without duplicate hardware owners or consumer rewrites.

## U3 — T5 Pro drivers, chip/rail arbitration, bus cutovers, GNSS, headless boot

After accepted U2 and owner direction: migrate verified T5 Pro display/touch/LoRa/GNSS/SD/power and other fitted hardware into functional ELFs. Remaining I²C clients use the existing I²C ELF capability. **PCA9535 `0x20` must have one chip/register owner** used for button input, EPD/TPS control pins and GNSS/LoRa enable; clients receive nonoverlapping masked output grants or copied input/events, never raw second register ownership. **TPS65185 `0x68` has one register/HV/VCOM owner** and one EPD power sequencer coordinates that capability with granted PCA pins. BQ VBUS/charger consumers reuse the U1 BQ owner. **One radio-rail policy owner alone holds PCA IO00**, provides `board.power.radio` leases to GNSS and LoRa, retains the rail while either client is active and never lets one client power off the other. Verify actual board wiring, safe polarities, startup cycles and multi-client failure behavior; no invented hardcoded core chip policy.

Before migrating SPI and hardware-UART device clients, install stable SPI and UART bus/provider ELFs; initial backends may privately delegate *raw* operations to isolated firmware primitives. EPD/LoRa/SD clients depend on SPI as applicable; GNSS depends on hardware UART and the shared rail provider and publishes semantic location streams. Verify bus/power/SD boot, pad mux, UART console and DMA dependencies. Once clients use stable capabilities, replace each bus ELF's internal backend with exclusive native I²C/SPI/UART controller ownership, quiesce/rebind with generation-safe handles and retire all temporary normal-runtime firmware interfaces/imports by **U3 Work Complete**, without a second consumer rewrite. Isolated real module-store/ROM/recovery/one-way diagnostics may remain but never publish production bus capability/fallback. No controller overlap.

E-paper uses bounded frames/chunks; LoRa preserves packets and shared-rail acquisition never authorizes transmission. GNSS UART/pins/rail move out of `GpsKernelIo.cpp`; GNSS ELF publishes `location.fix.v1` independently of app polling, GPS/diagnostic apps consume `location.position` without `gps-nmea`/`T5GpsApi`. UI stays compiled into firmware but optional: scheduler/manager/services/idle do not depend on rendering or foreground apps. Pro GUI works. Actual ESP32-S3-CAM boots without Pro/CAM drivers, display, optional SD or GUI, with stable observable idle/recovery and optional one-way serial diagnostics. No CAM driver/provisioning yet. **Yield:** Pro and headless CAM with no duplicate chip/rail owner or normal firmware I²C/SPI/UART backend.

## U4 — provisioning and one real camera image

After accepted U3 and owner direction: first-run/approved-reapply provisioning through common ZIP engine, verified board/profile/bootstrap media, authorization and recovery ledger. Install only actual CAM-fitted hardware-owning ELFs, activate generic `camera.*`, capture and write **one test image** to a verified output. Memory/DMA/frame lifecycle safe, GUI inactive on CAM/working on Pro. No assumed SD/network/sensor, retired T5 bus primitive, universal T5 chip/rail package or duplicate owner. **Yield:** provisioned headless CAM proven by one image and retained Pro.

**Not U4 gates:** always-on streaming, external client, network/Wi-Fi provisioning, service autostart, browser dashboard, interactive serial shell or UI-to-ELF extraction. Physical acceptance stays owner-controlled; no automatic milestone advancement.
