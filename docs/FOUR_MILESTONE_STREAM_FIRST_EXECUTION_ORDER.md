# U1–U4 execution order — streams first; four milestones

**Normative sequencing; specification only.** Read [stream audit/allocation](STREAM_PIPE_MILESTONE_ALLOCATION.md), [USB contract remediation](USB_CONTRACT_VIOLATION_REMEDIATION.md), [shared-chip and rail ownership](SHARED_CHIP_AND_RAIL_OWNERSHIP.md), [I²C bus ELF bootstrap](I2C_BOOTSTRAP_CUTOVER.md), [SPI/UART ELF bootstrap and cutover](SPI_UART_ELF_BOOTSTRAP_CUTOVER.md), [UI-optional headless boundary](HEADLESS_RUNTIME_AND_CAMERA_SERVICE_BOUNDARY.md), [ELF verification performance](U1_ELF_LOAD_VERIFICATION_PERFORMANCE.md), [hardware boundary](HARDWARE_AGNOSTIC_DRIVER_BOUNDARY.md) and each milestone. **USB contract remediation is a binding current U1 work order and U3 allocation, not an optional review or proof that source has been fixed.** The shared ownership contract overrides any inventory/table that assigns a single chip, register file, expander output or rail to two independent physical owners. This order overrides older U1 A–F workstream ordering and language requiring immediate native bus ownership or letting peripheral ELFs import firmware bus APIs. Temporary *bus ELF internal* firmware primitives for I²C, SPI and physical UART do not authorize thin device proxy ELFs. U4's one-image proof overrides camera-streaming-service language. No U0, interim hardware tests, UI-as-ELF conversion or automatic merge/release/flash. Specifications do not establish implementation or hardware results.

## U1 — streams, stable I²C provider, USB and shared-chip VBUS, packages

Implement on the existing U1 PR #96 (`impl/u1-riscrte`, originally branched after PR #86 merged). Inspect current HEAD and actual linked code; do not create another PR or assume earlier source inventory is still current. **First complete generic installed-ELF producer/sink endpoints** in the single registry/capability system: execution-context ownership, generation, rights, cross-context connection, bounded buffers/deadlines, revocation/cancellation, quiescence and no unbounded provider I/O under a global stream mutex. Preserve byte v1/record v2 ABIs and callers. No optional transform/tee/merge/camera/display/LoRa expansion.

**Next establish the stable I²C bus provider** before converting dependent devices: install its ELF and publish normal versioned `i2c.bus`. The I²C ELF alone may privately delegate bounded raw controller setup/transfers to a temporary firmware port API. Device ELFs require the public bus capability, not firmware I²C imports. Verify noncyclic startup, single controller owner, finite I/O and fail-closed absence. Native controller ownership inside the same ELF belongs to U3.

**Assign actual shared hardware owners in the U1 USB/VBUS power graph, not just chip names.** Source identifies BQ25896 `0x6B` as the USB VBUS provider; its one chip-owning ELF arbitrates OTG versus charger functions and publishes `board.power.vbus` for the host to acquire before starting. **Inspect and eliminate competing normal-runtime BQ register writes and charger initialization in `BoardT5S3.cpp`/`NativeBatteryBridge.cpp`; an installed BQ VBUS ELF plus a resident charger writer violates one-owner even if USB serial works.** Preserve essential early boot/battery safety with only a verified isolated one-way handoff where necessary; firmware battery callers consume the BQ owner's scoped capabilities or fail safely, not silently bypass the owner. BQ27220 is a distinct gauge. If actual USB power needs PCA9535 `0x20` outputs, install one PCA register-owner ELF with exclusive masked pin grants; other functions later consume the same owner. TPS65185 `0x68` is EPD HV/VCOM on the same I²C bus, **not automatically a USB VBUS prerequisite**. Require verified dependency graph and safe absence without pulling unnecessary display/TPS code into U1. Prevent duplicate address/output ownership and unsafe shutdown per [shared-chip contract](SHARED_CHIP_AND_RAIL_OWNERSHIP.md).

**Apply the same bus architecture to SPI/UART without unrelated U1 scope.** Establish versioned bus/provider ABI, import restrictions and reusable ELF/lifecycle primitives; if an actual U1 dependency requires either bus, install its bus ELF first and make it sole importer of narrow temporary firmware backend. Otherwise SPI/UART bus package creation, fitted-peripheral conversion and native takeover belong to U3. Hardware UART `uart.port` differs from USB CDC `serial.port`.

**Complete USB extraction, including the whole provider-to-app path.** Installed USB controller/host/class/power ELFs own device work and publish devices and generic `serial.port` RX/TX streams. Serial Monitor/programmer consume them with baud/DTR/RTS. Remove normal-runtime USB-specific firmware orchestration, host polling, fixed class IDs/VID selection, device/session state, USB-to-registry projection, transport stream shuttle, protocol error-log parsing and firmware fallback in `NativeUsbBridge`, `NativeSerialPortBridge`, `NativeStreamBridge` and helpers. A compatibility label or retained `T5UsbApi` is not an exception if reachable in production. New compatible USB class ELF must load/match/publish with no firmware change. Preserve legitimate generic registry/leases/streams and a **verified exclusive boot-console versus USB-host PHY handoff** in the isolated platform port, not generic serial bridge. Audit dead legacy CDC loader by link reachability. [Specific acceptance and source map](USB_CONTRACT_VIOLATION_REMEDIATION.md).

**Then** use the same bounded streams for four-kind online/offline `.rte.zip` installation, safe extraction/verification/rollback and generic manifest-driven catalog, removing fixed USB eight-package counts, fixed versions/filenames, special USB downloads and latest-release loose asset paths. Driver Manager normal online flow must use the same generic catalog/ZIP engine already used by App Store/Package Manager, preserving recovery/dependencies; offline installed inventory never requires catalog. Signing-only purge proceeds independently. Generic recovery, streams and lifecycle do not require GUI callbacks; full optional UI boot is U3.

**U1 performance:** [ELF Load Verification Performance](U1_ELF_LOAD_VERIFICATION_PERFORMANCE.md) bypasses repeated full hashing only for ordinary installed-generation launch/inventory, retains install/recovery/explicit integrity and requires generation-bound receipts plus coherent invalidation before Work Complete. Measure latency. **U1 acceptance is not just a successful CH34x serial session:** no resident competing BQ operation, hard-coded class dispatcher, USB-specific bridge/projection or fixed distribution, and correct console/host handoff. Run proportionate source/link/import, backpressure, revoke, unplug, ownership and new-class installation checks; log actual results and blockers in [U1 ledger](U1_IMPLEMENTATION_LEDGER.md). **Yield:** responsive stream/package architecture, complete USB extraction through apps, stable I²C ELF interface, one assigned BQ owner and no direct firmware bus coupling from peripheral ELFs.

## U2 — independent package sources and exclusive physical identities

After accepted U1 and owner direction: independent package repo/build/release, source management, updates, provenance, dependency planning and profile-aware roles. Reuse U1 streams and transactions. Preserve bus package IDs/capabilities/consumer ABIs. Only bus ELFs may retain specifically allowed private temporary firmware backends. Package/profile identities distinguish physical chip, pin and shared-rail owner from capabilities: a different feature cannot install a duplicate driver claiming same chip/register file/output/rail. Generic admission enforces opaque exclusive resource claims without embedding board register maps in core. No second downloader, premature controller extraction, provisioning or GUI refactor. U2 is **not** a deferral of U1 generic driver catalog/ZIP or dynamic USB class discovery. **Yield:** independent publishing without duplicate hardware owners or rewrites.

## U3 — T5 Pro drivers, chip/rail arbitration, bus cutovers, GNSS, headless boot

After accepted U2 and owner direction: migrate verified T5 Pro display/touch/LoRa/GNSS/SD/power and other fitted hardware into functional ELFs. Remaining I²C clients use existing I²C ELF. PCA9535 `0x20` has one register owner for buttons/EPD/TPS/radio output; clients receive nonoverlapping masked grants or copied events, not raw duplicate registers. TPS65185 `0x68` has one HV/VCOM owner and EPD sequencer coordinates TPS with granted PCA pins. BQ charger consumers reuse **the U1 BQ owner**, not a second one. One shared radio-rail policy owner alone holds PCA IO00, supplies generation-bound `board.power.radio` leases and never lets GNSS or LoRa turn off the other. Verify fitted wiring, defaults, dependency cycles and fault cases.

Before SPI/physical UART device migration install stable SPI/UART bus ELFs; temporary backends may privately delegate raw operations to firmware. EPD/LoRa/SD depend on SPI where fitted; GNSS requires physical UART and shared rail, publishes semantic location. Verify SD bootstrap, pad mux, UART console and DMA. Once clients use stable capabilities, swap I²C/SPI/UART bus ELF internal backends to exclusive native controller ownership, quiesce/rebind with generation-safe handles, and remove normal firmware imports by U3 Work Complete. Preserve only independently justified isolated boot/recovery/module-store/one-way diagnostics, never normal fallback.

EPD frames/chunks bounded, LoRa packets atomic; GNSS UART/pins/rail migrate out of `GpsKernelIo.cpp`, ELF publishes `location.fix.v1` without app polling, GPS/diagnostic apps consume `location.position` without `gps-nmea`/`T5GpsApi`. Migrate firmware LoRa/SPI and BoardT5S3 device-specific expander/touch/gauge/display/backlight operations to their assigned owners, not additional firmware bridge names. **U3 also explicitly audits the active `Esp32NetworkProvider.cpp` Wi-Fi hardware/connection-policy boundary**: migrate actual Wi-Fi device behavior to installed generic-network provider ELF while isolating only justified minimal immutable CPU/OS/boot-recovery port primitives. SoC-integrated Wi-Fi is not *board-added hardware*, but that does not authorize normal hardware behavior in hardware-blind framework. Preserve U1 online installs and CAM headless/offline boot; U4 Wi-Fi provisioning is not added. Follow [USB remediation U3 allocation](USB_CONTRACT_VIOLATION_REMEDIATION.md).

UI stays compiled into firmware but optional: scheduler/manager/services/idle do not depend on rendering or foreground apps. Pro GUI works. Actual ESP32-S3-CAM boots with no Pro/CAM peripheral packages, display, optional SD or GUI into stable idle/recovery and optional one-way diagnostics. No CAM driver/provisioning yet. **Yield:** Pro/headless CAM with no duplicate chip/rail owner or normal firmware I²C/SPI/UART/device driver backend.

## U4 — provisioning and one real camera image

After accepted U3 and owner direction: first-run/approved-reapply provisioning through common ZIP engine, verified board/profile/bootstrap media, authorization and recovery ledger. Install only actual CAM-fitted hardware-owning ELFs, activate generic `camera.*`, capture and write **one test image** to verified output. Memory/DMA/frame lifecycle safe; GUI inactive on CAM and working on Pro. No assumed SD/network/sensor, retired T5 bus primitive, universal T5 chip/rail package, duplicate owner or deferred U1 USB fix. **Yield:** provisioned headless CAM proven by one image and retained Pro.

**Not U4 gates:** always-on streaming, external client, network/Wi-Fi provisioning, service autostart, browser dashboard, interactive serial shell or UI-to-ELF extraction. Physical acceptance remains owner-controlled, no automatic milestone advancement.
