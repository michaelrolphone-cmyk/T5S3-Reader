# U1–U4 execution order — streams first; four milestones

**Normative sequencing; specification only.** Read [stream audit/allocation](STREAM_PIPE_MILESTONE_ALLOCATION.md), [I²C bus ELF bootstrap](I2C_BOOTSTRAP_CUTOVER.md), [SPI/UART ELF bootstrap and cutover](SPI_UART_ELF_BOOTSTRAP_CUTOVER.md), [UI-optional headless boundary](HEADLESS_RUNTIME_AND_CAMERA_SERVICE_BOUNDARY.md), [ELF verification performance](U1_ELF_LOAD_VERIFICATION_PERFORMANCE.md), [hardware boundary](HARDWARE_AGNOSTIC_DRIVER_BOUNDARY.md) and each milestone. This order overrides older U1 A–F workstream ordering and older language requiring immediate native bus ownership or allowing peripheral ELFs to import firmware bus APIs directly. Temporary *bus ELF internal* firmware primitives for I²C, SPI and hardware UART do not authorize thin device proxy ELFs. U4's one-image proof overrides earlier camera-streaming-service language. No U0, interim hardware tests, UI-as-ELF conversion or automatic merge/release/flash. Specifications do not establish source implementation or hardware results.

## U1 — streams, stable I²C provider, USB, packages

After owner merges PR #86, start ONE implementation PR from current master. Inspect merged byte v1/record v2 streams, pipes, App Store HTTP, GNSS and `serial.port` code. **First complete generic installed-ELF producer/sink endpoints** in the single registry/capability system: execution-context ownership, generation, rights, cross-context connection, bounded buffers/deadlines, revocation/cancellation, quiescence and no unbounded provider I/O under a global stream mutex. Preserve ABI and callers. No optional transform/tee/merge/camera/display/LoRa expansion.

**Next establish the stable I²C bus provider** before converting dependent power/expander devices: install its ELF and publish the normal versioned `i2c.bus` capability. The I²C ELF alone may privately delegate bounded raw controller setup/transfer to a temporary firmware port API. Device ELFs require its public capability, never direct firmware I²C imports. Verify noncyclic startup, single controller owner, finite I/O and fail-closed absence. Native I²C controller ownership inside the same ELF belongs to U3, not U1.

**Apply the same architecture to SPI/UART without adding unrelated U1 scope.** Establish versioned bus/provider ABI, privileged-import restrictions and reusable ELF/lifecycle primitives; if an actual U1 dependency requires either bus, install its bus ELF first and make it the *sole importer* of its narrow temporary firmware backend. Otherwise SPI/UART bus package creation, fitted-peripheral conversion and native takeover belong to U3. Hardware UART `uart.port` must not be confused with USB CDC's semantic `serial.port`. See [SPI/UART cutover](SPI_UART_ELF_BOOTSTRAP_CUTOVER.md).

Physical USB/controller/host/class/power ELFs then publish generic `serial.port` RX/TX streams; Serial Monitor and programmer consume them with independent baud/DTR/RTS control. No firmware USB host/class/session/device logic, selection, stream processing or fallback. **Then** use the same bounded streams for four-kind online/offline `.rte.zip` installation, safe extraction/verification/rollback and generic catalog, removing fixed downloads and USB-only catalogs. Signing-only purge can proceed independently. Generic recovery, streams and provider/service lifecycle do not require GUI callbacks; full optional UI boot is U3.

**U1 performance:** [ELF Load Verification Performance](U1_ELF_LOAD_VERIFICATION_PERFORMANCE.md) bypasses repeated full hashing only for ordinary installed-generation launch/inventory, retains install/recovery/explicit integrity checks and requires generation-bound receipts plus coherent inventory invalidation before U1 Work Complete. Measure launch and inventory latency. **Yield:** responsive generic driver/stream/package architecture, true USB device implementation in ELFs, stable I²C ELF interface and no new direct firmware bus coupling from peripheral ELFs.

## U2 — independent package sources and stable bus ABIs

After accepted U1 and owner direction: independent package repo/build/release, source management, updates, provenance, dependency planning and profile-aware roles. Reuse U1 streams and transactions. Preserve existing I²C and any established SPI/UART package IDs, capabilities and consumer ABIs. Only each bus ELF may retain its specifically allowlisted private temporary firmware backend. No new per-device compatibility import, separate downloader, premature controller extraction, provisioning or GUI refactor. **Yield:** independent package distribution without forcing clients to rewrite for subsequent bus takeover.

## U3 — T5 Pro drivers, all three bus cutovers, GNSS, headless boot

After accepted U2 and owner direction: migrate verified T5 Pro display/touch/LoRa/GNSS/SD/power and other fitted hardware into functional installable ELFs. Remaining I²C clients use the existing I²C ELF capability. **Before migrating SPI device clients or hardware-UART clients, install stable SPI and UART bus/provider ELFs**; their initial backend may privately proxy *raw* transfers to isolated firmware primitives. Display/LoRa/SD devices depend on SPI; GNSS depends on hardware UART and publishes its own semantic location stream. Verify bus/power/SD boot, pad-mux, UART diagnostic-console and DMA dependencies instead of inventing devices. Once consumers are on stable capability interfaces, replace each bus ELF's internal firmware backend with exclusive native I²C/SPI/UART controller ownership, quiescing/rebinding with generation-safe handles. Retire all three temporary normal-runtime firmware interfaces/imports before **U3 Work Complete**; previously migrated peripheral drivers must not need a second rewrite. Preserve only separately justified isolated module-store/ROM/recovery/one-way serial paths, never production bus capabilities or fallback. No controller overlap.

E-paper uses bounded frames/chunks; LoRa preserves packets. GNSS UART/pins/rail move out of `GpsKernelIo.cpp`, GNSS ELF publishes `location.fix.v1` independently of app polling, and GPS/diagnostic apps consume `location.position` without `gps-nmea`/`T5GpsApi` coupling. UI stays compiled into firmware but optional at runtime: scheduler/manager/services/idle do not depend on rendering or foreground apps. Pro GUI works. The actual ESP32-S3-CAM boots without Pro/CAM drivers, display, optional SD or GUI, with stable observable idle/recovery; only optional one-way serial diagnostics. No CAM driver/provisioning yet. **Yield:** functional Pro and driverless headless CAM, without normal firmware I²C/SPI/UART device backends.

## U4 — provisioning and one real camera image

After accepted U3 and owner direction: first-run/approved-reapply provisioning through common ZIP engine, verified board/profile/bootstrap media, authorization and recovery ledger. Install CAM-specific hardware-owning ELFs, activate generic `camera.*`, capture and write **one actual test image** to a verified output. Keep memory/DMA/frame lifecycle safe; GUI inactive on CAM and working on Pro. Do not presume SD/network/sensor before inventory or reintroduce retired T5 bus primitives. **Yield:** provisioned headless CAM proven by one image and retained Pro.

**Not U4 gates:** always-on streaming, external client, network/Wi-Fi provisioning, service autostart, browser dashboard, interactive serial shell or UI-to-ELF extraction. Physical acceptance stays owner-controlled; no automatic milestone advancement.
