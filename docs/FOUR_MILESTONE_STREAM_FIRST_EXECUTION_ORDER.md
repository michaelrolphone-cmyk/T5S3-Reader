# U1–U4 execution order — streams first; four milestones

**Normative sequencing; specification only.** Read [stream source audit/allocation](STREAM_PIPE_MILESTONE_ALLOCATION.md), [I²C bus ELF bootstrap and cutover](I2C_BOOTSTRAP_CUTOVER.md), [UI-optional headless boundary](HEADLESS_RUNTIME_AND_CAMERA_SERVICE_BOUNDARY.md), [U1 ELF verification performance](U1_ELF_LOAD_VERIFICATION_PERFORMANCE.md), [hardware boundary](HARDWARE_AGNOSTIC_DRIVER_BOUNDARY.md) and each milestone below. This dependency order overrides older U1 A–F execution ordering; the I²C specification overrides older requirements for immediate full I²C hardware ownership *and* older language permitting direct temporary firmware I²C imports by peripheral ELFs. U4's one-image proof overrides camera-streaming-service language. No U0, separate stream-release gate, interim hardware tests, UI-as-ELF conversion or automatic merge/release/flash. Specifications do not establish implementation or hardware results.

## U1 — streams, stable I²C bus ELF, USB, then packages

Starts only after owner merges PR #86 and initiates ONE new implementation PR from master. Inspect merged byte v1/record v2 streams, pipes, App Store HTTP transfer, GNSS and `serial.port` code. **First implement generic hardware-owning installed-ELF byte/record producer and sink endpoints** in the common registry/capability system: execution-context ownership, generation, rights, cross-context open/connect, bounded buffers/deadlines, revocation, cancellation, safe quiescence and no blocking provider I/O under a global stream mutex. Preserve ABI and callers. No optional transform/tee/merge/camera/display/LoRa expansion.

**Next, establish the stable I²C provider boundary before migrating its dependent devices.** Package/install an I²C bus ELF which publishes the normal versioned `i2c.bus` capability. For U1 only, that ELF may internally delegate bounded raw controller setup/transfers to a private temporary firmware port API. **It is the sole allowed production caller/importer of that API.** Power/expander and other device ELFs depend only on the I²C ELF capability, never directly on firmware I²C symbols. Verify startup and power cycles, exclusive controller ownership, finite I/O and absent-bus failure. Full I²C controller ownership in ELF is deferred to U3, but the bus *interface and package must already exist* in U1.

Physical USB/controller/host/class/power ELFs then publish generic `serial.port` RX/TX streams; Serial Monitor and programmer consume them with independent baud/DTR/RTS control. Firmware retains no USB host/class/device logic, selection, stream processing or fallback. **Then** the same bounded streams serve four-kind online/offline `.rte.zip` installation, safe extraction/verification/rollback and generic catalog; eliminate fixed driver downloads and USB-only catalogs. Signing-only purge can proceed independently. Generic package recovery, streams and provider/service lifecycle do not intrinsically depend on a GUI callback; full conditional UI boot conversion remains U3.

**Mandatory U1 performance correction:** implement [ELF Load Verification Performance](U1_ELF_LOAD_VERIFICATION_PERFORMANCE.md). Bypass repeated full ELF hashing on ordinary committed-generation launch/inventory hot paths only, preserve install/recovery/explicit-integrity checks, then replace the bypass with generation-bound verification receipts and coherent inventory invalidation. Measure launch/inventory latency. **Yield:** responsive generic driver/stream/package architecture, real USB device behavior in ELFs, and a stable I²C bus ELF with its explicitly temporary internal port delegation.

## U2 — independent package sources, same I²C consumer ABI

After accepted U1 and owner advance: independent owner-controlled package GitHub repo/build/release, source management, updates, provenance, dependency planning and profile-aware roles. Reuse U1 streams and transaction. Keep the I²C bus package ID and public capability stable. Only the **bus ELF** may retain the versioned private temporary firmware import; upstream packages declare its bus capability, not `kernel.i2c`. No new per-device adapter, separate downloader, early I²C controller takeover, provisioning or GUI refactor. **Yield:** independent packages and unchanged I²C consumer contracts.

## U3 — T5 Pro drivers, internal I²C ELF takeover, GNSS and headless boot

After accepted U2 and owner advance: move verified T5 Pro display/touch/LoRa/GNSS/SD/power hardware into functional ELFs via generic capabilities, records/frames and lifecycle. Migrate remaining I²C peripherals against **the same I²C bus ELF capability**. Resolve actual power/bus bootstrap dependencies, quiesce clients and exclusively hand off the physical controller from the temporary firmware implementation to a hardware-owning implementation **inside the existing I²C ELF**. Retire normal firmware I²C entry points and privileged imports before U3 Work Complete. Previously converted power/expander/other client ELFs must not need another migration or API change solely because the bus implementation changed. No overlapping controller ownership or fallback.

E-paper uses bounded owned-frame/chunk transfers; LoRa preserves packets. GNSS UART/pins/rail move out of `GpsKernelIo.cpp`, provider publishes `location.fix.v1` independent of app polling, and GPS/diagnostic apps consume semantic `location.position` without hard-coded `gps-nmea`/`T5GpsApi`. UI stays in firmware but is optional at runtime; scheduler/manager/services/idle do not depend on rendering or foreground apps. Pro GUI remains functional. Real ESP32-S3-CAM must boot without Pro/CAM drivers, display, SD or GUI, with stable observable headless idle/recovery and optional one-way serial diagnostics. No CAM driver/provisioning in U3. **Yield:** functional Pro and driverless headless CAM without runtime firmware I²C.

## U4 — provisioning and one real camera image

After accepted U3 and owner advance: declarative first-run/approved-reapply provisioning via the common ZIP engine and verified board/profile/bootstrap media, authorization and recovery ledger. Install CAM-specific hardware-owning ELFs, activate generic `camera.*`, capture and write **one real test image** to a verified available output. Keep memory/DMA/owned frame lifecycle safe; GUI remains inactive on CAM, active on Pro. Do not assume SD/network/sensor before inventory or reintroduce transitional T5 I²C primitives. **Yield:** provisioned headless CAM proven by one image and retained functional Pro.

**Not U4 gates:** always-on streaming, external network client, Wi-Fi provisioning, service auto-start, browser dashboard, interactive serial shell or UI-to-ELF extraction. Physical acceptance remains owner-controlled; no automatic milestone advancement.
