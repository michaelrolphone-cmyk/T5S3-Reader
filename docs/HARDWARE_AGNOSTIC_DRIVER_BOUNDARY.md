# RiscRTE hardware-agnostic runtime and driver ownership contract

## Authority, target and temporary bus migration

**Normative target architecture.** Read after [RISCRTE_PLATFORM_SPEC.md](RISCRTE_PLATFORM_SPEC.md) and before hardware, transport, driver, registry or stream specs. Firmware hardware implementations described in historical documents are legacy facts, not design precedent. The **only authorized transitional bus-backend exceptions** are [I²C bus ELF bootstrap](I2C_BOOTSTRAP_CUTOVER.md) and [SPI/UART bus ELF bootstrap](SPI_UART_ELF_BOOTSTRAP_CUTOVER.md). Their *installed bus ELFs*, not peripheral drivers, exclusively call narrowly allowlisted temporary firmware raw controller primitives until U3 native cutover. No implementation or hardware qualification is claimed by these documents.

## 1. Hardware-agnostic core; actual functionality in ELFs

The generic RiscRTE core MUST NOT know what USB, SPI, I²C, hardware UART, GNSS, LoRa, displays or other devices are beyond opaque dynamically published capability identifiers. It MUST NOT enumerate a transport, select a chipset/class/VID/PID, manage host sessions, interpret register maps, implement device protocols, own normal device power policy, expose device-specific firmware bridges, or silently substitute for an absent ELF. Provider ELFs perform real device discovery/probing, matching, device/endpoint claims, register and protocol operations, configuration, power policy, transfers, synchronization, hotplug, failure recovery and safe teardown. ELFs may consume lower-layer provider capabilities rather than duplicate their implementations. An ELF that merely encodes requests or forwards *device behavior* to compiled firmware is not a completed driver conversion.

**Specific temporary root-bus exception:** the installed I²C, SPI or hardware-UART **bus ELF** MUST publish the production versioned provider capability and own public client mediation, instance/session/lease logic and lifecycle from the start. While untangling dependencies, and only if actually needed, **that bus ELF alone** may import a narrow, versioned, bounded firmware CPU/board-port backend for its own raw controller setup and transfers. Each corresponding port primitive is import-allowlisted for its one matching bus provider, never for power, expander, GNSS, display, LoRa, SD, USB class, application or other peripheral ELFs. Port code MUST NOT implement device register policy, NMEA, packet framing, class selection, device-specific recovery or publish a competing `i2c.bus`, `spi.bus` or `uart.port` provider. The bus ELF cannot mask a missing/failed ELF with firmware fallback. The bus-level proxy exception does not authorize new per-device firmware APIs or make a compiled bus a permanent core service.

U1 MUST establish the stable installed I²C bus ELF because the USB power/expander chain uses it; native I²C controller ownership is a U3 gate, not U1. U1's generic provider/stream/privileged-import mechanisms must also support SPI/UART without special core logic, but SPI/UART bus ELFs are installed in U1 only if a verified U1 dependency actually needs them. U3 installs their bus ELFs **before** moving SPI/UART consumers, optionally uses private temporary raw backends during consumer migration, then changes the **existing bus ELFs' internal backends** to native hardware ownership and removes all three normal-runtime temporary APIs before U3 Work Complete. U2 retains public bus IDs/contracts unchanged. U4 cannot require retired T5 transition calls. Preserve an isolated and demonstrably necessary boot-module-storage/ROM/recovery/one-way diagnostic port path where relevant; it does not publish a production provider or operate concurrently with an exclusive ELF owner. USB CDC's semantic `serial.port` is not the hardware `uart.port` controller.

## 2. Permitted generic runtime and port roles

The compiled core may provide generic ELF loading/linking, package admission/versioning, dependency and capability resolution, execution contexts, rights/consent, opaque handles, resource accounting, lifecycle, scheduling, bounded streams and records, event journal, VFS/module access, generic failure/recovery, and memory/executable-memory primitives. It treats capability strings as opaque keys and has no hardware-name dispatch switch. A software lease is not ownership of a physical bus or rail. Lease acquire/release invokes provider-defined generic lifecycle/dispatch rather than implicitly resetting hardware. Drivers must quiesce actual tasks/IRQ/DMA and callbacks before their code or dependent buffers are unmapped; uncertain teardown pins/quarantines safely instead of invoking freed code.

A minimal separately identified CPU/port bootstrap may configure CPU, memory, loader and *truly required* module store/recovery. Transport-neutral privileged OS/CPU imports may supply task, memory, interrupt, cache/DMA and opaque resource-token primitives without containing device behavior. The three explicitly constrained transient bus backends above are the sole temporary runtime hardware-controller exceptions; they reside outside registry, resolver, stream routing, package manager and GUI code. Do not turn a debugging console or recovery USB/UART/SD implementation into a normal driver or hidden fallback. Moving to a different CPU/ISA may require another port; adding a compatible peripheral should require an ELF/profile, not core changes.

## 3. Capability composition and dependency cycles

Provider manifests declare versioned requires/provides and profile data. An illustrative graph assembled dynamically:

```text
Serial Monitor -> serial.port <- USB CDC ELF <- usb.host <- USB host ELF
                                                    |
                                                    optional board.power
                                                             |
                                                     power/expander ELF
                                                             |
                                                i2c.bus <- I²C bus ELF
GNSS ELF -> uart.port <- UART bus ELF
LoRa ELF -> spi.bus <- SPI bus ELF
```

Each bus/provider ELF publishes normal capability records; only its own private backend changes during migration. Drivers can compose capabilities and publish many instances. Generic core sees IDs, dependency edges, versions, rights, owner contexts, leases and generations, not physical identifiers, pins, transport behavior or device priority. Adding a new compatible class/chipset must not require a firmware switch/capability enum/build flag or special catalog entry. A controller/provider ELF arbitrates actual shared bus access, or an opaque port resource lock enforces exclusivity while its bus ELF delegates to the temporary backend. Check real power/clock/pin boot prerequisites; an I²C/SPI/UART provider must not depend on a device requiring that bus unless an independent safe bootstrap exists. Do not confuse USB CDC virtual serial with the MCU UART.

## 4. Discovery, registry, ownership and authorization

Generic registry accepts bounded provider-published arrivals, changes, loss and removal; it does not enumerate USB, parse descriptors, choose GNSS sources or poll a transport. Drivers and optional installed discovery providers own probing. Validate record size, generation, rights and publication origin; marshal callback mutations safely. Leases and streams belong to execution contexts and revoke on provider loss. Provider ELFs own hardware sessions, actual contention and quiescence; two drivers never initialize shared controllers independently. Privileged raw bus backends require an explicit matching bus-ELF-only import policy, per-instance exclusive ownership, finite timeout/size and cancellation. Metadata or package installation grants no hardware rights. Native ELFs are not by themselves memory-isolated. Do not restore package signing; preserve independent loader/import and authorization checks.

## 5. Versioned ABI and safe bus takeover

One generic driver root, manifest requires/provides and versioned provider interface tables/dispatch shall support probe/start/suspend/resume/stop/remove where applicable. Provider/consumer roles may share an ELF. Cross-ELF handles, buffered data and events are opaque or copied, generation-safe, bounded, and never reference unmapped code. Generic streams may own queues/backpressure; providers perform real I/O. Individual I²C/SPI/UART consumers use only their provider's stable versioned API, not `Wire`, global `SPI`, `HardwareSerial` or private firmware symbols.

For each physical bus controller's native cutover: audit consumer and boot graphs, suspend admissions, quiesce/drain or cancel clients, revoke old-generation operations, release/deinitialize firmware controller and safe-state pins/rails, then exclusively initialize controller within the **same installed bus ELF**. Rebind consumer contexts through stable API with fresh handles; no concurrent controllers, unbounded waits or fallback on failure. Remove production firmware backend symbols/import grants only when takeover succeeds. A separately justified boot-only recovery path remains isolated and cannot simultaneously own the bus. The U3 gate covers normal-runtime I²C, SPI and UART individually; record any verified independent instances or ROM/console reservations.

## 6. USB migration acceptance

Existing USB host/controller/class/power/CDC/CP210x implementations and `NativeUsbBridge.cpp` must be inspected as actual legacy source, not copied as architecture. A genuine U1 conversion requires operational USB host enumeration, power/device selection, interface/endpoint management, transfers, serial line control, hotplug and recovery in functional ELFs; the core merely routes generic capability/stream/lifecycle operations. USB CDC and alternative `serial.port` providers register without new firmware source. Remove/disable an ELF: capability disappears, handles revoke and no compiled USB fallback works. Check multiple providers, disconnect/reconnect, safe teardown, missing/corrupt package, permission failure and no implicit boot-time power enable. Static/link checks reject reached firmware USB host/class/VID/PID and special catalogs outside isolated boot/ROM paths. The allowed I²C bus ELF's temporary private raw backend does not count as firmware USB logic. SPI/UART port exceptions apply **only if a real U1 dependency requires their bus ELFs**, never as a blanket USB loophole. Physical USB behavior remains pending owner qualification until tested.

## 7. Migration rules and review gate

Read [I²C Bootstrap Cutover](I2C_BOOTSTRAP_CUTOVER.md), [SPI/UART Cutover](SPI_UART_ELF_BOOTSTRAP_CUTOVER.md), [Four Milestones](FOUR_MILESTONE_STREAM_FIRST_EXECUTION_ORDER.md), [Runtime Driver Architecture](RUNTIME_DRIVER_ARCHITECTURE.md), and relevant SDK/device specifications. Record target requirements first, then label unreached implementation `CURRENT/LEGACY, NONCOMPLIANT` without presenting it as target. No new hardware-specific core bridge or per-device firmware imports. A new bus provider may expose a versioned SDK without the generic resolver knowing what it means. U1 can finish with the narrow I²C backend; U3 cannot finish while any of the three temporary **normal-runtime** backends remain. If removing a peripheral ELF leaves its device functioning normally through firmware, that peripheral was not modularized. If removing a bus ELF leaves the ordinary bus capability functioning through firmware, the bus was not modularized. If introducing a new compatible device requires a firmware hardware patch, the core is not hardware agnostic. Source/build evidence and owner hardware qualification must be reported separately.
