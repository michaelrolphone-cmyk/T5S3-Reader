## U1 acceptance: prove end-to-end rather than rename the bridge

1. **Provider-driven dynamic discovery:** a newly installed compatible USB class ELF, including a fourth test class/package, can be admitted, match/probe, bind, publish device arrival/removal and semantic `serial.port` without editing firmware, a fixed VID/ID array or a USB-specific dispatcher. Class ELFs own protocol and class selection; host ELF owns enumeration/host work. Generic core only loads/manages opaque provider descriptors, resource rights, event registry, streams and lifecycle. Missing/broken class or host fails closed. No implicit fallback to firmware CDC/host.
2. **Serial app path:** Serial Monitor and ESP ROM programmer acquire authorized `serial.port`, use bounded RX/TX streams and independent baud/DTR/RTS, survive partial reads/writes, buffer saturation, unplug/replug and cancellation without losing accepted TX bytes or accepting RX beyond capacity. No `T5UsbApi` or `open_usb` in normal app path; temporary ABI stubs may be present only if uncallable for hardware. Ensure no blocking USB/SD/provider transfer occurs while holding global stream or registry locks.
3. **Physical resource ownership:** installed I²C bus ELF only temporary firmware I²C importer; exactly one BQ `0x6B` chip owner while USB/VBUS/charging/telemetry paths execute. Verify board battery initialization and read calls cannot reset charger, disable OTG, race with or bypass ELF. Host obtains `board.power.vbus` before controller start; stops safely and relinquishes it after quiescence. If a boot-critical initialization genuinely precedes the module store, explicitly inventory a **one-way, isolated bootstrap handoff** that relinquishes BQ before the ELF claims it; no boot-loop, parallel controller or ongoing resident normal-runtime charger implementation. Preserve power/fault fail-closed/quarantine rules; do not infer actual board wiring from an I²C address.
4. **Exclusive PHY handoff:** audit USB-host versus console pad/PHY ownership; controller ELF and boot/console platform port coordinate exclusive lease, release and restore, including failed start/stop and recovery. Preserve working CAM serial/boot sequence, but no `Serial.end()/begin()` policy in generic USB/serial bridge.
5. **Distribution and observability:** generic package index/ZIP for application/driver/service/provider with offline installed inventory independent of catalog, pinned release asset integrity, rollback and unchanged active driver on failure. Install a new USB class provider with manifest/asset changes only, **no firmware or fixed-exporter edit**. Diagnostics are structured, not parsed from USB-tagged log strings. Preserve canonical `usb-cdc-acm` lineage, update changed manifests/apps and resolve reported compile/link defects.
6. **Evidence:** record actual build/link and symbol reachability (including old CDC), import and hard-coded-ID/catalog scans, host tests for missing providers/duplicate BQ ownership/console handoff/reconnect/revocation/backpressure, packaging/release-equivalent artifact and checks, and owner hardware CH34x outcome separately. Do not equate a successful CH34x session, file removal, manifest status or host fixture with full architecture acceptance. Any unresolved item remains explicit in `docs/U1_IMPLEMENTATION_LEDGER.md`; no Work Complete while U1 blockers remain.

## U3 acceptance and milestone guardrails

By U3 Work Complete, native I²C/SPI/UART bus ELFs exclusively control normal hardware, and firmware GNSS/LoRa/board-added peripheral implementations are retired. PCA9535, TPS65185, BQ and radio-rail owners retain the single-owner rules; GNSS and LoRa share rail leases; EPD HV/VCOM sequencing remains correct. GNSS apps consume generic `location.position` streams. Audit integrated Wi-Fi firmware behavior as an **additional explicitly tracked U3 boundary item**: the generic framework remains hardware-blind, while truly unavoidable boot/recovery/CPU primitives are named, bounded and isolated; Wi-Fi device behavior must not be silently classified as generic runtime just because its radio is SoC-integrated. U4 remains declarative provisioning and one actual CAM image, **not** a deferred USB fix or Wi-Fi provisioning/streaming milestone.

**Precedence and scope:** This document refines U1 Workstream D and U3's 'integrated Wi-Fi excluded from board-added conversion' wording: Wi-Fi does not count as a *board-added* part, but its **active driver/policy boundary is still tracked in U3**. USB-specific logic may not be retained in firmware under a 'compatibility' label when reachable by normal production. Minimal boot/ROM/recovery and exact owned I²C temporary backend exceptions survive only under their independently defined contracts. Respect the existing three-step workflow, branch and owner controls.
