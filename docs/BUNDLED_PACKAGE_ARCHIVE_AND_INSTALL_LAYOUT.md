# U1 bundled package archive and package-owned installation layout

**Status:** Normative U1 implementation and acceptance requirement, September 18, 2026. **Not implemented by this document.** Read [RiscRTE Platform Specification](RISCRTE_PLATFORM_SPEC.md), [ordinary package format](RISC_PACKAGE_FORMAT.md), [stable package identity and version policy](PACKAGE_IDENTITY_VERSION_POLICY.md), [Unified Package Manager](UNIFIED_PACKAGE_MANAGER_MVP.md), [U1 milestone](NEXT_HARDWARE_TEST_MILESTONE.md) and [future provisioning](DEPLOYMENT_PROVISIONING.md). This user-authorized addition **expands U1**, rather than becoming a deferred provisioner or an independently merged/owner-tested intermediate milestone. Preserve the working ordinary unsigned transaction, provider admission, loader permission and recovery controls. Do not reinstate the unwanted signed RISC-PKG implementation under a ZIP/archive name.

## 1. Required outcome

A package is **one downloadable/copyable ZIP-compatible archive**, not an `.elf` plus a separate `.json` manifest and other independently distributed files. The archive carries one ordinary package manifest, any executable(s), ABI/import metadata and an arbitrary bounded tree of declared supporting resources: icons, fonts, images, layouts, configuration defaults, dictionaries, data files or other package-owned assets. A resource-only or service package need not contain an ELF unless its kind/runtime contract requires one. Source folders may contain multiple files; the publisher emits exactly one package archive per `(kind, stable id, version, target)` and a generic discovery catalog pointing to that archive. The installed form is an **extracted, verified, per-package directory**, never a loose shared ELF/manifest pair or an ELF executed in place from the downloaded archive.

Use a documented ZIP-compatible `.rte.zip` distribution suffix (e.g. `driver-usb-cdc-acm-0.2.0-xtensa-esp32s3.rte.zip`); the package manager identifies valid input by checked format plus manifest, not filename alone. The filename is only a transport label. Use a stable `id` and independently increasing `version` from the manifest, never `-v2` forks to represent implementation revisions. Do not confuse this unsigned ZIP container with the deprecated signed RISC-PKG experiment. Historical release files remain immutable.

## 2. One archive format and manifest authority

A versioned ordinary schema (e.g. schema 2, final number chosen after inspecting current parser) resides at the archive root as `.package.json`. It retains existing kind, ID, package version, architecture/ABI/runtime requirements, dependencies, artifact entry point and item size/SHA-256 semantics. Extend `entries` to cover **relative, nested, package-owned paths** and file type/role as required; do not replace the manifest with a second ZIP-only identity or unversioned ad-hoc metadata. Every file in the archive other than ZIP structural metadata must be declared or explicitly allowed by a narrowly specified schema rule; no hidden extra executables, scripts or files. The directory tree is deterministic, with no user-specific absolute paths or build-temporary files. Executable entry points resolve only beneath the package root; resource lookup uses the package root or a scoped package-resource API, not hard-coded `/Apps/foo.elf` or global `/sd` paths.

ZIP reader MUST parse the central directory and local headers consistently, validate archive boundaries, entry count, cumulative declared and actual uncompressed sizes, compression ratios and per-entry limits before writing. Support at least stored and bounded DEFLATE entries if supported by the selected audited library. Reject unsupported encryption, malformed ZIP64/multidisk/overlap/data descriptors or other features unless deliberately implemented and tested. Reject absolute paths, `..` components, empty/ambiguous names, backslashes/path normalization collisions, duplicate case-folded names where filesystem requires it, embedded NUL/control characters, symlinks, hardlinks, device files and unexpected executable flags; refuse extraction outside the private stage root. Use streaming reads/decompression with bounded RAM and bounded filesystem utilization; ZIP bombs, CRC mismatch, truncation, unexpected extra bytes, SHA-256 mismatches and missing/extra manifest entries fail without changing the installed generation. CRC-32 is ZIP transport checking; SHA-256 is package content consistency, neither implies a trusted publisher. Validate decompressed bytes in the owned staging tree and revalidate exact ELF/ABI/import metadata via the existing independent manager/loader path before activation.

The host packer MUST read actual source manifests and produced payloads, validate unique identities/versions and produce reproducible archives with normalized paths, ordering, timestamps and permission flags. The release catalog stores ONE archive asset name/size/SHA-256 per package plus manifest-derived discovery metadata. Catalog and archives are pinned to one immutable release snapshot. Do not keep the old fixed-four-asset online driver intake, separate App Store ELF/JSON downloads, USB-specific catalog or a second archive publication pipeline. A genuinely new app/driver/service/provider package joins without editing core code, a list of seven drivers or the packer source.

## 3. Installed directory ownership

Install each kind using the **same generic path-mapping and transactional engine** with a package-owned extracted directory:

```text
/Apps/<stable-id>/         .package.json, executable(s), resources/...
/Drivers/<stable-id>/      .package.json, executable(s), resources/...
/Services/<stable-id>/     .package.json, executable(s), resources/...
/Providers/<stable-id>/    .package.json, executable(s), resources/...
```

These are desired layout examples; an existing canonical mount prefix may be retained if verified and consistently documented. All four kinds MUST have equivalent per-ID directories. The package manager alone owns deployment metadata, staging, backup, commit, installed inventory and clean uninstall inside that directory; the app/driver/service consumes its own resolved installed root through an execution-context-safe read-only/scoped resource handle. The top-level `/System` namespace is separately owned by RiscRTE under [RiscRTE System Storage Layout](SYSTEM_STORAGE_LAYOUT.md) and MUST NOT be used as an alternate package install root, package resource tree, or user-content location. Keep mutable user/application data in an independent durable namespace so an update/uninstall or rollback never silently wipes it. No executable or support file may overwrite another package's files. Folder names derive from validated canonical IDs, not display names or ZIP-provided paths; installed inventory is manifest-based, not a blind directory enumeration granting code execution.

Preserve existing transaction/recovery semantics: stream archive to an owned download stage, inspect manifest and dependency plan without executing, safely extract/verify in a new generation tree, check free space for archive + staging + backup, refuse unsafe in-use replacement, atomically commit whole **directory generations**, and preserve the previous verified generation for recovery. Interruption at download, extraction, verification, migration, rename, uninstall or activation must leave the previous generation usable or an explicitly diagnosed recoverable state. Never partly expose a new ELF paired with old resources. Preserve mapped ELF and provider quiescence pins, quarantine on uncertain IRQ/DMA/callback cleanup and do not force-unload a physical driver. Clean only manager-owned generations after validation.

## 4. ZIP service and unavoidable installer bootstrap

Provide an independently installable, general-purpose **ZIP archive service** exposing a versioned generic capability (e.g. `archive.zip@1`) for authorized application/service archive listing and bounded extraction; optional archive creation can be added only if justified by this milestone's actual package tooling. It must use the same audited ZIP library/validation primitives as packaging. The system's **minimal ordinary package installer must be capable of unpacking a ZIP before this service is installed**—otherwise a fresh SD cannot install the ZIP service itself, offline drivers, or the package manager's own update. Place the minimal bounded archive decode/extract primitive in a transport-neutral, non-hardware package bootstrap/library that the service reuses or wraps; do NOT create two competing full installers, a firmware ZIP device driver, a permanent dependency on app launch, a service-specific privileged loader, or an implicit requirement to have networking. The ordinary package manager remains the sole authority for package preflight, installation and transaction. Service access to unrelated user ZIPs is mediated by scoped file handles, not blanket filesystem permissions. If an independently installable service cannot safely reuse the bootstrap primitive, document the minimal alternative explicitly and prove first-install/no-service behavior before U1 acceptance.

## 5. Legacy migration without breaking shipped devices

Audit current loose app ELF/JSON pairs, driver four-file package inputs, ordinary package directories, loader absolute paths, springboard/app catalog, package manager API, Driver Manager, recovery journals, release scripts, and user-created files **before** changing them. Keep a finite read-only/bounded legacy *source adapter* that can import existing loose ELF+JSON and ordinary directory inputs into the new schema and single common transaction where needed for deployed SDs; do not continue publishing loose pairs as the normal output. Migrate existing installed apps and any non-directory installs to per-ID directories with an idempotent crash-safe journal, in-use checks and rollback; reuse already directory-installed drivers when valid. Do not automatically delete unknown or user-maintained folders, unrecognized legacy versions or previously published assets. Installed legacy software that cannot safely migrate is reported with a precise, recoverable remediation path, rather than silently hidden or exposed as a duplicate package. Resolve the CDC `usb-cdc-acm-v2` identity fork using [the stable identity policy](PACKAGE_IDENTITY_VERSION_POLICY.md) during the same migration, not a second identity alias invented by ZIP packaging.

Update every consumer and provider loader to resolve executable and assets from manager-validated installed package roots; no normal `Apps/foo.elf`, adjacent `foo.json`, `/Packages/Inbox/<id>/.package.json` or fixed online filenames as a permanent new-install assumption. Compatibility input adapters may accept historical paths only under explicit tests and a documented removal condition. Driver or app activation must work offline with no catalog or ZIP service after a package is installed.

## 6. U1 implementation sequence and acceptance

1. Inventory runtime reader/manifest/ELF paths, transactions, extraction/ZIP libraries, boot/recovery requirements and current released assets. Decide/document schema, bounded ZIP feature subset, resource path ABI and versioned installed-root API based on real implementation limits; avoid a parallel new installer.
2. Implement/archive-test generic bounded reader/streaming extractor and deterministic host packer, then route common source adapters, catalog, online/SD staging, all four kinds and recovery through ONE ZIP-to-ordinary-manager pathway. Create the ZIP service without making it a prerequisite for fresh installation.
3. Move installed apps/services/providers to per-package directories; adapt launcher, springboard, App Store, Driver Manager, Package Manager, provider executor and resource lookup. Migrate legacy installs safely, including CDC identity. Keep app and package version-bump rules and independent runtime permissions.
4. Replace release scripts/workflows: current release publishes exactly one `.rte.zip` for each current package, plus a generic catalog and firmware artifacts; old split ELF/manifest/four-file outputs are not required to perform current online installs. No fixed driver lists. Preserve full firmware artifact chain of custody.
5. Run production-facing tests: four kinds via offline/online ZIP install/upgrade/uninstall; extra resource nested paths; no ELF/resource pairing split; missing ZIP service/fresh SD; no catalog after install; large or malformed archive, ZIP Slip/bomb, duplicate/path normalization, symlink, CRC and SHA failure; interrupted download/extract/commit/restart; in-use and failed provider quiescence; migration of old app/driver identities and path layouts; version/ABI update refusal; deterministic build output; firmware/app/driver/service package and release-equivalent build. Verify no release path depends on split normal distribution or old signing code.

**Stop rule:** U1 is NOT software complete until the single ZIP bundle and per-ID extracted-directory model works for applications, drivers, services and providers from online and SD, installers function without ZIP service/network, all consumers resolve from package roots, legacy data is safe, release outputs/catalog agree and tests/builds pass. No extra intermediate owner board test, automatic merge/tag/release or requirement to implement future SD *provisioning* is introduced. Future provisioning eventually consumes these ZIP archives using the ordinary manager, but its manifest/parser/first-run workflow remains deferred.
