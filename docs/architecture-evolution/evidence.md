## E1 Capability selection and ABI

**Facts.** [App requirements](https://github.com/michaelrolphone-cmyk/T5S3-Reader/blob/2b45ab662c0ffe3650ce0f841083ea47886022c9/src/runtime/capabilities/AppCapabilityRequirements.h#L33-L60) parse only minimum API constraints; [installed snapshot resolution](https://github.com/michaelrolphone-cmyk/T5S3-Reader/blob/2b45ab662c0ffe3650ce0f841083ea47886022c9/src/runtime/packages/InstalledCapabilityResolver.cpp#L149-L174) chooses a highest satisfiable advertised API. [Installed registration](https://github.com/michaelrolphone-cmyk/T5S3-Reader/blob/2b45ab662c0ffe3650ce0f841083ea47886022c9/src/runtime/drivers/InstalledProviderGraph.cpp#L238-L253) stores the selected exact API for dependencies, and [acquisition](https://github.com/michaelrolphone-cmyk/T5S3-Reader/blob/2b45ab662c0ffe3650ce0f841083ea47886022c9/src/runtime/drivers/InstalledProviderGraph.cpp#L432-L452) passes it into the exact-match graph. [Provider ABI](https://github.com/michaelrolphone-cmyk/T5S3-Reader/blob/2b45ab662c0ffe3650ce0f841083ea47886022c9/sdk/driver/RiscProviderV2.h) has version/size fields and explicitly append-only quiesce/diagnostic extensions.

**Inference.** Minimum app declarations and exact graph binding are intentionally bridged; their coexistence is not itself a mismatch bug. A higher advertised number still needs an explicit compatible-layout/behavior promise for independent clients. **Hypothesis:** future independently released interfaces could break that promise unless release evidence catches it; no current binary corruption is claimed.

Bounds are visible in [graph header](https://github.com/michaelrolphone-cmyk/T5S3-Reader/blob/2b45ab662c0ffe3650ce0f841083ea47886022c9/src/runtime/drivers/ProviderGraphV2.h), [app requirements](https://github.com/michaelrolphone-cmyk/T5S3-Reader/blob/2b45ab662c0ffe3650ce0f841083ea47886022c9/src/runtime/capabilities/AppCapabilityRequirements.h) and [installed resolver](https://github.com/michaelrolphone-cmyk/T5S3-Reader/blob/2b45ab662c0ffe3650ce0f841083ea47886022c9/src/runtime/packages/InstalledCapabilityResolver.cpp#L16-L20): 16 modules, 32 grants, six mandatory app requirements, 64 inspected entries per root and snapshot depth eight.

## E2 Existing provider lifetime foundation

**Facts.** [Graph](https://github.com/michaelrolphone-cmyk/T5S3-Reader/blob/2b45ab662c0ffe3650ce0f841083ea47886022c9/src/runtime/drivers/ProviderGraphV2.cpp#L134-L216) retains dependency pins/tables until unload succeeds. [Module unload](https://github.com/michaelrolphone-cmyk/T5S3-Reader/blob/2b45ab662c0ffe3650ce0f841083ea47886022c9/src/runtime/drivers/ProviderModuleV2.cpp#L255-L279) retains failed-quiesce modules instead of force-unmapping. [Owned spec](https://github.com/michaelrolphone-cmyk/T5S3-Reader/blob/2b45ab662c0ffe3650ce0f841083ea47886022c9/src/runtime/drivers/ProviderOwnedSpecV2.h) copies bounded metadata and candidate bytes. The [test runner](https://github.com/michaelrolphone-cmyk/T5S3-Reader/blob/2b45ab662c0ffe3650ce0f841083ea47886022c9/test/run_provider_graph_v2_test.sh) includes real fixtures for caller-buffer mutation, retained dependency pointers, failed start, failed teardown and graph destruction safeguards, with sanitizer builds for several cases.

**Inference.** A general lifetime rewrite duplicates existing mechanisms. A concrete consumer/provider boundary that falsely reports success should be corrected to honor this graph instead. Native ELFs share an address space; these lifetime controls are not process isolation or a claim of complete permission enforcement.

## E3 App allocation ownership

**Facts.** [App ledger](https://github.com/michaelrolphone-cmyk/T5S3-Reader/blob/2b45ab662c0ffe3650ce0f841083ea47886022c9/src/runtime/resources/AppAllocationLedger.h) tracks blocks, bytes and peaks, retains old ownership on realloc failure, and reclaims tracked blocks. Its comment explicitly excludes provider/firmware allocations. [Memory bridge](https://github.com/michaelrolphone-cmyk/T5S3-Reader/blob/2b45ab662c0ffe3650ce0f841083ea47886022c9/src/native/NativeAppMemory.cpp#L13-L82) supplies 4096 entries, bounded lock waits and exit memory logs. [Allocation test](https://github.com/michaelrolphone-cmyk/T5S3-Reader/blob/2b45ab662c0ffe3650ce0f841083ea47886022c9/test/resources/app_allocation_test.cpp) exercises 100 repeated rounds, failed allocations/reallocation, overflow, capacity and idempotent cleanup.

**Inference.** Existing app reclamation is substantive counterevidence to a missing-ownership claim. It does not by itself produce a peak budget for provider activation. No test in this documentation task was executed locally.

## E4 Provider memory overlap and recent evolution

**Facts.** [Owned snapshot allocation](https://github.com/michaelrolphone-cmyk/T5S3-Reader/blob/2b45ab662c0ffe3650ce0f841083ea47886022c9/src/runtime/drivers/ProviderOwnedSpecV2.h#L41-L48) tries PSRAM then ordinary byte-addressable memory; [snapshot retention](https://github.com/michaelrolphone-cmyk/T5S3-Reader/blob/2b45ab662c0ffe3650ce0f841083ea47886022c9/src/runtime/drivers/ProviderOwnedSpecV2.h#L80-L104) copies the candidate. [Module loading](https://github.com/michaelrolphone-cmyk/T5S3-Reader/blob/2b45ab662c0ffe3650ce0f841083ea47886022c9/src/runtime/drivers/ProviderModuleV2.cpp#L188-L215) makes another temporary candidate copy until relocation returns, with a similar allocation fallback. The per-image maximum is 8 MiB.

Recent history deliberately [made loading lazy](https://github.com/michaelrolphone-cmyk/T5S3-Reader/commit/606a747594e042f593f9452eaa6bd5245179b55b) and [bounded registration stack frames using heap workspaces](https://github.com/michaelrolphone-cmyk/T5S3-Reader/commit/78616103e5be7250eeb5490bcb298e5331bfeb7e). The current registration source enforces a 384-byte compiler frame warning threshold. [Integrity-check history](https://github.com/michaelrolphone-cmyk/T5S3-Reader/commit/1e4e21ba83b1b2fbd3282005e9d6d719ad2cd347) moved full payload hashing out of normal loading while retaining install/update checks. Stale comments describing repeated runtime hashing are not evidence that it still happens.

**Inference.** Multiple bounded allocations can overlap; a per-image cap is not an aggregate admission reservation. **Hypothesis:** that overlap threatens useful working-set headroom on representative devices. Measure before changing policy or removing copies. [Memory architecture](https://github.com/michaelrolphone-cmyk/T5S3-Reader/blob/2b45ab662c0ffe3650ce0f841083ea47886022c9/docs/MEMORY_ARCHITECTURE.md) explicitly keeps normal ELF resident memory in RAM and defines storage VM as explicit mapped windows, not transparent paging.

## E8 Package publication and lifetime counterevidence

**Facts from the historical U1 `74c7bdfd` snapshot, not claims about current U1 or merged master.** [Mutation gate](https://github.com/michaelrolphone-cmyk/T5S3-Reader/blob/74c7bdfdad4ea43cd589d672bf24595070f2d9c5/src/runtime/packages/PackageMutationGate.h) coordinates manager mutation; [use gate](https://github.com/michaelrolphone-cmyk/T5S3-Reader/blob/74c7bdfdad4ea43cd589d672bf24595070f2d9c5/src/runtime/packages/PackageUseGate.h) pins package roots and prevents replacement while in use. [Transaction state machine](https://github.com/michaelrolphone-cmyk/T5S3-Reader/blob/74c7bdfdad4ea43cd589d672bf24595070f2d9c5/src/runtime/packages/PackageOrdinaryTransaction.h#L78-L225) implements stage/target/previous publication, recovery and uninstall tombstones, with conservative handling of invalid/unknown state. ## E9 Display portability refinement

**Context, not implementation evidence.** On 2026-10-01 the owner described capability-based applications over downloadable hardware drivers as an important part of the ESP32 platform vision, with current e-paper emphasis expanding to monochromatic reflective LCD and an ESP32 AMOLED smartwatch. The owner also named three parallel near-term goals: expressive fast e-paper rendering, the smallest core that assembles the existing UX from drivers/apps, and original CrossPoint feature parity enabling its app to deploy. These are stated goals, not verified achieved capabilities. Specific hardware/resource/input requirements and the CrossPoint target revision/build contract remain unknown. The [platform specification](https://github.com/michaelrolphone-cmyk/T5S3-Reader/blob/3300229d0a232b4e6047a7c93b2f518c033c3cfa/docs/RISCRTE_PLATFORM_SPEC.md) already distinguishes a CPU/ABI port from installing compatible device providers.

**Facts at unchanged PR #220 head.** The [display SDK](https://github.com/michaelrolphone-cmyk/T5S3-Reader/blob/e0031d06f976fa6b3940f31693907318c3de93ac/sdk/driver/RiscDisplayOutputV1.h) contains runtime geometry, safe insets, rotation support, damage alignment, refresh/latency metadata, format identifiers through RGB565, optional retained-image/clean/brightness flags and presentation intents. These declarations do not establish implemented support for every format or feature. The [client](https://github.com/michaelrolphone-cmyk/T5S3-Reader/blob/e0031d06f976fa6b3940f31693907318c3de93ac/Apps/display_output_client.h) accepts only MONO1/GRAY2, validates actual acquired geometry/stride, and submits default options. The [e-paper provider](https://github.com/michaelrolphone-cmyk/T5S3-Reader/blob/e0031d06f976fa6b3940f31693907318c3de93ac/Drivers/display_epd_video/driver.c) advertises 960×540, those two formats and rotation zero; it ignores the submit options argument and does not support brightness.

The [firmware renderer](https://github.com/michaelrolphone-cmyk/T5S3-Reader/blob/e0031d06f976fa6b3940f31693907318c3de93ac/lib/GfxRenderer/GfxRenderer.cpp#L79-L123) rejects non-MONO1, while [Model Viewer](https://github.com/michaelrolphone-cmyk/T5S3-Reader/blob/e0031d06f976fa6b3940f31693907318c3de93ac/Apps/model_viewer.c#L1181-L1188) restricts dimensions/stride. These are current consumer limits, not proof that the SDK intrinsically requires e-paper.

**Inference.** Build on the existing descriptive ABI. Capability portability requires actual consumer adaptation or declared refusal as well as provider registration; a renamed fixed-board interface is insufficient. Geometry/color/refresh/input witnesses should challenge supporting finding S1 without expanding it into a speculative renderer redesign.

## E14 Rendering and daily-use ownership evidence

**Facts.** [Hollow Trail loop](https://github.com/michaelrolphone-cmyk/T5S3-Reader/blob/3300229d0a232b4e6047a7c93b2f518c033c3cfa/Apps/hollow_trail.c#L525-L562) overlaps packing with the scan, copies only when staging was used, and retains a direct pack-to-backbuffer path. [Desk-clock fast resume](https://github.com/michaelrolphone-cmyk/T5S3-Reader/blob/3300229d0a232b4e6047a7c93b2f518c033c3cfa/src/DeskClockSleep.cpp#L214-L265) reinitializes the needed board/clock/display path and paints before returning to deep sleep, intentionally avoiding SD mount, app discovery, touch/network setup and full UI boot. This is current product behavior to preserve, not a claim that a packaged equivalent already exists.

[Performance notes](https://github.com/michaelrolphone-cmyk/T5S3-Reader/blob/3300229d0a232b4e6047a7c93b2f518c033c3cfa/docs/HOLLOW_TRAIL_RENDER_PERFORMANCE.md) explicitly distinguish host raster measurements from device FPS and overlapping input/scheduler time. **Inference.** Ownership extraction should preserve the no-copy and overlapped work paths and measure real workloads. A generic capability boundary does not require a copied message per pixel/row or removal of expressive rendering. The owner's daily serial/programming/USB/clock/game workflows are stated requirements; this review does not claim they all passed a new regression suite.
