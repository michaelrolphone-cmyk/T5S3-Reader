# RiscRTE Runtime Provider/Driver Implementation State

## Normative target — read this before interpreting current code

The governing architecture is [RISCRTE_PLATFORM_SPEC.md](RISCRTE_PLATFORM_SPEC.md), [HARDWARE_AGNOSTIC_DRIVER_BOUNDARY.md](HARDWARE_AGNOSTIC_DRIVER_BOUNDARY.md), [RUNTIME_DRIVER_ARCHITECTURE.md](RUNTIME_DRIVER_ARCHITECTURE.md), and [PLATFORM_CAPABILITY_ROADMAP.md](PLATFORM_CAPABILITY_ROADMAP.md). **The generic framework does not own hardware and must not know what USB, GPS, UART, SPI or any other hardware family is beyond opaque capability identifiers.** Full device implementation, discovery and actual resource arbitration live in independently installed ELF provider(s); generic contexts/leases are software permissions and lifetime bookkeeping. A firmware-side USB host, GPS adapter or bus manager is a **CURRENT/LEGACY, NONCOMPLIANT** implementation, not a target design. This document reports existing code accurately; no source migration occurs merely because the architecture specs change.

## CURRENT/LEGACY, NONCOMPLIANT — fixed network provider

Radio functionality formerly inside activities now lives in compiled `src/providers/network/Esp32NetworkProvider.cpp`, bound by `src/runtime/network/NetworkService.cpp`. The app-facing header avoids board/ESP-IDF details, and internal C++ contracts split generic network state/address/shutdown from Wi-Fi scan/connect/MAC/SSID/signal. However these are *compiled* provider contracts with a fixed firmware-lifetime binding, not independently installable driver ELFs or general resolution. Migrated consumers include Wi-Fi selection, file transfer, Calibre, OPDS, KOReader sync, firmware update and compatibility native networking. Credentials/UI/retry remain above the provider, and compiled networking shutdown owns clock sync, disconnect and radio-off. `bash test/run_runtime_network_test.sh` tests existing extraction; physical Wi-Fi verification remains required. Target: move actual radio/link logic and any hardware-dependent networking code to ELFs; generic network services may consume published interfaces.

## PARTIALLY MODULAR — GNSS provider pathway

`GPS_DRIVER.md` documents the installable `gps-nmea` ELF and `position.gnss` capability. Receiver logic and NMEA parsing are in the ELF; firmware has no GPS parser fallback. It proves independent build/package/load/unload. The firmware still implements a GPS-specific runtime adapter and hardware UART/rail allocation, a fixed facade and provider lifecycle. These aspects are noncompliant. Target: generic resolver/provider ABI, separately supplied UART and power capabilities where necessary, GNSS-ELF-owned physical session and provider-originated `location.*` publication. No compiled GNSS/UART/rail driver may remain in normal runtime.

## GENERIC BUT STILL FED BY HARDWARE-SPECIFIC FIRMWARE — device registry

`src/runtime/capabilities/DeviceRegistry.h` implements a bounded, transport-neutral firmware-owned registry with copied provider identity/capability names, states, priorities, generation-safe handles, shared/exclusive *software* capability leases and invocation identities. Wrong owners cannot inspect/release others' leases; removal revokes grants; `releaseOwner()` cleans invocation-wide grants. This generic record/rights machinery is consistent with the target **provided it stays hardware blind**. It does not itself own the device, physical transport or physical lease.

A 24-entry lifecycle journal records Added/StateChanged/CapabilityLost/Removed, a 64-bit sequence, copied removal identity, revoked-grant counts and GAP on overflow; independent owner-task cursors can poll retained events. `DeviceEventSubscriptions.h` adds eight invocation-owned subscriptions, gap blocking until atomic inventory resnapshot, and teardown through `ExecutionContext::Resource::DeviceEvents`. `T5DeviceApi.h` / `NativeDeviceBridge.cpp` implement read-only versioned inventory/subscribe/snapshot/poll/unsubscribe for authenticated current invocations via copied bounded records. Observation grants no hardware authority, stale/cross-owner handles fail, and there is not yet a complete cross-task event bus. These generic mechanisms should remain but must accept publication from arbitrary ELFs, not synthesize USB or GNSS from firmware-side adapters.

### Noncompliant firmware GNSS projection

A hard-coded onboard GNSS adapter currently publishes a UART logical device with `location.position`, `location.altitude`, `location.time`, `location.accuracy`, and `location.satellites`. Compatibility GPS startup obtains a context `location.position` lease **then firmware claims UART/power and loads the ELF**. A firmware-only context callback stops module/UART/power and releases grants. This firmware-owned hardware state must move to a driver/provider ELF (possibly consuming independent UART/rail providers). Registry publication should originate in the installed provider. Keep current claims/tests as compatibility evidence, not architectural precedent.

### Noncompliant firmware USB projection, discovery and physical arbitration

`UsbSerialProjection.h` mirrors legacy `NativeUsbDevices::Registry` into the generic registry. `NativeSerialPortBridge.cpp` projects a USB serial interface with `serial.port` and `serial.host`, deriving identity from firmware USB session epochs, VID/PID/product and binding. A firmware owner-task `nativeDeviceDiscoveryTick()` reconciles host snapshots from `ActivityManager::loop()`, ELF input updates and observation operations. USB callbacks publish firmware snapshots, not directly generic device records. A blocked owner task can delay discovery. `NativeSerialPortBridge.cpp` and `NativeStreamBridge.cpp` implement a firmware USB session reservation and exclusive physical USB/serial lease; stream scheduler callbacks wait for owner-task authorization and firmware handles stale epochs/replug. This gives useful revocation and conflict-test coverage but **is not the intended device architecture**: core code must not enumerate USB, project USB snapshots, reserve USB physical sessions or interpret epochs/VID/PID.

Target: USB-host and class provider ELFs perform all controller/device discovery, interface and session ownership, attach/rebind and real USB transfers. They publish copied generic records to the unchanged transport-neutral registry, obtain generic software grants for callers and enforce their own physical session rights. Replace direct firmware USB streams with class-driver-produced/consumed generic byte streams. Delete USB-specific firmware loader/bridge/registry/projection/dispatch and silent resident chipset fallback from normal operation. The same model applies to every other transport. `UsbSerialProjection` tests remain legacy behavior tests until replaced by provider publication tests.

## CURRENT/LEGACY test coverage

Existing suites include `test/resources/device_registry_test.cpp`, `device_event_test.cpp`, `device_subscription_test.cpp`, `usb_serial_projection_test.cpp`, `test/streams/usb_discovery_tick_test.cpp`, `usb_device_api_test.cpp`, `usb_direct_ownership_test.cpp`, plus existing bridge/stream/serial regression suites. They exercise identities, lease conflicts/owner denial, stale generation, cleanup, event ordering/gaps/snapshots, serial discovery/USB loss, duplicate opens and stream/serial exclusivity. They establish behavior of current code, **not** compliance with ELF-owned hardware; host tests do not prove physical USB, UART, PSRAM, power or cross-core safety.

## Required migration sequence

1. Preserve the transport-neutral registry/event/permission/execution-context APIs and ensure their implementation contains no hardware-type branches. Allow every provider ELF to publish/retract bounded records through one ABI; validate producer identity and generation, without parsing physical metadata.
2. Introduce a complete generic driver ABI/dependency resolver and provider-facing publication/authorization interfaces. Remove `kernel.usb.host` special-case activation and hard-coded USB/GPS provider paths.
3. Extract entire host-controller USB operations, USB power via a provider dependency, and complete CDC/vendor class implementations into ELFs. Remove compiled-in USB host/VBUS/endpoints/transfers, discovery tick and projection, direct USB stream I/O, USB-specific lease state and resident fallback from normal firmware.
4. Extract actual UART/rail ownership and GNSS-specific lifecycle and publication into provider ELFs. Make the GNSS ELF consume hardware/provider capabilities and publish `location.*` and record streams itself. Remove compatibility GPS hardware dispatch in firmware once consumers migrate.
5. Extract compiled Wi-Fi link/radio implementation and all other production hardware paths into independent providers; replace fixed binding with generic resolver selection. Provider ELFs own physical bus/resource arbitration; core may offer generic opaque CPU/OS resource grants only.
6. Keep recovery boot/storage/network hardware code explicitly outside the normal runtime driver path, never as silent substitute provider. Build generic dependency-loss and physical safety tests, signed packages and permissions, and verify on real boards.

## Completion and verification gates

**Minimum modularity acceptance:** install a new unsupported device using only a driver ELF/manifest/profile and prove actual hardware I/O without reflashing firmware; remove that driver and confirm the capability disappears instead of falling back to compiled hardware. Test competing hardware clients, failure/cancellation, unplug/replug, generation/handle invalidation, teardown, resource/power leaks and provider unload. A build, driver package, registry entry or thin descriptor/proxy ELF does not pass. Do not label the GNSS or USB architecture complete until physical and source-boundary checks are demonstrated.

## Legacy/current-state rule

Concrete names, source paths, ABI symbols and packages here are retained precisely to identify deployed code. When this document conflicts with a target spec, the target governs new changes and this document remains an explicit record of behavior needing migration. **Do not add more hardware-specific framework code as an incremental step toward driver modularity.**
