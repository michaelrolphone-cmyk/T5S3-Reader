# RiscRTE Runtime Provider/Driver Implementation State

## Target platform contract

The normative driver/provider design is `RUNTIME_DRIVER_ARCHITECTURE.md`, governed by `RISCRTE_PLATFORM_SPEC.md` and the device/capability/resource model in `PLATFORM_CAPABILITY_ROADMAP.md`. RiscRTE applications and services should request semantic capabilities; the resolver/device registry selects providers; runtime-owned resources mediate hardware; installable drivers/providers remain independently replaceable where practical.

This file is not a competing architecture. It records the migration state of existing code. New work should close the gaps below rather than institutionalize them.

## Current implementation

### Compiled-in network provider precursor

Radio operations previously embedded in activities now live in `src/providers/network/Esp32NetworkProvider.cpp`, bound by `src/runtime/network/NetworkService.cpp`. The application-facing header has no Arduino, ESP-IDF or board dependencies.

Two independently versioned internal C++ contracts currently separate generic network state/address/shutdown from Wi-Fi scan/connect/configuration/MAC/SSID/signal operations. These are compiled-firmware contracts, not a published driver ELF ABI. Binding is still fixed for firmware lifetime and is therefore a precursor to, not an implementation of, general capability resolution/dynamic provider selection.

Migrated consumers include Wi-Fi selection, file transfer, Calibre, OPDS, KOReader sync, firmware update and the compatibility native network bridge. Credential UI, retry/navigation/rendering policy remains above the provider. Common shutdown now centralizes clock-sync stop, disconnect and radio-off sequencing.

`bash test/run_runtime_network_test.sh` validates provider/service behavior and guards against direct Wi-Fi calls returning to migrated activities. Physical acceptance remains required for scan/connect/AP/reconnect behavior.

### Installable GNSS provider pathway

The first actual installable hardware provider is documented in `GPS_DRIVER.md`. GPS parsing is no longer compiled into firmware. The existing `gps-nmea` ELF, `position.gnss` capability and `T5GpsApi` facade prove the independent build/package/load/unload pathway while remaining a compatibility slice pending the roadmap's general resolver and semantic `location.*` ABI.

### Unified Device Registry and context-owned leases: GNSS and USB vertical slices

`src/runtime/capabilities/DeviceRegistry.h` provides a bounded, firmware-owned, transport-independent inventory. It copies device/provider identity and semantic capability names into fixed records; discovery state, transport, capability metadata, priority and opaque generation-safe device handles can be queried without loading an ELF. Its resolver acquires shared or exclusive capability leases under a nonzero application invocation identity. A wrong owner cannot inspect or release another invocation's lease. Removal or loss of availability revokes leases; slot reuse changes the handle generation. `releaseOwner()` provides deterministic invocation-wide revocation. The registry is firmware-owned and serialized by the runtime owner task; there is no app-facing direct registry-object API or general asynchronous discovery service.

The registry has a **24-entry fixed-capacity lifecycle journal**. Device registration emits `Added`; meaningful state transitions emit `StateChanged`; AVAILABLE/BUSY becoming unusable or removed also emits `CapabilityLost` with the number of forcibly revoked leases; removal emits `Removed` with a copied identity even after the device handle is invalid. Repeated identical states emit nothing. Each record has a monotonically increasing 64-bit sequence, and independent owner-task readers use `cursor()`/`poll()` without installing callbacks. `Gap` explicitly reports overwritten events; `overwrittenEvents()` provides diagnostics. A cursor of zero can replay retained history but does not imply complete historical delivery.

`src/runtime/capabilities/DeviceEventSubscriptions.h` adds a **bounded eight-slot, owner-task subscription layer** around this journal. Only the currently running `ExecutionContext` can subscribe, read, inventory-snapshot or unsubscribe using generation-safe opaque handles; cross-owner and stale handles fail closed. Each subscription starts at the current journal sequence and maintains its own cursor. If events were overwritten, `poll()` reports `Gap` and refuses further events until `snapshot()` atomically copies the current inventory and resets that subscription's cursor. Insufficient snapshot capacity reports `Limit` without acknowledging the gap; an empty inventory can be snapped with zero capacity. `ExecutionContext::Resource::DeviceEvents` removes every remaining subscription before ELF unload. Explicit unsubscribe of the final handle releases that cleanup registration. USB host task callbacks still publish snapshots only.

**Application-facing device observation now exists.** `lib/NativeApps/include/T5DeviceApi.h` defines a versioned C-compatible API table exported through `t5_device_get_api(1)` by the ELF loader. `src/native/NativeDeviceBridge.cpp` checks the active app host and running execution context for every operation and exposes `inventory`, `subscribe`, `snapshot`, `poll` and `unsubscribe` using copied, bounded C records. An ELF never supplies its own invocation/owner identity, obtains a direct registry pointer, imports a callback into the registry, or gains hardware access merely by observing. Event gaps block delivery until an adequate atomic resnapshot. `test/streams/usb_device_api_test.cpp` compiles the real bridge and tests unauthorized access, C layout, no-serial inventory, disconnect/replug generation changes, revocation, overflow, recovery and teardown. The isolated launcher symbol test also recognizes the export. See [Device Observation API](DEVICE_OBSERVATION_API.md). This implements a pull-based observation API, **not** a semantic capability acquire/lease API or asynchronous cross-task notification fabric.

The onboard GNSS adapter publishes a UART logical device with `location.position`, `location.altitude`, `location.time`, `location.accuracy` and `location.satellites`. Starting its existing compatibility API resolves an invocation-owned `location.position` lease before claiming UART and loading the driver ELF. A firmware-only `ExecutionContext` cleanup callback unloads the provider, releases UART/power and revokes leases before the application ELF is unloaded. Explicit stop untracks the callback; failed start/read unwinds ownership and marks the device failed. Existing application and GPS ELF ABIs are unchanged.

`src/runtime/capabilities/UsbSerialProjection.h` connects the legacy lock-protected USB serial enumeration snapshot to the same inventory. USB host callbacks publish only into `NativeUsbDevices::Registry`; the firmware owner task reconciles snapshots in `NativeSerialPortBridge.cpp`. A bound USB serial interface is a semantic USB device with `serial.port` and `serial.host`. Disconnect, interface rebinding or session epoch changes replace its generation-safe identity, revoke its leases, and publish ordered `CapabilityLost`/`Removed` events before the new `Added` event. VID/PID/product are **not** permanent or globally unique physical identity. The existing `T5SerialPortApi` remains a compatibility surface.

**Owner-task discovery is now connected to firmware execution, not just serial calls.** `nativeDeviceDiscoveryTick()` snapshots the USB host's lock-protected enumeration and reconciles it without requiring an application, serial API, live lease or host start. `ActivityManager::loop()` calls it each firmware activity iteration; native-app `MappedInputManager::update()` calls it during an ELF's owner-task input polling while the outer activity loop is blocked. Device observation operations also reconcile before reading. A callback alone does not mutate the unified registry: arrival/loss appears at the next owner-task tick. Repeated ticks of an unchanged host snapshot are idempotent. The tick never powers, starts or stops USB, never acquires a lease, and does not make an unbound USB device available. This is **cooperative discovery**: an ELF that blocks its owning task without polling input or reaching another owner-task reconciliation point can delay delivery. It is not a dedicated background discovery worker or a general multi-transport driver manager.

`NativeSerialPortBridge.cpp` and `NativeStreamBridge.cpp` share one owner-task physical USB session reservation and one exclusive `serial.port` capability lease for **both** semantic serial sessions and legacy direct USB streams. A session can be reserved during asynchronous host enumeration; on binding, only the original consumer's execution context acquires the physical lease. The direct stream's pipe-scheduler callbacks may not perform I/O until the owner task has acquired this lease; they never mutate the device registry. The direct stream's owner-task open/read/write/pipe-connect operations reconcile enumeration. A stale stream epoch reconciles device loss and revokes its old lease without claiming an identical replacement. A failed duplicate direct open must not release the active stream's lease. Explicit close and invocation teardown release the direct lease, while serial teardown releases its serial lease and host. Existing app/driver ELF ABIs are unchanged.

`test/resources/device_registry_test.cpp`, `test/resources/device_event_test.cpp`, `test/resources/device_subscription_test.cpp`, `test/resources/usb_serial_projection_test.cpp`, `test/streams/usb_discovery_tick_test.cpp`, `test/streams/usb_device_api_test.cpp` and `test/streams/usb_direct_ownership_test.cpp` exercise identity, priority, conflicts, cross-owner denial, stale-generation rejection, app cleanup, journal ordering/loss/overflow, subscription gap/snapshot behavior, owner-task arrival/removal/replug without serial API calls, immediate revocation on tick, public read-only ABI authentication, direct-versus-serial exclusivity, duplicate-open ownership and safe stale-stream rejection. The production USB semantic bridge and original stream test remain in the host suite. These tests do **not** prove physical USB enumeration, cross-core timing, UART/PSRAM/power behavior; those require on-device verification.

## Required convergence with the roadmap

The two initial live adapters are GNSS and USB serial. USB projection and lifecycle journal publication occur on the firmware owner task through cooperative discovery and selected native API operations. The tick has no hardware probe/host activation functionality; it only mirrors an already-published USB serial binding. An authenticated ELF can observe it but cannot acquire a generic semantic capability or receive asynchronous push notifications through this API. The USB host still has its existing lifecycle and compatibility snapshot; device registration is not evidence that its installable driver was activated or tested. Physical USB VBUS lifetime, multiple interfaces, hub discovery, BLE inventories and independent driver/provider activation remain outstanding. The remaining `usbOpen` flag is a compatibility guard for stream slot occupancy; it must not be treated as the physical authorization source. This slice consolidates the known direct/serial paths' exclusive capability lease, not every future USB class or kernel client.

`GpsDriverRuntime` is still the concrete compatibility adapter beneath its semantic device record; generic provider activation, manifest-driven capability declarations, automatic provider selection, dependency graphs, framework-wide events and public app-facing semantic location APIs remain outstanding. Do not mistake a registered device for an installed, activated or verified driver.

Next: verify physical direct/serial USB ownership and repeated disconnect/reconnect on-device; provide context-authorized semantic capability acquisition/lease operations rather than observation only; extend discovery to other USB classes and BLE; generalize resource cleanup and manifest capability requirements/launch gating; and expose semantic location without breaking deployed `T5GpsApi`. A dedicated owner-task event-wake mechanism remains a future requirement for ELFs that never yield to the cooperative pump. Network should migrate from fixed compiled binding to the same provider/capability model where feasible.

Shared I2C/SPI/GPIO buses must become runtime-owned managers before arbitrary installable drivers receive bus access. USB, BLE, UART and future transports should register devices/capabilities through the same registry rather than create parallel inventories. Capability-loss/device lifecycle events should flow through the common event fabric. All transport discovery callbacks must marshal registry mutations onto its owner task until synchronization is explicitly implemented.

HTTP/TLS, DNS/mDNS and higher network facilities belong in reusable RiscRTE networking services above the Wi-Fi provider rather than individual applications. VFS/mounts, provider discovery, device profiles, dependency resolution, signed packages and driverless recovery remain roadmap work.

## Legacy/current-state rule

Source paths, ABI symbols, package names and concrete provider names in this document are intentionally preserved because they identify code that exists today. Conceptual references use RiscRTE terminology. If this implementation-state document conflicts with the architecture/roadmap, the architecture governs new work while this file remains evidence of what must be migrated.
