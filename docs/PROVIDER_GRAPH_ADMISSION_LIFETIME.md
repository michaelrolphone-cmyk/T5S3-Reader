**Updated September 18, 2026.** Normative for provider execution subject to [RISCRTE_PLATFORM_SPEC.md](RISCRTE_PLATFORM_SPEC.md), [HARDWARE_AGNOSTIC_DRIVER_BOUNDARY.md](HARDWARE_AGNOSTIC_DRIVER_BOUNDARY.md), [PACKAGE_MANAGER_SCOPE_CONTRACT.md](PACKAGE_MANAGER_SCOPE_CONTRACT.md) and the integrated [U1 milestone](NEXT_HARDWARE_TEST_MILESTONE.md). Source integration still needs exact head/linked-firmware verification and physical hardware validation; this document is not a device test result.

## Required registration and authorization

`GraphV2::addVerified` is ordinary/nonprivileged admission. The provider executor is firmware-private but hardware-blind: it takes a bounded manager-validated ordinary package identity, API/dependencies, import declaration and privately owned exact ELF bytes; validates architecture and relocations, enforces the independently allowed generic privileged OS/CPU symbol set, context identity and capability rights, and activates the module through generic lifecycle/graph operations. It cannot let a manifest string or checksum authorize privilege. An unsigned normal package is eligible for admission when **independent** loader/import/runtime policies are satisfied; publisher signatures and signed receipts/floors are unnecessary and, for the active repository, subject to explicit owner-directed purge.

Private C++ access alone is not a security boundary; native ELFs share an address space. The historic name `addAuthenticatedPrivileged` is confusing because it arose during the signing experiment. During U1, audit its production consumers and rename or replace signing-implying terminology with policy-checked/private admission *without deleting the independent checks or widening public ELF privileges*. No build or activation path may depend on P-256/signer/trust/NVS floors. Preserve generic runtime rights and diagnostics.

## Owned bytes, dependency pins and quiescence

`GraphV2::addChecked` and `OwnedNodeV2` copy bounded identity, path, capabilities, dependency names/interface tables, import declarations, expected integrity digest and complete candidate ELF bytes into graph-owned storage. The caller can mutate or free its buffers after registration without changing activation input. `ModuleV2::loadVerifiedBytes` privately copies and validates the same candidate bytes, ELF structure and symbol/relocation policy before relocation. SHA-256 detects byte mismatch, not publisher identity or privilege. Other legacy path-based `dlopen` routes need matching exact-byte/lifetime protections when touched; do not claim a filename is immutable SD content.

Retain the `risc_provider_dependency_v1[]` passed to `start()` and pin dependency interfaces through quiesce and stop. Generation-safe grants/streams are revoked on loss. A failed physical quiesce quarantines the mapped code, dependency pins, candidate bytes and outstanding resources rather than unloading hardware that may still hold ISR/DMA/task/callback references. A zero software lease count does not prove physical safety. Generic runtime code may manage only opaque grants/pins and invoke lifecycle; controller/USB/I2C/power arbitration and recovery live in ELFs.

## CURRENT/LEGACY, NONCOMPLIANT integration residue

`InstalledProviderGraph.cpp`/`DeviceProviderExecutorV2.cpp` supply the merged installed-module pathway and source-integrity/import checks, and physical provider packages were published in v1.2.19. Their existence does **not** mean an arbitrary provider/class can bind without firmware modification: `NativeUsbBridge.cpp` still names host and class ELF package IDs, selects class by VID, polls USB host and maintains USB sessions; Serial Monitor/registry/stream adapters and `BOARD_T5S3_PRO` guard still need removal. `NativeDriverManagerBridge.cpp`'s `usb-provider-catalog.json` input supplies a special provider list and dependency download logic; this is transitional discovery data, not loader policy and cannot remain required. Driver package installation is separate from graph activation.

The target is generic manifest- and provider-advertisement-driven selection; each installed class ELF probes its device, publishes generic device/capability records and handles physical sessions. The ordinary manager passes candidates to a hardware-blind executor. Its source inventory is installed package metadata and runtime provider publication, **not** the online release catalog or a compiled ID list. No missing or corrupt driver triggers a compiled USB replacement. A new compatible `serial.port` provider needs no bridge/core change.

## Required U1 verification

Exercise the actual production graph/loader and manager together: ordinary unsigned package admission; tampered bytes/ELF/symbol/ABI/import refusal; caller-buffer mutation after admission; dependency cycles, missing/version conflicts and stable interface tables; mapped-generation update/uninstall refusal; failed start/quiesce quarantine and exact pins; generic provider-published arrival/removal and stale handle/stream revocation; addition/removal of a new compatible provider with no USB firmware patch; zero reference to signing/floor receipts and old USB catalog in the normal path. Existing `test/run_provider_graph_v2_test.sh` and ELF import audits are useful but are not physical proof. Finish firmware source/link audit and one complete [U1](NEXT_HARDWARE_TEST_MILESTONE.md) software handoff; owner tests USB, I2C/VBUS and electrical/IRQ/DMA safety only afterward.
