# U1 detailed validation and one owner hardware-test handoff

**Binding companion to [U1 milestone](NEXT_HARDWARE_TEST_MILESTONE.md).** Retains its E/F acceptance details under [four-milestone stream-first order](FOUR_MILESTONE_STREAM_FIRST_EXECUTION_ORDER.md), [I²C bus ELF cutover](I2C_BOOTSTRAP_CUTOVER.md), [SPI/UART cutover](SPI_UART_ELF_BOOTSTRAP_CUTOVER.md) and [ELF verification performance](U1_ELF_LOAD_VERIFICATION_PERFORMANCE.md). U1 requires stable installed **I²C bus ELF provider boundary**, not native I²C-controller takeover. SPI/UART bus ELFs are U1 requirements only where an actual U1 driver uses them; otherwise their consumer and native-controller cutovers belong to U3. Proportionate checks establish software completion; only owner starts physical qualification.

## Workstream E — integrate without intermediate owner tests

1. Test production package transactions, generic catalog/graph, registry/events, provider calls and stream rights: online/offline four kinds, missing catalog, snapshot mismatch, corrupt/missing/extra files, duplicate IDs/versions, invalid SHA/ELF/import, active replacement, interrupted recovery/remove, installed-not-activated, multiple providers including alternative `serial.port`, reconnect generations, competing clients, failed quiescence and no compiled USB fallback. Focus on demonstrated defects and durable invariants, not a new comprehensive E2E gate.
2. Audit linked firmware and ELF imports: reject normal firmware USB host/class/chipset/session/projection, hard-coded driver IDs/VIDs, special USB catalog and unwanted signing. **Bus rule:** the installed matching I²C/SPI/UART bus ELF alone may import its own specifically allowlisted, versioned temporary firmware *raw controller* backend if U1 actually requires it. I²C bus ELF is mandatory U1; SPI/UART ELFs only when reached by U1 consumers. Reject direct firmware bus imports or globals in any device ELF/app, firmware peripheral register/protocol/power behavior, competing firmware-published bus capability, overlapping controller ownership and USB fallback. Record matching package ID, stable public bus contract, private symbols/allowlist, caller graph, limits, controller ownership and U3 removal action. A permanent generic resolver exception keyed on bus name is prohibited. Boot/ROM/debug-console text and isolated code are not normal runtime provider implementations.
3. Exercise actual I²C ELF startup with noncyclic power graph, bounded transfer/timeouts, exclusive controller owner, rights, corrupt/missing/disabled provider, revocation and safe rail defaults. Dependent USB/power fails closed if I²C ELF is absent even with firmware raw primitive code present. Verify device manifests require `i2c.bus`, never `kernel.i2c`, and remain compatible with a bus ELF implementing the same public ABI natively. If SPI/UART bus ELF is genuinely in U1, apply the same missing-provider/import/boundedness/exclusivity checks to it; do **not** require unused bus ELF or native I²C/SPI/UART cutover in U1. Distinguish USB CDC semantic `serial.port` from physical `uart.port`.
4. Run proportionate host tests, package/ELF import/relocation audits, app/driver/firmware builds and release-equivalent staging where feasible. Preserve firmware binaries/checksums outside mutable `.pio` before ELF builds. Include launch/inventory hashing latency checks. Do not idle for CI; log actual PASS/FAIL/NOT RUN and never claim unperformed hardware results. Fix known blocking software defects before handoff.

## Workstream F — one owner hardware session after software implementation

Deliver exact firmware, app, driver/version/architecture, artifacts, installation order (I²C bus ELF before power/expander/USB dependents, plus SPI/UART bus ELFs only if used), SD backup/recovery, diagnostics and one coherent hardware procedure:

1. Cold boot without optional USB ELFs: USB capability absent, UI/SD/manager functional and no fallback or unexpected VBUS. Install I²C bus ELF, power/expander and USB stack via common engine; verify stable `i2c.bus`, dependency graph, Serial Monitor on `serial.port`, baud/DTR/RTS. Temporary raw firmware operations must remain private to the bus ELF.
2. Connect known ESP32-S3-CAM CDC test device; verify sustained VBUS/boot, enumeration and real probe, RX logs/TX, scroll/display and reconnect. CP210x physical PASS requires an actual CP210x device; note absent variants.
3. Test disconnect/reconnect, generation revocation, multi-client contention, abort/unload, resource leaks and safe IRQ/DMA/host/power shutdown. If power uses I²C, check bus single-owner and bounded failure; no premature native-controller takeover.
4. Remove USB host/class ELFs: their capabilities vanish with no firmware substitution. Remove I²C bus ELF separately: `i2c.bus` and dependent power/USB fail safely; raw firmware primitives cannot be reached by consumer drivers. Reinstall and test corrupted/missing/interrupted update preserving last-good generation; inspect boot/recovery separately. For any U1 SPI/UART ELF, verify equivalent fail-closed bus absence and that isolated diagnostic UART does not impersonate `uart.port`.
5. Exercise unrelated real device ELF witness and four-kind offline/online operations. An I²C witness owns its device behavior in its ELF, uses installed bus capability, never firmware port directly. Do not extrapolate cross-board hardware acceptance.

Owner closes physical acceptance. Keep same implementation PR for discovered defects. [U3](NEXT_MILESTONE_T5_PRO_HARDWARE_DRIVER_MIGRATION.md) replaces **all three** bus ELFs' temporary backends where applicable, removes normal firmware bus imports and confirms upstream consumer compatibility, alongside GNSS/apps and headless boot. [U4](NEXT_MILESTONE_PROVISIONING_AND_ESP32_S3_CAM.md) remains provisioning and one image.
