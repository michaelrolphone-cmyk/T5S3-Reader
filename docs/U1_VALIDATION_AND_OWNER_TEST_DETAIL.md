# U1 detailed validation and one owner hardware-test handoff

**Binding companion to [U1 milestone](NEXT_HARDWARE_TEST_MILESTONE.md).** This retains the original U1 workstream E/F test/qualification detail while applying the owner-authorized [temporary I²C bootstrap](I2C_BOOTSTRAP_CUTOVER.md), [stream-first execution order](FOUR_MILESTONE_STREAM_FIRST_EXECUTION_ORDER.md) and [ELF load performance gate](U1_ELF_LOAD_VERIFICATION_PERFORMANCE.md). Proportionate builds/checks establish software completion; owner alone begins physical qualification. Do not invent an intermediate milestone or force a full I²C-controller ELF conversion in U1.

## Workstream E — integrate and validate without intermediate owner tests

1. Add deterministic host tests at the **actual production** ordinary manager, catalog adapter, graph executor, registry/event API and provider-call boundaries: every kind/from both sources; no-catalog offline; release snapshot mismatch; duplicate IDs/dependencies/cycles; malformed/extra/missing files; mixed versions, corrupt SHA/ELF/import; active-module update refusal; interrupted download, stage/backup/uninstall recovery; provider install without activation; producer-provided device records, provider selection including another `serial.port`, unplug/reattach generation invalidation, competing clients, failed quiescence and no compiled USB fallback. Focus on stable invariants and demonstrated defects; do not build brittle comprehensive milestone-wide test bureaucracy.
2. Add static architecture gates over compiled/link-reachable normal firmware source and firmware ELF/map: reject USB host/class/chipset, `NativeUsbBridge`, `UsbSerialProjection`, hard-coded USB driver IDs/VIDs, `/usb-provider-catalog.json` and `BOARD_T5S3_PRO` USB-selection logic outside driver source and documented boot-only allowlist. **For I²C/charger, distinguish actual firmware device semantics (reject) from the single explicitly scoped transitional bus-only port API (allow until U3; record exact files, callers and version).** Reject duplicate runtime bus/controller ownership and inappropriate app access. Check no package signing code/tool/required release step and no signed-only paths link into ordinary firmware. Avoid simplistic regex false positives on generic strings, API documentation or compiled debug-console port.
3. Execute relevant host suites, package tests, provider relocation/import audits, `build_all_apps.py`, manifest-derived functional driver builds, the two available firmware environments and release-equivalent artifact staging where feasible. Preserve firmware binaries outside mutable `.pio` before ELF builds and verify checksums before staging. Verify asset list from built outputs, not a reconstructed name guess. Running CI is supplementary: continue independent implementation while it executes, record actual outcomes without a blocking wait loop. Test I²C transfer bounds, authorization, single-owner failure, missing dependency and safe power/rail sequencing proportionately; **no mandatory full I²C ELF handoff test before U3**. Include generation-bound ELF verification and normal launch/inventory latency regression.
4. Record what passed/failed/not run at exact commit in a `U1` milestone ledger/PR description. Fix known software/build/test defects before marking READY. Owner-only electrical/hardware behaviors stay UNTESTED, not PASS. Do not automatically publish a release to prove a build.

## Workstream F — one physical-test handoff, after the implementation work

Provide exact firmware application/merged image identification, app and driver versions and matching architecture/ABI, immutable release/artifact identifier or reproducible build commands, full install order, SD-backup and rollback/recovery instructions, a captured test log template, expected errors/indicators and **one** end-to-end hardware procedure:

1. Cold boot with no optional USB providers installed: normal UI/SD/package manager still works, USB/serial capability absent, no firmware USB fallback or unexpected VBUS drive. Install USB prerequisites and class ELFs through generic online/offline manager; confirm inventory and dependency order; install/update Serial Monitor and open it through `serial.port` without reboot/firmware recompile where supported. Note the explicitly installed power/expander ELFs and transitional bus API if still required, without falsely claiming full I²C extraction.
2. Connect the known-working ESP32-S3-CAM CDC test device; verify sustained VBUS through boot, enumeration, correct class/probe, configured baud and DTR/RTS if supported, receive sustained logs and transmit where device supports it. Separately test a CP210x device if available; do not claim CP210x physical PASS without one. Verify display/scroll/UI, and check Serial Monitor/port reopening.
3. Disconnect/reconnect repeatedly including rapid replug; verify device generations, revocation, no stale session, provider-published events and stream loss/recovery, no power/heap/task leak. Exercise simultaneous clients and expected exclusive physical ownership. Test abort/close/unload, safe IRQ/DMA/host drain and power role/charger conditions; do not intentionally create an electrical hazard without suitable measurement. Where USB power uses transitional I²C, confirm one bus owner and safe failure/timeout rather than require premature controller-ELF takeover.
4. With SD backup, remove/disable a USB class provider and then host/controller, verify its capability vanishes, active users fail/release safely, and no compiled-in USB path restores function. Reinstall driver alone, observe capability return without firmware flash; test corrupted/missing driver and interrupted replacement preserving last good generation. Inspect boot/recovery separately. The temporary bus primitive must not independently make USB work without the missing hardware-owning ELFs.
5. Test a non-USB or newly added fixture package not listed in the old catalog, plus representative application/driver/service/provider offline+online operations and catalog offline behavior. Note limitations on EPD47/other ESP devices explicitly; do not infer cross-chip binary compatibility from ESP32-S3 builds. If an I²C device is the independent witness, verify its *device behavior* actually resides in its ELF and call out the remaining transitional controller API explicitly.

Only the owner can close physical acceptance. On failure, retain full source/test continuity on the same branch/PR and fix the discovered defect; do not open a parallel speculative redesign. Full I²C controller takeover, final removal of the temporary firmware API and T5 Pro peripheral migration belong to U3; U4 remains one real camera image after provisioning.
