# U1 detailed validation and one owner hardware-test handoff

**Binding companion to [U1 milestone](NEXT_HARDWARE_TEST_MILESTONE.md).** Retains U1 workstream E/F validation while applying [I²C bus ELF cutover](I2C_BOOTSTRAP_CUTOVER.md), [stream-first order](FOUR_MILESTONE_STREAM_FIRST_EXECUTION_ORDER.md) and [ELF load performance](U1_ELF_LOAD_VERIFICATION_PERFORMANCE.md). Proportionate builds/checks establish software readiness; owner alone begins physical qualification. U1 requires the stable **I²C ELF provider boundary**, not complete ELF-owned controller hardware.

## Workstream E — integrate without intermediate owner tests

1. Test production package transaction, generic catalog and graph executor, registry/events, provider calls and stream rights: online/offline for all four kinds, no-catalog operation, snapshot mismatch, malformed/missing/extra files, duplicate/conflicting versions, corrupt SHA/ELF/import, active replacement, interrupted recovery and removal, provider install without activation, multiple providers including alternative `serial.port`, disconnect/reconnect generations, competing clients, failed quiescence and no compiled USB fallback. Focus on durable invariants and demonstrated defects, not a new broad E2E suite.
2. Audit compiled/link-reachable firmware/ELFs: reject firmware USB host/class/chipset/session/projection, hard-coded USB IDs/VIDs, named USB catalog and signing-only code. **I²C rule:** the installed I²C bus ELF is the only permitted consumer/importer of the explicitly versioned temporary firmware port I²C ABI. Reject direct firmware I²C imports in power, expander, USB, touch, RTC, charger/gauge and any other peripheral driver or application; reject firmware peripheral register/control behavior, a competing firmware-published `i2c.bus`, and any USB fallback. Record actual bus ELF package ID, public capability/ABI, private primitive symbols, import allowlist, controller lifetime and U3 removal action. Treat documentation/debug-console mentions separately from compiled code.
3. Exercise I²C ELF startup without cyclic power dependencies, bounded transfer/timeouts, exclusive ownership, consumer permission, missing/corrupt/disabled bus ELF, revocation and safe rail defaults; dependent power/USB ELFs must fail closed when the bus ELF is absent even though firmware primitive code exists. Confirm upstream packages declare `i2c.bus`, not `kernel.i2c`, and their imports remain valid against a mock replacement bus-provider implementation with identical ABI. **No hardware-owning bus-controller cutover is required until U3.**
4. Run focused host tests, package/ELF relocation/import audits, available app and driver builds, both supported firmware environments and release-equivalent artifact staging where feasible. Preserve/checksum firmware outputs before mutable ELF builds. Include installed-generation hash/launch latency regression. Continue independent implementation while CI runs; record actual PASS/FAIL/NOT RUN and no fictitious physical PASS. Fix known blocking defects before completion.

## Workstream F — one owner hardware session after software implementation

Provide matching firmware/apps/drivers/versions/architecture, artifact IDs, installation order including the **I²C bus ELF before its power/expander dependents**, SD backup and recovery instructions, expected diagnostics and one coherent test procedure:

1. Cold boot without optional USB ELFs: USB/serial absent, UI/SD/package management retained, no unexpected VBUS or USB firmware fallback. Install I²C bus ELF and power/expander/USB ELFs through common manager; verify graph and normal `i2c.bus` publication, Serial Monitor via `serial.port`, baud and DTR/RTS. The I²C bus may still delegate its *internal raw transfer implementation* to the temporary firmware ABI.
2. Connect ESP32-S3-CAM CDC serial device and verify sustained VBUS/boot, enumeration, actual driver probe, RX logs/TX and app display/scroll; check a CP210x device only if available. Record untested physical variants explicitly.
3. Exercise disconnect/reconnect, generation revocation, multi-client contention, abort/unload, resource leakage and safe IRQ/DMA/host/power shutdown. If USB power needs I²C, verify one bus owner, finite failures and safe rail states; do not force full I²C ELF controller takeover prematurely.
4. Disable/remove USB class and host/controller ELFs and check loss/recovery without firmware USB substitution; separately disable/remove **the I²C bus ELF** and verify its capability and every dependent power/USB capability disappear or fail safely. The temporary firmware primitives must be unusable by device ELFs when the bus ELF is absent. Reinstall packages and exercise corrupted/missing/interrupted replacement preserving last-good generation; inspect boot/recovery separately.
5. Exercise an unrelated real device ELF witness, all four package-kind operations and offline catalog absence. For an I²C witness, its register/device behavior stays in its own ELF, its bus access goes via installed `i2c.bus`, and only the bus ELF imports firmware raw I²C temporarily. Do not infer multi-board hardware compatibility from one ESP32-S3 test.

Owner closes physical acceptance. Preserve the same implementation PR on failures. U3 changes only the I²C bus ELF's controller backend, removes temporary firmware I²C entry points/imports and verifies earlier migrated consumers still work against its unchanged public capability. U4 remains provisioning plus one real camera image.
