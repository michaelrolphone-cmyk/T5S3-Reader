# RiscRTE ordinary package format and source index

**Normative current package format, September 18, 2026.** Read [RISCRTE_PLATFORM_SPEC.md](RISCRTE_PLATFORM_SPEC.md), [PACKAGE_MANAGER_SCOPE_CONTRACT.md](PACKAGE_MANAGER_SCOPE_CONTRACT.md) and [UNIFIED_PACKAGE_MANAGER_MVP.md](UNIFIED_PACKAGE_MANAGER_MVP.md). Implement remaining source adapters/catalog and remove obsolete signing code as one integrated [U1 milestone](NEXT_HARDWARE_TEST_MILESTONE.md). This document describes the ordinary format in the merged implementation and required compatibility, not the former proposed P-256 archive. The experimental signed archive's old design exists in git history only after the explicitly requested repository purge; it is neither an active spec nor an accepted package format.

## Package semantics

A distribution package has one kind: `application`, `driver`, `service` or `provider`. These are manifest types, not distinct installation engines. A physical driver may also act as a capability provider. Existing ordinary installations use a bounded `.package.json` alongside payloads, with an `entries` inventory and a singular `artifact` ELF when applicable. Preserve existing working ELF+JSON sidecar inputs by converting them through a source adapter. New source compatibility is not permission to maintain independent app and driver installation transactions.

A normal manifest contains a bounded schema/version, kind, safe stable ID, canonical version, architecture and minimum compatible runtime API, artifact path/name, bounded entry inventory (`name`, `size_bytes`, `sha256`, `executable`), and capability/version requirements. The generator may supply an additional provider-ABI/import declaration as ordinary checked payload data. A manifest must not encode or grant loader privilege or publish a device merely by being installed. Fields and input bounds must match the **actual** validated ordinary parser before changing on-disk schema; any extension is deliberate, documented, versioned and compatible with installed assets.

Reject truncated/malformed JSON, duplicate identities or entry aliases, path traversal, absolute or unexpected paths, invalid versions/architecture/ABI, incompatible dependencies, unsupported ELF, missing/extraneous files, bad lengths and mismatched hashes. SHA-256 here checks *byte consistency and corruption*, not publisher authenticity. Validate source bytes, reread/validate the manager-owned stage and validate the installed generation; keep exact privately owned executable bytes for privileged-loader checks. Distinct loader policy determines allowed OS/CPU imports, grants and activation. Never let a manifest or digest self-authorize privileged execution.

## Shared lifecycle

The same ordinary package inspection, dependency/ABI preflight, exclusive stage and use-gate, recovery-capable previous-generation replacement, installed inventory/update/uninstall and diagnostics serve both offline SD and online downloads. Read-only preview, download and installation are distinct; installation alone must not activate a driver or grant physical access. Preserve a known-good installed generation on failed/intentionally interrupted replacement; recover interrupted stages and uninstall tombstones without deleting unknown files. Refuse replacement/uninstall of mapped or unsafe-to-quiesce modules; quarantine and retain their dependency pins when necessary.

Offline installation requires neither a catalog, network, desktop-side Python nor signing keys. Online sources eventually deliver identical canonical directory/package inputs to the same engine, not a special driver publisher. Prior installed packages remain visible/usable and locally removable when the online source is unavailable.

## Generic online source index — not a second package format

A bounded `package-catalog.json` (or equivalent generic index) is **only** an online discovery and locator list generated from actual ordinary package manifests and exported release files for all four kinds. A row identifies kind, ID, version, target, capabilities/requirements, immutable release/source identity, asset names and declared length/SHA-256 as appropriate. The manager applies the normal manifest/entry checks again after downloading. Do not accept arbitrary unbounded source-provided paths/URLs or trust a catalog checksum as a publisher identity.

Catalog and all its payloads must be resolved against **one immutable release/tag snapshot**; independent `latest` lookups can mix index and payload revisions and are prohibited. Prevent duplicate/stale/conflicting/missing rows at export. Catalog unavailability must not prevent installed package inventory, local uninstall, normal provider activation or SD installation. A catalog never chooses a chipset, authorizes imports, makes core aware of `usb`, controls physical ownership or contains a required fixed list of drivers.

The former `usb-provider-catalog.json` was generated by `scripts/build_installed_usb_stack.py` from exactly seven hard-coded entries, required by `scripts/export_canonical_driver_release.py`, fetched by `NativeDriverManagerBridge.cpp` and paired with four fixed driver assets by `NativeOnlineDriverInstall.h`. It is a transitional production coupling, **not part of this format or target source contract**. In U1, replace producer/exporter, firmware fetch/overlay, download logic, tests and release publication with generic manifest-derived discovery. No normal runtime/build/release reference to the old name survives. Historical immutable releases may still contain their old assets, and a finite compatibility importer for old loose `.t5driver.*` or app sidecars may remain if separately documented; it may never restore the USB catalog or a firmware hardware fallback.

## Package cryptography: removed from scope and repository

The user explicitly directs purging unwanted package-signing work. Remove the P-256 archive/signature writer/verifier, signer trust/keys/revocation, signed provenance/receipts, NVS cryptographic floors, signed-only install/load assumptions, signed experiment tests/tools/release gates and obsolete experimental signed-format docs from the **active repo** after reference analysis. Extract genuinely useful bounds, hash, safe path, exact-byte checks, staging and recovery into ordinary code before deleting signed-only modules. Do not merely move the experiment to `experimental/` or replace it with a renamed signature feature. Git history retains its prior implementation; no history rewrite is required. Previously installed signed-only data must not be silently destroyed: accept it only if it satisfies the ordinary format independently, otherwise report a safe unsupported-generation state.

Unrelated TLS, general-purpose crypto services, ordinary SHA-256 file verification and independent privileged import/relocation/authorization must remain. Native ELFs share memory; unsigned acceptance does not imply memory isolation. Signing is neither necessary nor sufficient to establish physical resource safety.

## Acceptance

Prove all four kinds across SD and generic online discovery/install/update/inventory/uninstall/recovery; malformed/oversized/path/ABI/dependency/ELF/digest rejection; mixed-release prevention; interrupted and in-use refusal; legacy input parity; and operation when the catalog is missing. Add a manifest-derived new driver without modifying firmware or its package-catalog generator source. Prove no normal-path signing or old USB catalog dependency and no loss of permission/import controls. CI/host tests establish software evidence, **not** the physical USB result; the hardware-test handoff and its stop rule are [U1](NEXT_HARDWARE_TEST_MILESTONE.md#4-definition-of-done--milestone-stop-rule).
