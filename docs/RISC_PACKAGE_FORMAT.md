# RiscRTE ordinary package format, ZIP distribution and generic source index

**Normative target for U1, September 18, 2026.** Governing documents: [Platform](RISCRTE_PLATFORM_SPEC.md), [Package Scope](PACKAGE_MANAGER_SCOPE_CONTRACT.md), [Stable Identity and Version](PACKAGE_IDENTITY_VERSION_POLICY.md), [Bundled Archive and Install Layout](BUNDLED_PACKAGE_ARCHIVE_AND_INSTALL_LAYOUT.md), [Unified Package Manager](UNIFIED_PACKAGE_MANAGER_MVP.md), and [U1](NEXT_HARDWARE_TEST_MILESTONE.md). **Current implementation is NOT yet the target:** merged ordinary packages are loose `.package.json` plus files; shipped app assets may be adjacent ELF/JSON pairs and driver online intake can expect four files. U1 MUST replace normal distribution with one ZIP bundle per package and one extracted owned installation directory per package, while safely adapting legacy inputs. This new owner-authorized requirement strengthens earlier U1 language that described loose pairs as the canonical end state. The signed RISC-PKG/P-256 experiment is unrelated and must be purged, not revived.

## Package model and stable identity

All distributable packages have one of four kinds: `application`, `driver`, `service`, `provider`. They share **one** ordinary schema, source adapter, preflight, transaction/recovery, inventory, update/uninstall and generic catalog. Classification does not create four special managers, and driver/provider are not equivalent to compiled hardware ownership. The stable `(kind,id)` is the update lineage; numeric `MAJOR.MINOR.PATCH` increments on independently distributed changes. Architecture, runtime/driver ABI, firmware floor and capability API versions are separately checked compatibility fields; never create `foo-v2` just to record an ABI change. Verify source, archive manifest, installed manifest, catalog and UI share the same identity/version. See [Package Identity and Version Policy](PACKAGE_IDENTITY_VERSION_POLICY.md) for the U1 CDC migration and automated gates.

## One ZIP-compatible package artifact

**Distribution contract:** exactly one immutable, ZIP-compatible `.rte.zip` archive per `(kind,id,version,target)`, carrying the ordinary root `.package.json`, executable where applicable, all provider ABI/import metadata and arbitrary explicitly declared nested resources (fonts, images, configuration defaults, layouts, data, etc.). An executable is not required for a legitimately resource-only package. Filename is a transport label, not permission or identity. A bounded next-version ordinary schema extends `entries` for relative nested resource paths while preserving current size, SHA-256, executable/role and ABI/dependency semantics. Source files may remain separate in the repository, but current release and online distribution must NOT require an ELF plus sidecar or four individually downloaded driver files. Each generic catalog row locates one archive plus its length/hash and compatibility data; the host packer emits reproducible content from real manifests and produced payloads without a hard-coded USB driver list. The **complete** normative archive layout, ZIP parsing bounds, bootstrap ZIP service, installed directories, migration and tests are [Bundled Package Archive and Install Layout](BUNDLED_PACKAGE_ARCHIVE_AND_INSTALL_LAYOUT.md); it is a mandatory U1 completion gate, not optional future architecture.

A normal manifest contains bounded schema/version, kind, safe stable ID, canonical package version, architecture and minimum runtime API, artifact path, a declared file/resource inventory (`name` as a safe relative path, `size_bytes`, `sha256`, executable/role if applicable), and compatibility/capability requirements. Provider ABI/import declarations remain ordinary checked payload data, never privileged authorization. Match any on-disk schema extensions to the actual production parser, with versioned backward compatibility and tests; no ad-hoc ZIP-only metadata or second transaction engine. Missing, extra, aliasing and conflicting files are rejected. A digest establishes byte consistency, not publisher authenticity.

## Safe extraction and verification

The same shared package installer must parse/bound ZIP central and local records, archive size, entry count, compressed/uncompressed totals, compression ratio and memory/disk consumption before writing to a manager-owned stage; stream rather than load entire packages into RAM. Reject ZIP Slip (`..`, absolute paths, separators/normalization collisions), duplicate entries, symlinks/other nonregular files, encrypted or unsupported features, malformed/truncated/overlapping records and decompression bombs. Cross-check ZIP CRC, archive consistency, manifest-declared exact file sizes and SHA-256 of extracted bytes, and the stage/install ELF/architecture/ABI/import policy. Reject unsupported format variants instead of attempting permissive extraction. Neither ZIP metadata nor manifest/declaration/hash authorizes privileged code. Keep exact manager-owned executable bytes for admission and no time-of-check/time-of-use substitution. See archive spec for detailed negative-test matrix.

## Installed layout and shared lifecycle

The installed form is a **verified, extracted package-owned directory** for every kind, e.g. `/Apps/<id>/`, `/Drivers/<id>/`, `/Services/<id>/`, `/Providers/<id>/` beneath the validated installation mount. The directory contains its installed manifest, ELF if any, and resource tree. Resolve entry points and resource paths relative to the manager-validated package root; remove persistent assumptions about `/Apps/foo.elf` and sidecar `foo.json`. Files cannot cross package boundaries. **`/System` is not a package installation root**; its ownership/classes are defined by [RiscRTE System Storage Layout](SYSTEM_STORAGE_LAYOUT.md). User-created state resides in a distinct durable namespace, not inside a replaceable code generation. Runtime/system state derived from packages may be maintained under the appropriate `/System` semantic class without becoming package payload or installed inventory. Inventory derives from checked manager-owned manifest records, not guessed files, and installed packages remain usable offline after the archive or generic catalog disappears.

SD inbox and online download both yield the **same complete ZIP artifact** and invoke the same ordinary package preflight, dependency plan, content validation, exclusive owned stage, installation-generation transaction, use-gate, crash recovery, update and uninstall. Installation does not execute providers or grant hardware access; the independent privileged executor and execution-context policy decide activation. Preserve last-good **whole directory generation** on failed/incomplete download, extraction, commit or uninstall; refuse replacement/uninstall while code is mapped or driver fails physical quiescence and pin unsafe generations/dependencies. Cleanup only recognized manager-owned files. Legacy loose inputs and installed flat apps are migrated/adapted by a bounded, idempotent and rollback-safe source/layout adapter; historical released artifacts remain unchanged. Do not silently delete unknown SD files, installed resources or userdata to achieve a clean layout.

A versioned general-purpose `archive.zip` service provides authorized apps with generic ZIP operations, but **must not be a prerequisite for installing itself** on a new offline device. Reuse one bounded ZIP decoding library/minimal package-bootstrap path for the installer and the service; do not introduce competing installers or bring back the signed archive implementation. Boot/recovery must remain functional without the service or networking.

## Generic online source index — not a package format

A bounded `package-catalog.json` (or equivalent generic index) discovers **all four kinds**, providing kind/ID/version/target, manifest-derived compatibility and capabilities, one archive filename/size/SHA-256, and one immutable release/source identity. It does not select chipsets, authorize imports, convey trust in an untrusted hash, own hardware or determine installed activation. Pin catalog and archive download to one immutable source snapshot; never independently fetch `latest` for different artifacts. Reject duplicates, conflicts, missing/stale assets and paths outside configured source. Catalog unavailability cannot block installed inventory, local uninstall, normal provider activation or SD installation.

Former `usb-provider-catalog.json` and scripts with exactly seven hard-coded drivers, the Driver Manager's fixed catalog URL and the four-file driver intake are transitional production coupling and must be deleted/replaced in U1. The old separate app ELF/JSON download is likewise only a bounded legacy input adapter; it is NOT retained as the normal release format. An unrelated compatible new package must be auto-included from its manifest/artifact without firmware or packer source modifications. Historical immutable release assets may remain for existing deployments without becoming new production dependencies.

## Package signing is excluded and must be purged

The owner explicitly directs removing package-only P-256 signing, trust/key management, signed provenance/receipts, signed RISC-PKG archive format/tools/tests, NVS cryptographic floors and mandatory signed-only install/loader assumptions from the active repo after extracting any genuinely useful ordinary parser/hash/staging/recovery behavior. **ZIP is a packaging container, not a renamed signed archive.** Preserve unrelated TLS/general crypto, ordinary SHA-256 integrity, bounded extraction/path/ELF checks, separate runtime privilege authorization, secure execution-byte ownership and transactional recovery. Previously signed-only or unsupported installed data is preserved and safely diagnosed, never silently destroyed or self-authorized.

## U1 acceptance

Prove from the **production** manager: all four kinds, each as one `.rte.zip`, via SD/online install/update/inventory/uninstall/recovery; multiple nested resources and correct app/driver resource access; no ZIP service/network/bootstrap dependency for fresh offline installation; missing catalog after install; safe legacy flat app/driver migration; malformed/ZIP Slip/bomb/extra/duplicate/symlink/truncated/corrupt inputs; interrupt and unsafe provider quiescence; last-good whole-generation preservation. Release-equivalent build emits one deterministic archive per identity/version/target, generic index points to verified archives, and current consumers do not rely on loose distribution or flat installed app paths. Enforce versions/CDC identity and no signing or USB-specific catalog. Record firmware, app, driver, service/package build tests and archive custody at one commit; hardware verification is still one owner test at [U1](NEXT_HARDWARE_TEST_MILESTONE.md), not a prerequisite for code completion.
