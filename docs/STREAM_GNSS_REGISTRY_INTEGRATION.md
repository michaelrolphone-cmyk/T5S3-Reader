# GNSS stream / Unified Device Registry integration

**Status:** Live cooperative GNSS implementation candidate in draft PR #67; not yet validated on physical GPS hardware or approved for release. This document describes the implementation on the PR branch rather than the earlier PR #65 data-plane-only state. The canonical architectural references are [RiscRTE Platform Specification](RISCRTE_PLATFORM_SPEC.md), [Stream GNSS Record Adapter](STREAM_GNSS_RECORD_ADAPTER.md), [Runtime Driver Architecture](RUNTIME_DRIVER_ARCHITECTURE.md), and [Platform Capability Roadmap](PLATFORM_CAPABILITY_ROADMAP.md).

## One device registry, one stream registry

`RuntimeDevices::systemRegistry()` is the only production device registry. The existing `RuntimeStreams::Registry` in `src/native/NativeStreamBridge.cpp` is passed by reference into `LiveGnssSession`; no separate stream registry or GPS polling task is created. `LocationLeaseBinding` verifies actual, generation-qualified `location.position` Registry grants. A manifest `Dependency` lease cannot serve as physical provider authority. `GpsDriverRuntime::borrowLocationSource()` returns the driver-owned device handle and *borrowed* physical grant only on the owning task in the running execution context, while the ELF driver is active. This accessor is firmware-only and never transfers lease ownership.

The bridge serializes attach, subscription, record publish, record read, pipe pumping, disconnect and cleanup using its existing stream mutex. The installable GPS ELF's synchronous UART read executes on its claiming application task **outside** that mutex; only a copied `t5_gps_state_t` is submitted to the coordinator. If one subscriber's bounded queue is full, all-or-nothing publication retains one pending copied observation. `beforePoll()` retries that observation before allowing another hardware read; retry success also consumes the current poll. No-fix, stale observations, and duplicate accepted fixes do not become fabricated valid records. Optional measurements are unverified by default; numeric zero does not establish field presence.

On driver stop, the GNSS binding is disconnected before module unload, UART release or release of the driver's source grant. Subscriber device grants are relinquished and previously accepted records may drain to a terminal `DISCONNECTED` result. Context teardown releases subscription state before ELF unload. A new physical-device generation must acquire new leases and subscriptions; stale identities are not rebound.

## Separate access and physical ownership

`T5LocationApi.h` defines semantic API v1: `t5_location_get_api(1)` exposes `subscribe(authorization, token, stream)`, `poll(authorization)` and `unsubscribe(token)`. A caller must obtain `location.position` with READ rights through the trusted device API v3 `request()` flow (or a trusted existing grant); the semantic bridge validates the actual issued grant, current execution context, exact device generation, READ right and exact capability name. An altitude grant, raw hardware grant, or manifest dependency is not enough. It never receives application-supplied owner IDs or driver ELF pointers.

The active GPS source grant remains owned by `GpsDriverRuntime`. Consent-derived capability handles are separate non-authorizing dependency-mode registry leases; subscribers obtain their own shared `location.position` registry leases. `ExecutionContext::GnssDriver` is a distinct cleanup resource from `DeviceLeases`, so permission grants and GPS startup can coexist in either order. The GPS cleanup runs before stream cleanup, prevents module unload before disconnect, and releases its borrowed source grant exactly once.

**Concurrency limitation:** The implementation supports up to four independent typed-record subscriptions in its data-plane class. The firmware currently launches one application ELF at a time and polls GPS cooperatively on the claiming task. This is not yet a background location service delivering simultaneous data to four independently running applications. The stream scheduler never calls the GPS ELF.

**Discovery limitation:** The board GPS registry descriptor is currently published lazily when `GpsDriverRuntime::available()` is queried. The diagnostic app explicitly calls the legacy GPS API's passive `supported()` function before enumerating the device; it does not perform legacy GPS start/read. Generic pre-host GNSS discovery remains a separate follow-on change.

## Native diagnostic application

`Apps/gnss_stream_diagnostic.c` and its matching package manifest provide a real ELF consumer. It discovers the GPS registry device, requests explicit physical-button READ permission, starts/subscribes through the semantic location API, validates the record stream's exact `location.fix.v1` schema and read-only flags, polls on the app task, and decodes the 52-byte little-endian wire record without casting it to a native struct. It displays fix count, latitude, longitude, satellites and fix age, and releases the subscription and authorization on normal exit.

## Tests and acceptance gates

`test/streams/location_production_registry_test.cpp` covers production Registry grant validation, actual state revocation and journal loss, backpressure and retry, queued-record draining and generation replacement. `test/resources/gnss_permission_lifecycle_test.cpp` checks both permission-first and GPS-first acquisition orders, distinct cleanup handlers, zero residual grants and stale authorization rejection. `test/streams/location_native_bridge_test.cpp` links the real location ABI bridge and production permission registry against mocked physical GPS and downstream stream functions; it rejects invalid owner authority, manifest dependencies, unrelated capability grants and post-release/post-replacement handles. Host tests execute through `test/run_stream_test.sh` and `test/run_driver_test.sh`; firmware, ELF and application builds execute through `.github/workflows/platformio-build.yml`. Record CI results against the exact commit; never claim success for a cancelled or earlier run.

**Release gate:** Build both `t5s3-pro` and `lilygo-epd47-s3`, compile and validate the diagnostic ELF and both installed drivers, and run the host suite. Then exercise a real board and installed `gps-nmea` package: consent approval and denial, no-fix suppression, multiple actual fixes, record schema/coordinates, backpressure recovery, physical device loss, app exit/reentry, power ownership, and teardown without stale handles. The tests above provide simulated evidence only; physical acceptance is still outstanding until independently recorded. Do not merge PR #67 as fully accepted solely because host/firmware CI passes.
