## Shared implementation, not a second registry

`src/runtime/capabilities/DeviceRegistry.h` on this branch is the **identical Git blob** `6947ec84591698dfab166f41c3c10c2b947f5603` from PR #64 (`feature/unified-device-registry-leases`). This copy permits actual compile-time and host contract validation while the feature branches are independently reviewed. It does not create another registry class, instantiate a second firmware-wide instance, or back-port PR #64's driver, discovery, ELF observation interface and lifecycle wiring. Merge PR #64 before PR #65; when reconciling branches retain the single canonical file and its single `RuntimeDevices::systemRegistry()` instance. Verify that its blob remains in sync if PR #64 changes before integration.

`GnssRecordAdapter.cpp` explicitly instantiates `LocationLeaseBinding<RuntimeDevices::Registry, RuntimeDevices::LeaseInfo>` in both firmware builds. `test/streams/location_production_registry_test.cpp` uses that production registry directly rather than a test double and exercises genuine shared grants, owner refusal, source/consumer revocation, queued record draining, journal `CapabilityLost`, stale physical-device generations, and borrowed source-lease cleanup. The pre-existing test-double suite still exercises targeted negative paths. The host runner compiles both under address/undefined-behavior sanitizers; CI conclusions apply only to the exact checked commit.

## Wiring required for an actual location stream

1. Converge PR #64's `GpsDriverRuntime` invocation-owned `location.position` acquisition and lifecycle journal with PR #65's single shared stream registry. The GPS driver already owns a task-restricted synchronous UART reader; do not call it from the stream pipe scheduler or introduce an unrelated device registry.
2. Expose the driver's **existing borrowed** device handle and provider lease through a firmware-only, owner-validated accessor, then attach exactly one `LocationLeaseBinding` for that device generation. The stream bridge must authenticate the running `ExecutionContext` before allowing a subscriber to acquire its own shared capability grant; do not take app-supplied owner IDs or grant identifiers as authority.
3. Use the *same mutex* for all stream registry/coordinator/binding operations, including cleanup and subscriber reads. Read GPS on its claiming task outside that lock, copy `t5_gps_state_t`, and then submit under the lock. If a record is pending, retry it before polling another hardware observation. Validate optional measurement provenance; do not manufacture verified fields from zeros.
4. On capability-loss/removal or driver stop, invalidate source and pending state and immediately release the subscription-side grants. Keep accepted records readable until the finished queues drain. Release stream/subscription state before unloading the app ELF, and release the borrowed source grant only from the GPS driver. A replacement physical-device generation requires new grants and subscriptions.
5. Export a separately versioned, context-authenticated semantic subscription getter to ELFs and test it with real native-app launch/teardown. PR #64's device **observation** API (`T5DeviceApi.h`) only enumerates and observes device events; it intentionally does **not** authorize hardware access or subscribe to position data.

Until these steps are implemented and physical board tests cover no-fix, stale fixes, backpressure, reconnect, power and teardown, `location.fix.v1` is a tested data-plane foundation, **not a live end-to-end GPS feed**.
