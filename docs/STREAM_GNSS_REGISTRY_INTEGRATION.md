# GNSS stream / Unified Device Registry integration

**Status:** Live cooperative GNSS implementation candidate in draft PR #67, including dependent provider authorization in the **same PR targeting `master`**. Not yet validated on physical GPS hardware or approved for release. Canonical references: [RiscRTE Platform Specification](RISCRTE_PLATFORM_SPEC.md), [Stream GNSS Record Adapter](STREAM_GNSS_RECORD_ADAPTER.md), [Runtime Driver Architecture](RUNTIME_DRIVER_ARCHITECTURE.md), [Provider Authorization Integration](PROVIDER_AUTHORIZATION_INTEGRATION.md), and [Platform Capability Roadmap](PLATFORM_CAPABILITY_ROADMAP.md).

## One device registry, one stream registry

`RuntimeDevices::systemRegistry()` is the only production device registry. The existing `RuntimeStreams::Registry` in `src/native/NativeStreamBridge.cpp` is injected into `LiveGnssSession`; no second registry or GPS polling task is created. `LocationLeaseBinding` verifies generation-qualified `location.position` Registry grants. A manifest `Dependency` lease cannot serve as physical provider authority. `GpsDriverRuntime::borrowLocationSource()` returns the driver-owned device handle and *borrowed* physical grant only on the claiming task in the running execution context, while the ELF driver is active. It is firmware-only and never transfers lease ownership.

The bridge serializes attach, subscription, record publish/read, pipe pumping, disconnect and cleanup using the existing stream mutex. The installable GPS ELF's synchronous UART read runs on its claiming application task **outside** that mutex; only a copied `t5_gps_state_t` enters the coordinator. If one bounded subscriber queue is full, all-or-nothing publication retains one pending observation. `beforePoll()` retries it before another hardware read; successful retry consumes that poll. No-fix, stale and duplicate accepted fixes are suppressed. Optional measurements default to unverified; numeric zero does not prove presence.

**Startup is transactional:** if the ELF module reports ACTIVE but its source cannot be borrowed, or if `nativeGnssAttach()` rejects the semantic stream (such as resource exhaustion or outstanding undrained subscriptions), `GpsDriverRuntime::start()` now returns false, stops/unloads the module, releases UART and its physical lease, and unregisters its temporary cleanup handler. A later invocation/attempt can retry after resources are available; a stream-only attachment failure does not mark a healthy receiver as physically Failed. Never report a functioning `location.fix.v1` service merely because the UART driver started.

On driver stop, GNSS binding disconnects before ELF unload, UART release or source-grant release. The internal data plane marks accepted records drainable to terminal `DISCONNECTED`, releases subscriber device grants, and never rebinds stale generations. **Public consent is stricter:** if original permission is revoked, released or invalidated by replacement, subsequent raw stream access destroys that subscription and queue, returns `DENIED`, and cannot drain its accepted records. Hardware loss never grants permission to expose buffered location data.

## Separate consent and physical ownership

`T5LocationApi.h` defines semantic API v1: `t5_location_get_api(1)` exposes `subscribe(authorization, token, stream)`, `poll(authorization)` and `unsubscribe(token)`. A caller obtains `location.position` READ through trusted device API v3 `request()` (or a trusted existing grant). The bridge checks issued permission, running context, exact generation, READ right and capability before starting hardware, after startup and after subscription. Altitude, raw hardware and manifest dependency leases do not authorize position. App-supplied owner IDs and driver ELF pointers are not accepted.

The concrete issued consent handle is bound to each returned stream through firmware-only `GnssStreamAuthority`. Generic `record_read`, `record_info`, byte read/write and metadata operations recheck it. Revocation closes and clears the queue; regranting through a new handle cannot restore an old stream. `close()` and semantic `unsubscribe()` release matching subscriber grant and binding. Generic `connect()` denies GNSS endpoints even with valid consent: copying into an unprotected destination would bypass later revocation. GNSS-to-file/recorder delegation needs explicit permission propagation and sink purge/cancel semantics first. Already read app memory cannot be retracted; this mechanism does not provide ELF memory isolation.

The active GPS source grant belongs to `GpsDriverRuntime`. Consent-derived handles are separate dependency-mode registry leases and each subscriber obtains its own shared `location.position` lease. `ExecutionContext::GnssDriver` is distinct from `DeviceLeases` so granting permission and starting GPS can coexist in either order. Driver cleanup precedes stream cleanup; source lease is released exactly once.

**Concurrency limitation:** Four independent typed-record queues exist, but the firmware launches one application ELF at a time and polls GPS cooperatively on the claiming task. It is not a background service simultaneously serving four independent application tasks. Stream scheduler never invokes GPS ELF; GNSS pipes remain denied. Independently running future tasks require shared synchronization for permission mutation/stream validation.

## Passive GNSS discovery

On ESP32, `src/native/NativeDeviceBridge.cpp` passively calls `GpsDriverRuntime::available()` from inventory, observation and authorization methods. First call scans immediately; later scans are throttled to ten seconds with wrap-safe `millis()` subtraction, avoiding repeated package hashing. Discovery publishes receiver descriptor and package availability to the **existing** Unified Device Registry without starting GPS, claiming UART, powering the receiver or granting permission. Missing packages appear unavailable on supported hardware and newly installed packages may take one discovery interval to appear. Host USB fixtures omit this ESP32 hook.

`Apps/gnss_stream_diagnostic.c` uses device observation, semantic `T5LocationApi` and record streams, not legacy `T5GpsApi`. Discovery is on demand, not an autonomous main-loop scan; a background GNSS discovery/service worker remains follow-on work.

## Native diagnostic application

The diagnostic ELF and manifest discover the receiver, request physical-button READ permission, start/subscribe through semantic location API, validate exact read-only `location.fix.v1` schema, poll on the app task and decode the 52-byte little-endian record without native-struct casting. UI shows fix count, coordinates, satellites and fix age; it releases subscription and authorization on exit. Minimum firmware is **1.2.16**: `master` reached **1.2.15 without the semantic location API**. Preserve the original 1.2.15 firmware binary on backmerge and never label that older image as providing these capabilities.

## Tests and acceptance gates

`test/streams/location_production_registry_test.cpp` covers the production registry, source grants, backpressure/retry, queue drain and generation replacement. `test/resources/gnss_permission_lifecycle_test.cpp` verifies permission-first/GPS-first cleanup. `test/streams/location_native_bridge_test.cpp` links the actual semantic ABI bridge with mocked GPS/stream functions and injects revocation during driver startup and subscription. `test/resources/gnss_stream_authority_test.cpp` checks original-consent binding, release/regrant, dependency spoofing, unrelated permission, revocation and generation replacement. **`test/drivers/gnss_startup_failure_test.cpp` compiles the real `GpsDriverRuntime.cpp`** against mocked module/kernel/stream boundaries under sanitizers; it verifies stream attach failure releases bus/lease/context resources, retry succeeds, malformed module ACTIVE state fails closed and invocation teardown stops the provider. The raw stream bridge is compiled in both firmware targets. Host CI is not physical hardware validation.

**Release gate:** Pass host suites, both firmware builds, native ELF/released app validations, installed driver checks and artifact staging at the final head. Test an actual board with the installed GPS package: discovery without legacy calls; consent approval/denial; no-fix suppression; repeated real fixes, schema/coordinates, backpressure/retry, device removal, revoked raw-read denial, app exit/reentry, power ownership and cleanup. A simulated or compiled path is not hardware acceptance. PR remains draft until physical acceptance is recorded.
