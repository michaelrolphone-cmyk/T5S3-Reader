## Existing useful stabilization work — preserve, do not duplicate

The Driver Manager supports a compatibility `/Drivers/<id>/driver.elf` plus `manifest.json` view and publication via a shared ordinary four-kind transaction. It applies kind/identity/version/ELF/ABI/inventory/hash preflight, exclusive replacement leases, newer-semver upgrade, stage/target revalidation, backup and uninstall tombstone recovery; mapped packages cannot be replaced arbitrarily. Legacy `.install`/`.previous` recovery precedes `.pkg-stage`/`.pkg-previous` recovery. Installation does not activate a driver or grant hardware privileges.

Catalog/install/recovery mutations use a common reservation. Installed integrity, version, unresolved backup/removal, pending stage and mapped pins are checked before a download, with publication lease revalidation. Native-stream and HTTPClient fallback create `.part` exclusively and cannot truncate another transfer. The UI compares numeric versions and prevents equal-version/downgrade action. `PackageOrdinaryStageRecovery.h` offers four-kind source-independent read-only inspection, verified stage retry and selective explicit discard; `DriverStageActions.cpp` adapts it to bounded real SD driver manifests and verified, inventory-exact stages.

The user-facing offline Driver Manager recovery screen already exists. `NativeDriverManagerBridge.cpp` exposes append-only refresh/count/get/retry/discard with its shared mutation lock, scanning only reserved download/stage paths. Verified retry uses ordinary publication lease and rehash/version checks; arbitrary/unknown files are never deleted. `.part` alone has no manifest and can only be discarded after explicit inspection/confirmation, not published. Unresolved/mapped generations do not offer destructive recovery actions. The recovery view appears **before Wi-Fi** and can inspect stages no longer listed online. `T5DriverManagerApi.h` maintains append-only ABI-v1 `struct_size` guards; `Apps/driver_manager.json` was updated to 1.0.1 in that integration.

Host tests compile the app and check cancel/confirmation, retry, mapping refusal and stage handling, but do not prove SD power-cut persistence, electrical USB behavior or real IRQ/DMA quiescence. Legacy recovery ambiguity or invalid generations require explicit diagnosis; never delete unmanaged content to make the UI look clean.
