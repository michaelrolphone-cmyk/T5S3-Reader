# Unified manager and hardware ELF stabilization acceptance

Follow-up to merged PRs #76 and #78. PR #79 must not be merged, auto-merged, published or flashed by an agent; the repository owner decides when to merge and test. Green CI is not physical qualification.

## Current implementation: Driver Manager compatibility and recovery

The Driver Manager retains the working `/Drivers/<id>/driver.elf` and `manifest.json` layout. Publication uses the shared four-kind ordinary transaction: canonical kind/ID/version/artifact, exclusive replacement lease, newer-semver upgrades, independently verified stage/target, backup recovery and uninstall tombstone support. Legacy `.install`/`.previous` recovery precedes new `.pkg-stage`/`.pkg-previous` recovery. Every generation is checked against its own manifest, exact directory inventory, ELF structure, size and SHA-256. Installation never activates hardware or grants privileges.

The catalog/install operations share a mutation lock and snapshot selected metadata across network callbacks. Installed integrity/version, unresolved backup/removal, pending stages and mapped-driver pins are checked *before* Wi-Fi/download; the publication lease still handles races. Native streams and HTTPClient fallback create `.part` exclusively and cannot truncate another transfer's stage. Native transfer cleanup deletes only files it proved it created. The UI compares numeric package versions and suppresses equal-version/downgrade actions.

`PackageOrdinaryStageRecovery.h` provides four-kind, source-independent read-only inspection, verified retry without redownload and selective explicit discard. `DriverStageActions.cpp` adapts it to real SD driver directories, a bounded retained manifest, rehashed ELF, exact file inventory, and manifest-last cleanup. Unknown files/directories and unresolved legacy generations are never silently deleted.

The Driver Manager **now has a user-facing offline recovery screen**. Firmware `NativeDriverManagerBridge.cpp` exposes append-only recovery ABI methods for refresh/count/get/retry/discard, scans only the reserved `/Drivers/.driver-manager.part` and safe `.<id>.pkg-stage` names, and uses the SAME mutation lock as downloads and catalog refreshes. Its stage retry uses the shared publication lease, hash verification, and version checks; `.part` can only be discarded as a regular file at the exact manager-owned path, not retried without a manifest. The recovery screen runs before any Wi-Fi request, recognizes stages absent from the release catalog, allows explicit retry where validated, and offers a separate default-to-Keep confirmation before discard. Mapped or unresolved generations have no destructive UI action. Existing `T5DriverManagerApi.h` remains ABI-v1 and appends optional methods after the old prefix, guarded by `struct_size`. Updated native app manifest: `Apps/driver_manager.json` version **1.0.1**.

**Limitations:** The on-device UI is not a general file browser or a recovery tool for unknown/unmanaged files. Existing legacy `.install` and `.previous` entries require the normal generation-recovery path; an invalid target or ambiguous backup requires manual diagnosis. An interrupted loose `.part` has no reliable manifest/identity and must be discarded after inspection rather than published. Host tests compile the actual app and exercise cancelled versus confirmed deletion, stage retry and mapped refusal; CI compilation alone does not exercise physical SD power interruptions.

## Remaining before the *full* unified manager and physical driver migration

- One canonical bounded on-device manifest/parser for all four kinds, shared offline SD and download adapters, one installed inventory/update/uninstall API, compatible dependencies; migrate existing App Store and offline file browser without breaking flat ELF pairs.
- Privately owned manager-validated executable bytes/metadata handed to the PR #78 generic provider executor, with independent import/relocation checks, capability leases and no implicit activation on install.
- Remove competing compiled USB/I²C hardware owners before enabling physical ELF counterparts; qualify power/hotplug, IRQ/DMA quiescence, teardown/recovery and actual I²C transactions on both board variants.

## Physical test protocol for this PR

1. Record the exact PR head, board variant, SD payload revisions and boot serial log; back up SD before fault injection. Old `master` firmware does not contain PR-only recovery controls. Test using a separate explicit build/flash procedure; neither this PR nor CI flashes the device. Install the matching Driver Manager **1.0.1** ELF/manifest from this branch.
2. Install a driver. Verify manifest and ELF SHA-256 and installed version after reboot. Check Installed, Update, Installed newer and `1.10.0` versus `1.9.99`. Reject equal/downgrade versions before network transfer.
3. On a backed-up card, place a sentinel at `/Drivers/.driver-manager.part`. Open Driver Manager **without Wi-Fi**: recovery must appear before catalog, identify the download and show size. Cancel the action and verify byte-for-byte preservation; deliberately confirm Discard and verify only that exact regular file disappears. Repeat with a directory at the reserved path: discard must be refused. Test native-stream and HTTPClient fallback exclusivity separately.
4. Create a valid newer `.<id>.pkg-stage` while retaining the verified older target. Reboot without Wi-Fi, inspect the entry, cancel Retry, and confirm both generations unchanged. Select Retry and verify independent SHA/identity/version validation, publication and backup cleanup, then verify the displayed installed version after reboot. Repeat for a stage whose ID is **absent from the latest release catalog**.
5. Plant malformed/corrupt, stale/equal-version, unknown extra-file, nested-directory and partially purged stages on a backed-up SD. Inspection must report the relevant blockage, retry must not publish, and Discard must require two deliberate UI actions. Unknown content must never be removed. With a mapped driver, retry/discard must be refused; test a load racing the advisory check and confirm the final lease prevents replacement.
6. Interrupt after target->backup, stage->target, and target->removing. Verify reboot recovery preserves the committed state, never resurrects an uninstall, and never deletes unrelated entries. An unresolved generation or invalid installed ELF must not be presented as a fresh safe installation.
7. Test sustained USB serial power, enumeration, baud, disconnect/reconnect and teardown. Qualify actual hardware-owning USB/I²C provider ELFs separately only once firmware hardware-owner handover and loader activation are implemented.
8. For each of application, driver, service and provider, test offline and online install, dependency/ABI rejection, corruption, power cut, inventory and uninstall only if the corresponding live route is connected. Mark missing routes NOT IMPLEMENTED, not PASS.

No mandatory signatures, signer keys, signed provenance, or cryptographic NVS floors are in scope. SHA-256 detects content mismatch; it is not publisher authentication.
