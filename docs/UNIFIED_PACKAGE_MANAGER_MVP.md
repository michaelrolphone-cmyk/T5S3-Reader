# Unified Package Manager MVP — implementation and acceptance

**Status:** Roadmap priority 3, draft PR #76. A common privileged signed RISC-PKG intake → extraction → recoverable publication API now exists for applications, drivers, services and providers. The existing App Store and driver installers **still use their separate unsigned, integrity-checked publishing paths** and have NOT been migrated to the new API. Production signing-key allowlists are not provisioned; signed installed SD files are not protected against replacement through `dlopen`. The new publisher is therefore not authorized for production loading or release.

Authority: [RiscRTE Platform Specification](RISCRTE_PLATFORM_SPEC.md) → [Platform Capability Roadmap](PLATFORM_CAPABILITY_ROADMAP.md) §§26–28 and §39 → [RISC-PKG v1 format](RISC_PACKAGE_FORMAT.md) → [Security Architecture](SECURITY_ARCHITECTURE.md). This is an actual-state tracker rather than a replacement for those specifications.

## Required invariant

One runtime-owned manager authenticates and installs all four package kinds from identical bytes regardless of offline SD or online transport. The deterministic signed envelope binds identity, architecture/ABI, dependencies, entry SHA-256, security version and publisher key. Firmware/device policy—not package metadata—controls trust and rights. Installation grants **no hardware permission or activation**. Interrupted updates must preserve an authenticated generation; the exact authenticated executable bytes must remain bound through loading despite removable-SD changes.

## Implemented: legacy transitional paths

- `PackageIdentity.h`, `PackageJsonGuard.h`, `PackagePreflight.h`: bounded four-kind identities, duplicate-safe JSON, ABI/dependency metadata, budgets and numeric version policy. These checks alone do not authenticate publishers.
- `package_integrity.py`, `build_all_apps.py`, `AppPackageInstaller.cpp`, `NativeAppHost.cpp`: ELF length/SHA-256 validation, downgrade refusal and recoverable app ELF/JSON updates. Legacy JSON sidecars remain unsigned.
- `PackagePairTransaction.h`, `AppPackageRecoveryInventory.cpp`: legacy backup/stage recovery before springboard inventory while preserving unmanaged content.
- `PackageTransaction.h`, `PackageUseGate.h`: directory publication/recovery and process-wide exclusive replacement reservations, with GPS/USB CDC mapping pins before `dlopen` through successful `dlclose`. These do not defeat external SD substitution or yet cover every loader.

## Implemented: authenticated signed intake and extraction

- `PackageArchive.h`, `scripts/build_risc_package.py`, `PackageArchiveVerification.h`: canonical bounded uncompressed RISC-PKG framing/writing, external P-256 private-key signing, signed-prefix verification and full streamed entry SHA-256/ELF inspection. Decoder success is never authentication. Temporary test keys are generated outside the repository.
- `PackageTrustPolicy.h`, `PackageDeviceCrypto.*`, `PackageDeviceInspection.*`: real mbedTLS verification against firmware-provided exact kind/ID signer scopes, revocation and signer security floors. Read-only device inspection verifies the source without granting rights or loading it. Unknown/empty keys fail closed.
- `PackageArchiveStage.h`, `PackageDeviceStage.*`: source→fresh `/Packages/.intake.part` in bounded chunks; close/reopen and reauthenticate all bytes; detect a different valid signed prefix substituted during copy; check device security floor before and after copy. A successful stage can supply an authenticated 32-byte signed-prefix fingerprint retained in privileged RAM. Interrupted stages are not overwritten.
- `PackageArchiveExtract.h`, `PackageDeviceExtract.*`: require that original fingerprint; reauthenticate intake, enforce runtime and NVS floor policy, stream each entry into exclusively created `/Packages/.extract.part`, validate copied signed digests, close/reopen and independently hash all extracted files, reauthenticate intake and recheck the floor. An exclusively created manager lock serializes cooperating extractors; failures discard only the operation's owned files. The lock is retained until the final intake recheck. An interrupted stage blocks fresh extraction rather than being silently deleted.

## Implemented: retained provenance and signed publication (NEW)

- **`PackageSignedProvenance.h`:** each extracted generation retains `.risc-auth`, exactly the original canonical header + manifest + 64-byte P-256 signature. This reserved hidden basename cannot be package-controlled. A fresh verifier rechecks the record against firmware signer policy, decodes the same copied signed prefix, compares the optional original intake fingerprint, enforces ABI/dependencies and the device floor, checks the exact directory inventory and independently hashes every entry. It repeats provenance/inventory/floor checks after hashing. The record is not trusted merely because it is on SD.
- **`PackageDeviceDirectory.*`:** actual HalStorage read-only verification of extraction, target and prior-generation directory paths derived from expected kind/ID; refuses other paths and rejects unexpected or missing files. Supports verification after restart without an in-memory stage fingerprint, while still applying trusted signing and NVS policy.
- **`PackageSignedTransaction.h`:** common four-kind target/backup path derivation, one target replacement lease across preflight, prior-generation recovery, renames, post-publish verification, selective backup cleanup and floor advancement. Rejects active mappings, invalid stages, semantic downgrades by default, failed reads/renames and target corruption. After a cut at target→backup it verifies/restores the old generation; after stage→target it verifies the published one and resumes backup cleanup. It advances the device floor only AFTER the new target is verified and old backup has been completely removed, so normal recovery never needs to execute an older generation now below the committed floor. Failed NVS commit returns pending recovery with the verified target retained, not successful installation.
- **`PackageDevicePublication.*`:** firmware adapter uses the signed-directory verifier, device NVS floor store and HalStorage renames, plus a publisher-wide mutex for the shared extraction stage. Selective backup purge authenticates the old signed provenance, refuses unknown files, deletes only named remaining entries and deletes provenance LAST. Recovery handles the final empty-directory/rmdir cut. This publisher does not activate a package.
- **`PackageDeviceInstaller.*`:** transport-independent orchestrator accepts an already-opened readable `FILE*` from either SD or an online downloader and calls signed stage→extract→publish with the same policy and originally authenticated fingerprint. Two distinct caller-owned archive outputs and one caller-owned verification workspace avoid ELF-sized buffering. Publication-pending recovery and successful-install/intake-cleanup-pending are distinct outcomes. A successful publication removes only its fixed temporary intake file. No existing App Store or driver UI invokes this orchestrator yet.
- **`PackageSecurityFloor.h`, `PackageDeviceSecurityFloor.*`:** restart-persistent, monotonic device NVS floors keyed by complete kind/ID with collision-checked stored identity. Missing/corrupt/inaccessible states, writer serialization and commit failure are handled explicitly. Ordinary NVS persists across typical restarts but is **not a hardware tamper-resistant monotonic counter** under raw flash rewrite.

### Transaction and trust boundaries

The new signed publisher implements cooperative crash recovery, not an indivisible cross-filesystem/NVS atomic write: SD rename/cleanup and NVS commit are separate operations, with recovery retrying an interrupted floor commit. There is no authenticated durable installation-intent journal that binds an in-flight candidate across malicious SD replacement during a power cut. An attacker able to rewrite removable SD or raw NVS is outside this milestone's protections. Critically, directory verification and the package-use mutex do **not** make executable bytes immutable between verification and `dlopen`. Do not mark a signed generation executable/available until a loader-side authenticated-byte pin and boot recovery policy are implemented.

An online downloader and offline SD browser still need actual call sites to this same orchestrator; the legacy unsigned app/driver publishers must remain clearly segregated until parity and migration acceptance. A stale `.intake.part` or `.extract.part` requires explicit recovery/quarantine before another install, never an automatic broad delete.

## Outstanding acceptance milestones

1. **Authenticated ELF load lifetime:** bind exactly verified executable bytes to every `dlopen`, prevent physical SD replacement between verification and mapping, and extend execution-context/mapping leases to every application, driver, service and provider loader. Fail closed on revoked, corrupt or absent bytes.
2. **Boot/install intent and physical rollback policy:** add a recoverable device-controlled intent/journal or equivalent scheme binding the candidate fingerprint across a power cut and floor-commit window. Provision production signer keys, rotation/revocation, first-install enrollment and secure-boot/storage threat model. NVS alone cannot resist a raw-flash rollback attacker.
3. **Actual UI/source migration:** wire offline SD and online downloads to the common installer; migrate legacy unsigned App Store and driver routes only with equivalent inventory/recovery, storage/dependency/consent checks and integration tests. Implement explicit staging recovery/quarantine without deleting unknown content.
4. **Full four-kind management:** inventory, update, uninstall, quarantine, service/provider activation isolation, UI and fallback recovery. Signed provenance must remain enforced for every installed generation.
5. **Hardware acceptance:** both supported boards, actual SD/network installs, power cuts at every rename/NVS boundary, SD removal/replacement, in-use refusal, previous-generation recovery, all-four-kind lifecycle.

Hardware-specific implementations belong in installable driver ELFs; the framework supplies only generic capability-gated resources. Manifest declarations never authorize hardware. `/sd` remains the read-only ELF VFS; managed mutations use HalStorage. Keep PR #76 **draft, unmerged and unreleased** until the outstanding security and hardware gates pass.
