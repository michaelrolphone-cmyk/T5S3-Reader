# Unified Package Manager — merged foundation and required U1 completion

**Status: merged ordinary foundation; U1 implementation incomplete, September 18, 2026.** This is the package-manager branch under [Platform](RISCRTE_PLATFORM_SPEC.md), [ordinary package format](RISC_PACKAGE_FORMAT.md), [Bundled Package Archive and Install Layout](BUNDLED_PACKAGE_ARCHIVE_AND_INSTALL_LAYOUT.md), [Stable Package Identity and Version](PACKAGE_IDENTITY_VERSION_POLICY.md) and [Package Manager Scope](PACKAGE_MANAGER_SCOPE_CONTRACT.md). [U1](NEXT_HARDWARE_TEST_MILESTONE.md) governs the single integrated implementation and one hardware-test handoff. Its earlier loose-file assumptions are superseded by the owner-authorized single ZIP archive/per-ID directory requirement. Historical references to PR #76 as a draft or an unintegrated App Store/Driver Manager are not current work orders.

## Authorized objective

One ordinary source-independent manager for `application`, `driver`, `service` and `provider`, sharing manifest/preflight, version/architecture/ABI/dependency checks, owned file verification, stage/commit/recovery, inventory, update/uninstall and in-use gating. These are package kinds, not four transaction engines or authorization to invent unrelated services. App Store, Driver Manager and Package Manager are filtered user-facing views over the **same manager**; they do not own alternate installation or recovery mechanisms. Installing a hardware driver never itself activates it or grants hardware access.

**U1 distribution and installation are now explicitly bundled:** every current offline/online package is ONE ZIP-compatible `.rte.zip` file with root manifest, ELF where applicable, ABI/import metadata and nested resources. Release/catalog distribute one archive per stable `(kind,id,version,target)` and validate exact length/SHA-256. On device, safely extract into an owned per-ID package directory (apps, drivers, services and providers all follow the same policy), preserve old whole-directory generation on failure, and resolve launch/executable/assets through the manager-owned root. Normal releases cannot continue to require adjacent ELF+JSON app pairs or four loose driver assets. Finite bounded adapters still accept known historical inputs and migrate installed flat apps without destroying unknown files or data. Read the [archive/layout spec](BUNDLED_PACKAGE_ARCHIVE_AND_INSTALL_LAYOUT.md) for concrete ZIP validation, schema evolution, bootstrap ZIP service, staging, consumer migration and negative tests.

**No signing ecosystem is authorized.** Delete package-only P-256, trust/signer/key/revocation, signed provenance/receipts, cryptographic security floors and signed RISC-PKG archive/tool/test/docs from the active repo after extracting useful ordinary parser/hash/staging/recovery functionality. Do NOT use ZIP bundling to reintroduce signed archive code. Keep SHA-256 consistency, ZIP CRC, safe path/decompression bounds, ELF/import/ABI and independently enforced manager-to-loader policy, exact executable bytes, mapping pins, crash-safe replacement, TLS and unrelated OS crypto. An untrusted manifest or hash is not authorization to import privileged symbols.

## What exists and what is missing

Merged PR #76 supplied the four-kind ordinary engine plus an unrequested signed-format experiment. #78 supplied privileged-loader/provider foundations; #79 integrated App Store/Driver Manager and physical USB package pathways; #80/#81 addressed installer runtime and recovery defects. The owner reports most package operations tested on hardware; do not redo proven paths or imply all fault cases passed. Useful existing components include `PackageIdentity.h`, `PackageJsonGuard.h`, `PackagePreflight.h`, `PackageOrdinaryManifest.h`, `PackageOrdinarySdAdapter.h`, `PackageOrdinaryTransaction.h`, `PackageOrdinaryStageRecovery.h`, `PackageUseGate.h`, `InstalledCapabilityResolver.*`, `NativePackageManagerBridge.cpp`, `NativeOnlineAppInstall.h`, `NativeOnlineDriverInstall.h`, `AppPackageRecoveryInventory.cpp`, `DriverStageActions.cpp`, `InstalledProviderGraph` and `DeviceProviderExecutorV2`. This is an inventory, not a claim all functions are complete.

Current limitations: `Apps/package_manager.c` is primarily SD inbox oriented; generic SDK does not yet expose full installed/online inventory/update/recovery. Driver online discovery is coupled to the hard-coded seven-entry `usb-provider-catalog.json` and four fixed filenames, with legacy fallback; App Store has its own ELF/JSON online source adapter; ordinary packages are loose directories and installed apps can be flat ELF/JSON. The CDC lineage is incorrectly forked between `usb-cdc-acm` and `usb-cdc-acm-v2`, both at `0.1.0`, while a build script refuses versions other than `0.1.0`. Physical USB behavior in firmware is separately incomplete. ZIP bundling, ZIP service/bootstrap and all-kind per-ID roots are **new requirements, not implemented features**. Retain correct reusable transaction behavior instead of rewriting it from scratch.

## Canonical package/source/installed contracts

- Source manifests and real output assets feed one reproducible host ZIP packer and ordinary manifest schema. Archive entries list every allowed nested path with length/SHA, role and executable information; unsafe ZIP syntax, expansion, symlink and undeclared file inputs reject. Archive output and catalog identity/version/target/digest agree; no hard-coded driver list or version.
- Online generic `package-catalog.json` lists all four kinds and one immutable archive asset per package; its catalog and download use the same pinned release snapshot. It is discovery only, not installed inventory, trusted publisher, loader permission, chip selection or driver-activation authority. SD and online downloads produce the same canonical archive input, then the **existing common manager** performs all work. Offline install/inventory/uninstall and installed driver activation function without internet/catalog or ZIP service.
- Manager owns the per-ID verified installed directory and staging/backup journal. Package roots keep ELF, manifest and resources synchronized as one generation. Loader, springboard, app resource APIs, provider executor, all three manager UIs and recovery migrate to those validated paths; do not retain a permanent flat-app special case. Mutable app/user data stays outside replaceable code directories. Never overwrite another package or remove unknown user files.
- Shared SDK should be extended append-only with bounded generic online and installed refresh/count/get, preview, install/update, uninstall and recovery actions as needed; ABI `struct_size` guards must protect new fields. Dependency planning refuses cycles, mismatched versions, incompatible ABI, in-use replacement and unsafe provider quiescence with explicit diagnostics. Do not execute installed driver merely by inspecting an archive/catalog.
- Preserve stable package identity and strictly monotonic own manifest version for every changed app/driver/service/provider; CDC replacement is the same canonical product with ABI 2 compatibility, not a parallel `-v2` ID. Legacy identity/layout migration is a checked journaled step, not silent deletion or a permanent fake fork.
- The general-purpose `archive.zip` service may expose versioned archive operations to authorized apps, but **it cannot be a prerequisite to unpack/install itself**. Implement/reuse minimal transport-neutral ZIP bootstrap decode in the package path; use the same audited primitive for the service, not two full installers or any compiled device-specific ZIP driver. No separate provisioner is authorized: [SD deployment provisioning](DEPLOYMENT_PROVISIONING.md) remains future work.

## U1 implementation and acceptance

1. Audit all normal and legacy install/launch/asset/release paths. Implement versioned manifest resource paths and the bounded ZIP reader/extractor/packer, package bootstrap and ZIP service. Convert both source adapters and four-kind release catalog to **one archive download and one common installer**; remove `usb-provider-catalog.json`, fixed driver set, fixed four-file downloads and normal separate App Store pairs.
2. Extend generic manager SDK/UIs to complete four-kind inventory, online/offline install/update/uninstall/recovery and dependency diagnostics. Extract archives into verified owned per-ID staging roots; transactionally commit entire directory generations. Update launcher, provider graph, app store, driver manager, package manager and all resource lookups; migrate existing installed data safely. Preserve previous generation, in-use/quiesce protections and offline operation.
3. Purge signing-only implementation/tools/docs while retaining ordinary integrity/permission. Repair CDC stable identity, version increments, legacy-installed migration and automate prevention of same-version changed artifacts/forked product names. Ensure new unrelated package appears without firmware/exporter source edit.
4. Execute real production-facing tests for four kinds from both sources, resources and layout isolation, ZIP-service-absent first install, malformed/bomb/path/collision/CRC/SHA/ELF/ABI failure, release mixing, duplicate identity/version, interrupted download/extract/commit/uninstall/restart, mapped/unsafe provider refusal, directory migration and catalog-absent activation. Run release-equivalent builds, check firmware artifact custody and record actual success/failure on same commit. Do not idle waiting on CI while independent work is ready.
5. Deliver ONE coherent firmware, app, driver, service/package archive set and ONE physical-test sheet after all U1 software gates, including [cross-family reuse](DRIVER_PLATFORM_REUSE_ACCEPTANCE.md), [CDC identity](PACKAGE_IDENTITY_VERSION_POLICY.md) and [archive/layout](BUNDLED_PACKAGE_ARCHIVE_AND_INSTALL_LAYOUT.md). No interim board-test demand, auto-merge, tag or publication.

**Stop rule:** package MVP/U1 is not software complete while four kinds use separate distribution or installer pathways, any normal package still requires ELF/JSON sidecars, apps lack per-ID roots, the archive bootstrap relies on an installable ZIP service, unsafe legacy migration remains, the CDC fork/version failure persists, signing code remains, or generic catalog/provider independence and builds/tests are unproven. User alone completes physical acceptance; source/host tests are not hardware proof.
