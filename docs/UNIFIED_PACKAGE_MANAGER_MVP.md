# Unified Package Manager MVP — architecture and acceptance

**Status:** Priority 3, draft PR #76. The legacy online App Store now uses a digest-aware ELF/JSON pair transaction instead of independent destructive backup swaps; driver packages use the shared single-directory transaction. Shared identity, lexical JSON protection, metadata preflight, numeric version decisions and app release hash stamping exist. **These are transitional implementations, not the completed Unified Package Manager.** The common `package.risc` archive decoder, authenticated signatures and key policy, offline SD installer, unified four-kind lifecycle and verified-byte pinning remain unimplemented. Legacy unsigned artifacts are never considered publisher-authenticated.

Authority: [RiscRTE Platform Specification](RISCRTE_PLATFORM_SPEC.md) → [Platform Capability Roadmap](PLATFORM_CAPABILITY_ROADMAP.md), §§26–28 and §39 → [Runtime Driver Architecture](RUNTIME_DRIVER_ARCHITECTURE.md), [Application Execution Context Architecture](APPLICATION_EXECUTION_CONTEXT_ARCHITECTURE.md), and [Security Architecture](SECURITY_ARCHITECTURE.md). This document tracks implementation and acceptance without redefining the roadmap.

## Target invariant

One runtime-owned manager validates and installs **applications, drivers, services and providers** without loading candidate payloads. A versioned envelope binds identity, complete entry sizes/hashes, architecture/ABI, dependencies, capability declarations, security version and an authenticated publisher signature. SD and online distribution use the same envelope and installer. Interrupted updates retain a verified generation; installation grants no hardware access or activation. SHA-256 validates bytes against a declared digest but cannot authenticate a mutable manifest. Hardware protocol implementations reside in driver ELFs; the runtime exposes generic resource and capability interfaces.

## Implemented

### Shared identity, guarded manifests and preflight

- `src/runtime/packages/PackageIdentity.h`: four kinds; `(kind,id)` namespace; bounded lowercase IDs and numeric `major.minor.patch` versions; reject invalid kinds, unsafe artifact basenames, traversal, overflowing version components and trailing ID punctuation. Existing untyped, versionless application sidecars remain readable as legacy, not trusted by inference.
- `src/runtime/packages/PackageJsonGuard.h`: bounded, allocation-free JSON syntax/duplicate-key check including escaped-key aliases, malformed escapes, depth and size limits, executed before ArduinoJson by both legacy manifest parsers. It does not canonicalize signing bytes, parse archives or authenticate source.
- `src/runtime/packages/PackagePreflight.h`: borrowed typed envelope metadata view, bounded entries and requirements, declared hashes and budgets, architecture/runtime/security floors, capability/API availability, numeric version policy. A successful `ReadyForContentVerification` result does **not** mean a payload hash or signature was checked, and the helper remains unconnected to a common package decoder.
- Driver manifest parsing retains ABI, ELF header, payload SHA-256 and capability validation. Installed-driver version lookup now validates ELF content rather than trusting only the JSON version field.

### Release construction and legacy App Store integration

- `scripts/package_integrity.py` and `scripts/build_all_apps.py` record the exact built ELF's `size_bytes` and SHA-256 in its sidecar and aggregate catalog. They reject inconsistent existing metadata, excess manifest size and excess catalog entry/byte budgets. `src/native/AppManifest.cpp` validates these two fields together while still parsing sidecars with neither field for legacy compatibility.
- `src/native/AppPackageInstaller.cpp` supplies a real HalStorage/mbedTLS pair verifier. It validates manifest filename, ELF header and size, hashes the entire ELF when SHA-256 is declared, and requires both size and digest for **new staged releases**. An old digestless installed pair is validated only for filename/header/length consistency so that an installed generation can be migrated: it is not cryptographically verified or authenticated.
- `src/runtime/packages/PackagePairTransaction.h` publishes the flat `/Apps/<name>.elf` and `.json` pair together using `.part` staging and `.bak` recovery, rather than assuming two renames are atomic. The previous pair is verified for its available legacy/new constraints before partial target deletion, interruption at rename/cleanup boundaries is recoverable when the old or new pair verifies, and ambiguous/corrupt states are preserved for inspection.
- `src/native/NativeAppHost.cpp` now calls recovery before install and before launching a managed `/Apps` ELF; validates release length against manifest metadata, SHA-256 of the downloaded `.part` ELF before publication, and the manifest/ELF pair on launch and installed-version lookup. The shared transaction replaces the old independent `.bak` deletion/swap logic. Numeric downgrade refusal is applied to existing versioned apps, and the adapter forbids overwriting the exact active ELF path returned by the loader. The `.part` files of a rejected download are left for inspection, while future installs clean only these disposable paths after recovery.
- `test/resources/package_pair_transaction_test.cpp` injects rename/remove faults and tests refusal/rollback under ASan/UBSan. `test/native_apps/test_app_package_install_integration.py` guards against reconnecting the live App Store to the obsolete split swaps. Board CI compiles the real adapter; these tests are not a physical SD power-cut certification.

### Driver directory transaction

`src/runtime/packages/PackageTransaction.h` stages driver ELF and manifest under `/Drivers/.<id>.install`, validates them, moves the previous directory to `/Drivers/.<id>.previous`, then publishes the stage. Recovery can restore a complete verified backup or finish managed-only cleanup of a partial backup after the new target verifies. Corrupt/unmanaged target data is not deleted. **The driver installer still passes `replaceAllowed=true`; a generic module/lease pin gate is outstanding.**

## Current limitations and follow-up order

1. **Recovery boot sequencing:** the App Store and direct managed launch recover their own target pair, but the springboard checks its files' existence before attempting recovery and its installed-list enumeration skips incomplete updates. Add a bounded startup scan and recover all recognizable managed app pairs before enumeration/launcher presence checks, without mutating the directory during enumeration. Do not claim complete reboot-to-home recovery until this is done and tested.
2. **Trust and TOCTOU:** SHA-256 is an integrity check against a potentially mutable unsigned sidecar, not publisher authentication. Implement canonical signed `package.risc`, an allowlisted signing-key/trust policy, all-entry verification, security-version rollback persistence and pinned verified bytes from inspection through load. There remains a verification-to-load substitution window for SD media.
3. **Common decoder and installer:** exact bounded envelope/archive schema and canonical signing bytes, reject duplicate keys/filenames including FAT aliases, unknown fields, archive bombs and hidden executables. Connect it to shared preflight, version policy, dependency resolution, storage preflight and verified stage/publish. SD and network must send identical package bytes to the same path.
4. **Generic execution pins:** refuse replacing any driver/app ELF while mapped, running or pinned by a context/lease. The legacy app adapter checks its exact current loader path; the driver install still lacks the generic pin gate. Installer permission/consent belongs to the platform, not the manifest or arbitrary ELF app.
5. **Four-kind lifecycle and management UI:** service/provider install and activation separation, inventory, update, uninstall/quarantine, version/permission/trust display, fallback serial/Wi-Fi recovery, explicit unsigned development mode distinct from signed release policy.

`/sd` is a read-only ELF VFS: all modifications use `HalStorage` paths derived from trusted validated identities. No package declaration grants hardware permissions; hardware-specific behavior stays in driver ELFs.

## Acceptance and release gate

Host fault matrix: all four kinds, identity/versions, duplicate JSON keys, aliases/traversal, digest and signature tampering, ABI/security floors, missing dependencies, insufficient space, unmanaged content, in-use replacement, resets at each rename/deletion, install/reinstall/upgrade/downgrade/uninstall and no candidate execution. Compile both board targets and release artifacts. On real SD media: install online and offline, remove power at transaction boundaries and confirm the last usable app and driver remain recoverable and built-in recovery still runs. Latest pre-integration CI on `58c2e3a` passed both board builds, release package construction and host tests. **The integrated live App Store changes require their own passing CI and board/power-cut testing.** Keep PR #76 draft, unmerged and unreleased until the claimed subset and required gates pass.
