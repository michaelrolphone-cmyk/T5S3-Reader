## Defect and minimal repair

The registered GET `/api/opds` handler skips server objects whose serialized size
does not fit its 512-byte scratch buffer. It formerly inserted commas using the
source index. An oversized first record followed by a fitting record produced
`[,{"index":1,...}]`, which actual ArduinoJson rejects with `InvalidInput`.
The POST path accepts name/URL/username strings without a corresponding response
scratch-buffer limit, so the source condition is reachable through existing input.

A request-local `emittedAny` flag now inserts separators only between emitted
objects. Original indices, field order, password-presence flags, concealed password
values, store contents and response chunk bounds stay unchanged. There is no new
allocation, scan, retry, I/O operation or resource lifetime.

The existing omission of oversized records is deliberately retained. This repairs
invalid array syntax; it does not make oversized servers visible, impose new field
limits, change persistence, or qualify allocation failure or transport behavior.

## Evidence

`test/opds_response/response_test.py` extracts the complete production method and
compiles it against real ArduinoJson, with fixture HTTP/store endpoints and the
production `OpdsServer` declaration. It checks the actual GET registration and
POST field assignments. The original pinned method fails the initial oversized-
first fixture; the repaired method passes 287 requests normally and under
ASan/UBSan with ArduinoJson 7.4.2:

- All 256 skipped/emitted combinations in an eight-record store, including first,
  middle, last and all-record omission; empty and ordinary responses.
- Exact serialized sizes 510, 511, 512, 513 and 1024 bytes, plus escaped expansion.
- UTF-8 and escaped fields, stable source indices/order, password concealment and
  unchanged source data.
- Repeated omitted-only, recovered, ordinary and empty requests; no retained
  separator state, one JSON response and one terminal chunk.

The actual method also compiles to a 32-bit Xtensa object with ArduinoJson 7.4.2.
Hosted target-build jobs run the new sanitized test using their real ArduinoJson
dependency. Existing OPDS admission/app cancellation-retry and local aggregate
results are recorded in the PR; final remote SHA, independent review and exact-head
CI results will supersede this publication-time checkpoint.

Local LeakSanitizer is disabled only in the caller environment because ptrace is
unavailable; ASan/UBSan remain active and hosted defaults are unchanged. No full
local firmware link, physical network, SD, account or device qualification is claimed.
