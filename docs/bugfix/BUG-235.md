## Failure and repair

`JsonSettingsIO::loadState` accepted `{}` as successful state, clearing a live book
path and sleep history. `CrossPointState::loadFromFile` returned immediately for
any nonempty JSON, so both malformed syntax and invalid structure prevented its
existing binary migration path. Boot calls this loader before reader restoration.

The codec now requires an object with a string `openEpubPath`. Known optional
scalar fields must have their native types/ranges. If any ring field is present,
the array, position and fill must all be present, bounded to 16 entries, contain
uint16 values and reference existing slots. Unknown fields remain compatible.
Historical path-only and pre-ring `lastSleepImage` JSON remain supported. Parse
and validate before replacing live state. Invalid JSON reaches existing legacy
binary migration, using a fresh temporary state so retry does not accumulate old
ring entries and failed migration save does not publish recovered state.

No storage format/version, write policy or files outside the existing migration
are added. A valid binary recovery is saved through the existing state writer,
then its source is renamed by the existing migration behavior. The unchanged
legacy binary parser's unchecked/truncated-read semantics and unchecked rename
result are outside this repair and are not claimed fixed. No backup recovery
search, file deletion or UI is introduced.
