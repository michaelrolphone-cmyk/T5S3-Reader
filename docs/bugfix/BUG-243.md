## Reproduction and repair

An SD JSON record containing `"matchMethod": 2`, or a legacy binary with mode
byte 2, was cast directly to `DocumentMatchMethod`. NativeKOReaderBridge displayed
any non-BINARY value as Filename, but KOReaderSyncActivity selected binary hashing
for any non-FILENAME value. The mismatch could split document progress between
filename and binary identifiers while the setting still said Filename.

The store setter now admits only the two declared modes and normalizes every
other value to the existing Filename default. Both persisted loaders use that
setter. JSON additionally validates the integer type/range before narrowing and
requests the existing best-effort resave for invalid non-null fields. Missing or
null legacy fields retain the existing Filename default without an extra write.
A failed resave does not undo normalization in RAM; a subsequent load retries.
Valid Filename/Binary settings and credential/server fields are preserved.
The optional trailing binary byte is initialized to Filename before its read.

Source paths:
- `lib/KOReaderSync/KOReaderCredentialStore.cpp`
- `src/JsonSettingsIO.cpp`
- firmware version in `platformio.ini`

No settings-UI ABI, document-ID algorithm, endpoint, password handling, network
traffic or provider lifetime change. Existing unrelated JSON schema/migration
failure semantics and credential-save rollback reports are not claimed fixed.
