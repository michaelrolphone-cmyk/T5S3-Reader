## Failure and repair

`CrossPointWebServer::handleGetSettings` serialized each complete setting into a
512-byte array, then skipped it when the buffer filled. The ordinary dynamic
`fontFamily` setting includes two built-ins and up to 128 SD families. The complete
unchanged production handler and real ArduinoJson 7.4.2 return `[]` for a supported
130-option fixture. A strict negative regression also fails at the exact 512-byte
serialized-object boundary.

The same document now serializes into a fixed 512-byte HTTP chunk writer. No
whole-response/string allocation is added. Setting order, names, categories,
option bytes/escaping, selected values and other setting kinds remain unchanged.
The writer never sends an empty flush, which would prematurely end HTTP chunking;
the handler explicitly finishes once after the closing array bracket.

Output is bounded to 256 KiB per response and 15 seconds checked before/after
writes, using unsigned elapsed-time arithmetic. The byte cap exceeds 130 names
of 255 bytes each even at six-byte JSON escaping, plus the other settings.
Each emitted chunk invokes a real one-tick RTOS wait. Existing response socket
timeouts remain in effect. Disconnect, budget exhaustion or JSON allocation
failure closes the response without a misleading successful partial list. A new
request owns new document/writer state and can retry normally. Abort runs through
`CrossPointHttpServer::abortResponse`: it clears `_chunked` and stops the owned
`_currentClient`. The pinned WebServer `client()` returns a shared copy, whose
`stop()` alone would leave the owner's connection and automatic finalizer alive.
The regression models those copy semantics and invokes finalization after both
successful and interrupted handlers.

`WebServer::sendContent` has no return status; the writer detects disconnection
and elapsed budget, not an independently observable count of socket bytes.
The deadline is checked around the existing bounded send, not asynchronously
inside an individual socket operation. Device/network failure timing is untested.
