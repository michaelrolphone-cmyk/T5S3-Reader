## Confirmation and repair

The full unmodified `src/network/FirmwareFlasher.cpp` accepts a structurally complete seventeen-segment image with correct payload XOR checksum, real SHA-256 trailer, matching board marker and size above 64 KiB. The production validator returns `OK`; the regression expects `BAD_SEGMENTS`. Its ordinary `flashFromSdPath` caller invokes validation before any erase/write or boot selection.

The pinned Arduino-ESP32 2.0.17 framework uses [ESP-IDF 4.4.7](https://github.com/espressif/arduino-esp32/blob/2.0.17/tools/sdk/esp32s3/include/esp_common/include/esp_idf_version.h). That SDK defines [ESP_IMAGE_MAX_SEGMENTS 16](https://github.com/espressif/esp-idf/blob/v4.4.7/components/bootloader_support/include/esp_app_format.h#L100) and [rejects larger image counts](https://github.com/espressif/esp-idf/blob/v4.4.7/components/bootloader_support/src/esp_image_format.c#L307-L309). The repair uses the SDK constant directly and returns `BAD_SEGMENTS` immediately after reading the image header, before allocation/hash/segment parsing. It closes the opened input. Existing magic, size, checksum, SHA, board-identity and prevalidated-caller behavior are unchanged.

Firmware source 1.3.82 → 1.3.119, above the active performance reservation 1.3.118. The original unpublished 1.3.104 reservation is superseded. Latest published firmware 1.3.82 was checked. No independently distributed app/driver/provider changes, new image format or new validation API.
