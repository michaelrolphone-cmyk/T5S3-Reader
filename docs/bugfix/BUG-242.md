## Revalidated supported trigger

The original report's same-book `diagram.jpg`/`diagram.png` example is insufficient by itself: ChapterHtmlSlimParser extracts them with distinct ordinal names. A supported cross-format collision occurs on an ordinary Embedded Style setting change:

1. A chapter contains an equal-size black JPEG with inline `style="display:none"`, followed by a white PNG.
2. With Embedded Style off, the parser extracts `img_0_0.jpg` and `img_0_1.png`. Rendering the JPEG creates the old `img_0_0.pxc`.
3. Changing Embedded Style on invalidates the section page cache. `Section::loadSectionFile` rejects the setting mismatch; `clearCache` removes only the section file, leaving root image pixel caches.
4. Reparse skips the CSS-hidden JPEG before incrementing the image counter. The PNG now becomes `img_0_0.png` and its old extension-dropping key also resolves to `img_0_0.pxc`.
5. Equal dimensions pass the cache check, so the PNG displays the old JPEG pixels.

The regression compiles the actual image selection/path branch and image-base expression, full `Section::loadSectionFile`/`clearCache` methods, full production `ImageBlock.cpp`, and actual `DirectPixelWriter`/Serialization. The unchanged baseline compiles, then fails with `Wrong image pixels for /epub/img_0_0.png: got 00, expected ff`. It also covers the underlying direct ImageBlock path contract.

The surrounding parser/ZIP/XML state, CSS results, path normalization, image decoder output, storage and display surface are host fixtures. This is not an end-to-end EPUB file/decoder or hardware test.

## Minimal repair and migration

Retain the complete input filename, including extension, and append `.pxc2`. This is an injective suffix mapping of the existing input path and adds no hashing, recursion or I/O. Existing cache read/decode/failure paths are unchanged.

A new suffix avoids legacy overlap: an old cache for `diagram.jpg.png` would be `diagram.jpg.pxc`, which could otherwise equal an extension-preserving key for `diagram.jpg`. That multi-dot example tests ImageBlock's direct path contract, not the current parser-generated filename shape. Old `.pxc` files are ignored and left unchanged; affected images incur one fresh decode/cache write. No cache data-format, section-format or decoder-interface change is needed.

This fixes the canonical cross-extension collision. It does not solve broader same-extension ordinal reassignment or in-place image-content invalidation. If cache creation fails, the existing direct decode still renders the image; later visits retry.
