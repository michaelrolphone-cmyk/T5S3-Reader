# Shared chips, pins and power rails — exclusive ownership contract

**Normative for U1–U4; specification only.** Read with [hardware ownership](HARDWARE_AGNOSTIC_DRIVER_BOUNDARY.md), [I²C bus cutover](I2C_BOOTSTRAP_CUTOVER.md), [SPI/UART cutover](SPI_UART_ELF_BOOTSTRAP_CUTOVER.md) and [four milestones](FOUR_MILESTONE_STREAM_FIRST_EXECUTION_ORDER.md). This assigns physical resource ownership where functional inventories name the same component more than once. No firmware changes or hardware validation are implied.

## Rule: one physical owner, many scoped consumers

Assign **exactly one installed functional ELF owner to each verified physical chip instance, register file, expander output and shared rail** on a board. The I²C bus ELF owns bus arbitration and raw transactions; it does **not** own individual chip registers or board power policy. A chip's sole owner claims its I²C device address through `i2c.bus`, owns register shadow/configuration, reads, writes, interrupts, faults and safe teardown, and can expose several versioned capabilities or scoped interfaces. A separate functional power service may orchestrate multiple chip owners, but receives limited grants; it must not duplicate register ownership. The generic core tracks opaque rights, generations and dependencies only. Names, pins, polarity, chip identity, address and sequence data originate from a verified board profile interpreted by the relevant ELFs, never hard-coded framework logic.

No separate `buttons.elf`, `usb-power.elf`, `epd-power.elf`, `gnss.elf` or `lora.elf` may independently claim and mutate the same chip's registers or drive the same physical enable line. A capability name alone is not a physical ownership lease. Reconcile existing code/manifests at implementation kickoff; two proposed package IDs for the same chip must be consolidated into one physical owner with explicit consumer interfaces, rather than activated concurrently.

**Verified source reference, not fitted-board proof:** `lib/Board_T5S3/pin.hpp` lists PCA9535 at `0x20`, TPS65185 at `0x68`, BQ25896 at `0x6B` on T5 I²C; PCA IO00 = `LORA_GPS_EN`, IO12 = button, IO13/IO14/IO15 = TPS power-up/VCOM/wakeup, IO16/IO17 = TPS good/interrupt, and IO10/IO11 = EPD OE/mode. `Drivers/bq25896/driver.c` presently targets **BQ25896** to implement USB OTG VBUS through `i2c.bus`. Verify actual PCB revision and schematic before finalizing polarity, rail topology, all consumers or startup requirements. Sharing one I²C *bus* does not mean TPS65185 owns USB VBUS or that both chip drivers may own the same chip.

## Physical owner and consumer assignment

| Resource | Sole physical owner and interfaces | Authorized consumers / milestone |
| --- | --- | --- |
| I²C controller | Installed I²C bus ELF publishes `i2c.bus`; only it has temporary raw firmware import until U3 | BQ, PCA, TPS, touch, gauge, RTC chip ELFs; one address claim per fitted chip |
| BQ25896 `0x6B` | One BQ/charger/power ELF owns all BQ registers and OTG/charge arbitration; publishes `board.power.vbus` and other scoped charging/telemetry interfaces as appropriate | U1 USB host requests VBUS before starting; U3 charger/telemetry consume the **same chip owner**, not another BQ driver |
| PCA9535 `0x20` | One expander ELF owns both banks, direction/config, interrupt handling, register shadow and atomic masked operations; exposes scoped pin grants, input samples/events and safe output control | U1 if a verified USB prerequisite uses its outputs; U3 buttons, EPD controls and radio-rail owner consume distinct granted pins without raw address/register access |
| TPS65185 `0x68` | One TPS ELF owns its **entire** register file, HV/VCOM state and fault reporting | U3 EPD-power sequencer consumes TPS plus specific PCA pin grants; no separate display-versus-power TPS register owner. Not an assumed U1 USB VBUS dependency merely because it shares `i2c.bus` |
| PCA IO00 / shared GNSS–LoRa enable | One rail policy owner (`board.power.radio` or versioned equivalent) holds the **only** PCA IO00 output grant and publishes generation-bound power leases | U3 GNSS and LoRa drivers each acquire/release a rail lease; neither toggles IO00 or assumes the other is idle |
| EPD power sequence | One sequencer ELF/capability uses the TPS owner and narrowly granted PCA EPD/TPS pins; it owns ordering, delays, HV/VCOM shutdown and fault cleanup, **not** their underlying raw register files | U3 display driver requests an EPD power lease; shared PCA button input remains independently available |

A single chip owner may directly publish a high-level function (e.g. BQ `board.power.vbus`) instead of adding an unnecessary one-consumer sequencer. A separate rail/sequencer is justified when it arbitrates **multiple independent consumers or multiple chips**. Preserve stable chip/package identity and version rules; a source file containing both UI and power logic does not justify two physical owners.

## Expander and shared-rail API requirements

The PCA owner claims address `0x20` once. It grants **nonoverlapping output pin masks** and separately scoped read/subscribe rights on inputs. It owns all read-modify-write, register shadow, configuration and interrupt demultiplexing: an EPD power change must not overwrite the radio enable, button direction, other power pins or interrupt configuration. A button consumer never writes expander registers. Colliding pin grants are rejected; on revoked grants or failed/unconfirmed writes, output state becomes explicitly unknown/faulted and dependent power policies fail safely rather than restoring a stale whole-bank shadow. Implement pin-level safe defaults and release policies from validated profiles, bounded I²C calls, atomic masked writes and copied events. No raw PCA access by consumers or additional `Wire` bridge.

**GNSS/LoRa rail:** the rail owner, not either receiver/transceiver ELF, exclusively owns the PCA IO00 enable grant. `acquire(owner_context, requested_state)` returns an opaque, revocable lease; first successful acquisition enables the verified rail and confirms readiness where measurable; further acquisitions keep it on. Release, cancellation, driver crash and context teardown decrement only that owner's live lease. Do **not** disable the rail until all active consumers release and their hardware is quiescent; keep it on or quarantine/pin the responsible owner if shutdown safety is uncertain, with diagnostics and bounded power policy. Last release initiates a verified safe shutdown. Failure to enable means no successful lease; failed disable must not claim power is off. Consumers receive loss/fault events and rebind on owner-generation changes. GNSS inactivity must not power down active LoRa and vice versa; power acquisition itself never authorizes LoRa transmission. Profile establishes any independent reset/pins and whether a true shared rail exists; do not infer additional wiring from pin aliases alone.

**EPD power:** the EPD sequencer obtains only the PCA pins needed for display/TPS control, plus the TPS capability. Specify actual dependency order (bus → PCA/TPS → sequencer → display), verified rails and timing, HV/VCOM enable/disable and fault cleanup. Other PCA consumers, especially button and radio rail, must remain functional during refresh/sleep. No EPD driver or generic UI writes TPS/PCA raw registers; no separate `tps-display` and `tps-power` ELF both claiming `0x68`.

## Noncyclic activation and physical-resource inventory

Before registering or activating a provider, record **chip instance / register owner / output-pin owner / rail owner / public capabilities / each consumer / bus controller / power prerequisite / boot exception / safe absence**. Validate dependencies as a directed graph at chip and rail level, not just package IDs. A bus or expander owner cannot require a downstream rail whose only controller is that very bus/expander; use only verified boot-alive substrate or a separately isolated bootstrap that relinquishes hardware before runtime. The BQ VBUS branch and TPS EPD-HV branch may share the I²C bus without depending on one another. Confirm an actual PCA USB dependency before putting PCA in U1's activation chain; do not pull the TPS/EPD power graph into U1 by association alone. Normal runtime may not activate duplicate chip-address claims, conflicting PCA output masks, competing rail owners or two controller backends. Uninstall/update of a shared owner must be blocked while dependents hold leases or quiescence is uncertain; missing owner makes **all** dependent capabilities unavailable, never a firmware fallback.

## Allocation and acceptance

**U1:** Inventory and assign the shared resources in the *actual USB/VBUS activation path*, not only a list of fitted chips. The existing BQ `board.power.vbus` driver is the BQ chip's single owner; require its API to arbitrate OTG versus any charger use and prevent a second BQ owner. Install the I²C bus ELF first; if USB uses PCA outputs, install **one PCA expander owner** and acquire only its relevant pins. The power/USB ELFs depend on those capabilities. No mandatory EPD/TPS/radio functionality, but retain their future pin ownership in the profile and ensure no U1 provider claims those registers/outputs independently. Tests cover conflicting address/output claims, dependency graph, absent owner, safe VBUS shutdown and no second charger path. Physical proof stays in the single owner qualification session.

**U2:** Publish/version each physical owner once and express chip/rail dependencies in package/profile metadata. Independent sources cannot install a duplicate owner for the same fitted resource merely because manifests use different capability names; generic admission enforces opaque provider-declared exclusive resource keys/claims without interpreting I²C addresses or rail semantics in core.

**U3:** Complete PCA chip ownership shared by button, EPD control and radio enable; TPS single-owner and EPD power sequencing; GNSS/LoRa common rail lease ownership, including device-absent, startup, shared-use, sleep, teardown and failure paths. Migrate remaining chips and buses to ELFs; native I²C/SPI/UART bus cutover does not create a second chip/rail owner. Test button input concurrent with EPD power, masked writes that preserve IO00, rail lease sequences `GNSS → LoRa → GNSS release → LoRa release` and reverse, failed driver shutdown, TPS HV fault, USB VBUS while EPD active where electrically permitted and absence of conflicting claims. Check real current/voltage/polarity only at owner Release Qualification.

**U4:** Headless CAM loads only fitted/profile-matched drivers, not the Pro PCA/TPS/BQ/radio rail as universal system-core dependencies. The one-image proof is unchanged. No new firmware chip owner or interactive serial interface.

**Not satisfied by:** an inventory that says `PCA9535 = buttons + power`, two ELFs each using the same register file, separate GNSS/LoRa GPIO writes, a shared bus mutex without chip/pin leases, or tests that exercise drivers only in isolation. Implementations must show actual manifest/claim paths, dependency order, atomicity and multi-consumer teardown; a spec alone is not software or hardware acceptance.
