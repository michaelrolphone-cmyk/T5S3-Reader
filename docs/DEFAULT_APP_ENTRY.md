# Configured default application entry

The optional SD selector `/RiscRTE/default-app.txt` contains exactly one native ELF **basename** followed by an optional line ending, for example `camera_utility.elf`. It cannot contain a path, whitespace, extra lines, or a second choice. The selector names no device and grants no capability. The installed-app resolver verifies the package, sidecar, compatibility and artifact identity; the normal native ELF loader performs import and execution checks. An absent selector leaves the embedded e-ink GUI on paper targets and the normal idle provider runtime on headless targets. An invalid or unavailable selector is reported once per boot, with no retry or boot loop. A returned app is not relaunched automatically.

On paper, the existing display and input host starts first; a verified configured app enters through `runNativeApp` and returns to the embedded Home UI. No selector preserves the established Home/reader boot choice and retained e-paper behavior. The CAM port has no display or touch host. It enters the same native ELF `app_main` loader with an owner-task execution context, the existing stream runtime, installed provider graph, and U1 managed-application snapshot admission. The headless build links U1's strong admission hook, captures the verified sidecar before the loader opens the ELF, and checks the operation-owned ELF bytes. Its minimal app API supplies only cooperative `poll` and `millis`; unsupported UI/hardware takeover imports are absent or fail closed. Manifest `requires` are acquired before relocation, and an app may borrow only a declared installed provider capability. Cleanup runs before `dlclose`; a failed quiescence retains mapped provider resources rather than forcing another boot launch.

`Apps/camera_utility.c` is an installable `0.1.1` application requiring `camera.capture@1`. It requests one bounded 800×600 JPEG, waits cooperatively, validates complete JPEG framing, and writes one new `/sd/camera-utility-NNNN.jpg` through the generic stream file API. It tries at most 9999 four-digit names and never overwrites a prior capture. The output path and byte count may be logged, but image bytes are never logged or published. This small utility uses the already installed camera provider; it does not own sensor registers, SCCB, LCD_CAM or GDMA.

`cam-camera-app-experiment` is a lab-only deployment path. It embeds the ordinary application `.rte.zip`, installs it through U1's single package manager, and seeds the selector only when absent. It does not embed or reflash a driver package. The normal headless profile reads an owner-supplied selector and installed packages without a boot-time installer. This increment does not implement general U4 provisioning or extract the paper GUI into an ELF.
