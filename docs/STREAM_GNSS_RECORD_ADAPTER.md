# RiscRTE GNSS observation records and provider publication

## Authority and target

Read [RiscRTE Platform Specification](RISCRTE_PLATFORM_SPEC.md), [Platform Capability Roadmap](PLATFORM_CAPABILITY_ROADMAP.md), [Stream/Pipe Architecture](STREAM_PIPE_ARCHITECTURE.md), [typed record ABI](STREAM_RECORD_API_V2.md), [Application Execution Context Architecture](APPLICATION_EXECUTION_CONTEXT_ARCHITECTURE.md), and [GPS Driver](GPS_DRIVER.md). The target is an installable GNSS provider registered under `location.*`, resolved to a capability-lease-protected, read-only typed record endpoint. Consumers and producers never retain one another's ELF pointers. Runtime teardown reclaims their streams and leases before either ELF is unloaded.

## Implemented on PR #65: safe data-plane foundation

`Registry::produceRecord(owner, handle, payload, length)` is firmware-only: it atomically writes to an owner-validated READ-only typed stream without granting public ELF WRITE rights. It checks kind, capacity, terminal state and bounded backpressure. The firmware bridge must hold its existing registry mutex, just as it does for ordinary stream operations. Do not export this function to ELFs.

`src/runtime/streams/GnssRecordAdapter.h` accepts a **copy** of `t5_gps_state_t` from the claiming GPS driver task, not a driver callback. It requires fix status, valid fix flag, age <= 5000 ms, finite latitude/longitude and valid coordinate bounds. Stale, unsupported, no-fix and invalid observations return `AGAIN` without manufacturing a (0,0) fix. `open()` creates an invocation-owned, READ-only queue; `publish()` returns `AGAIN` on full rather than silently dropping. Hardware polling and driver lifecycle belong to the caller.

**Optional-field provenance:** legacy `t5_gps_state_t` has no per-field presence mask. Zero altitude, speed or course may mean *not observed*. `encode`/`publish` accept an explicit `verifiedFields` mask defaulting to zero. They mark altitude, HDOP, speed or heading valid only when actual source-presence evidence exists and the number passes its checks. An unverified field serializes as zero with its validity flag cleared. Unknown flags are rejected. An enhanced GNSS provider must report genuine GGA/RMC field-presence metadata instead of inferring observation from plausible default values.

`lib/NativeApps/include/RiscRteLocationRecords.h` defines a 52-byte little-endian `location.fix.v1`: version u32 @0; sample monotonic ms u32 @4; fix monotonic ms u32 @8; verified-field flags u32 @12; latitude and longitude binary64 @16/@24; altitude, HDOP, speed and heading binary32 @32/@36/@40/@44; satellites u8 @48; zero reserved @49–51. `fix_ms = sample_ms - age_ms` uses wrapping u32 monotonic time, **not GNSS UTC**. Decode at explicit offsets rather than casting a C struct. A schema change requires a new `.vN` identity and explicit transform. Record schema validation requires one final nonzero `.vN` suffix, not ambiguous earlier version segments.

### Bounded subscriber coordinator

`LocationPositionSubscriptions.h` uses the **existing** StreamRuntime registry, one source and at most four independent, generation-safe subscriber leases/READ-only streams. Each queue holds four complete records. The provider token binds owner and generation, with the resolved physical device generation checked at each publication. Foreign owners cannot unsubscribe, stale stream handles cannot alias reallocated slots, and a disconnected source cannot be replaced while old subscribers remain alive.

Initial fan-out is explicitly coupled `BLOCK_PRODUCER`: under the shared runtime mutex, all live queues are checked before any publication. If one is full, `AGAIN` is returned and nobody receives a partial/duplicate delivery. A retry of that same record is all-or-nothing. Closing/finishing a subscriber prunes it; accepted records drain before terminal `DISCONNECTED`. Counters distinguish accepted fixes, delivered copies, backpressure and repeated cached reads. This is not independent-consumer/drop-oldest delivery.

**Observation identity:** a driver may return the same cached fix repeatedly while sample time and fix age change. The coordinator compares the canonical wire payload except sample timestamp; fix time, coordinates, verified fields and measurements, satellites and reserved fields must match to suppress a previously **accepted** duplicate. A blocked sample is never marked accepted. A new source/device epoch resets identity; subscribing midstream does not promise replay of the last fix.

`CooperativeGnssProducer.h` retains at most one copied sample only after actual backpressure. The driver-owning task must call `retry()` on that sample BEFORE reading another hardware observation. `submit()` returns BUSY while pending, and retry preserves original sample time/verified fields. A duplicate, invalid reading or terminal result does not become a permanently pending fix. Clear pending state on device loss or before ELF unload. Neither class calls the driver, owns a worker task, nor stores pointers into an ELF.

### Device lease authorization binding (on PR #65)

`LocationLeaseBinding.h` is a **firmware-only template over the existing PR #64 DeviceRegistry contract**, not a second registry. After integration instantiate with `RuntimeDevices::Registry` and `RuntimeDevices::LeaseInfo`. `attach(owner, deviceHandle, providerGrant)` validates the actual `location.position` device lease, its owner and exact generation-safe device handle before registering a source. It BORROWS this grant: only the owning GPS driver may release it, after the binding is disconnected. A name, a cached GPS state or a caller-provided integer epoch is not authority.

`subscribe(owner)` requests a separate SHARED `location.position` lease with `preferred=deviceHandle`, validates the resulting device/owner/capability, opens a separate invocation-owned READ-only record queue and releases the grant on any failure. This method is never directly exported to an ELF: the firmware host authenticates the current execution-context owner before invoking it. `submit`/`retry` also check the provider's real grant before sending a copied fix, and use only the bound device handle rather than accepting an untrusted epoch. `reconcile` checks grants and removes individually revoked subscribers even without a new receiver fix. A revoked source calls `disconnect`, invalidates pending state and preserves accepted subscriber records for draining. `deviceLost(deviceHandle)` handles the same physical loss from PR #64's journal; loss events for a stale generation must not disconnect an identical replacement. `releaseOwner` reclaims subscriber streams and subscriber grants before `Registry::release(owner)`; it never prematurely releases the driver's borrowed source lease.

**Lease lifetime is shorter than drain lifetime.** On voluntary provider shutdown, physical-device leases may otherwise remain valid even though the source has stopped. `disconnect()` first finishes all subscriber streams with `DISCONNECTED`, then releases each subscriber's independent capability grant immediately and zeros its retained grant. It preserves generation-safe subscription tokens and stream queues until the owning consumers drain and unsubscribe. The borrowed provider grant remains the driver's responsibility and must be released after disconnect. A new provider cannot attach while old subscriber streams remain open, even though the hardware grants have already been returned. Repeated disconnect/owner cleanup must not double-release grants.

**Direct-close cleanup:** an ELF can call the ordinary stream v2 `close(handle)` rather than the semantic unsubscribe method. `LocationPositionSubscriptions::streamOpen(owner, token)` verifies both the token owner and actual stream liveness under the shared mutex; `LocationLeaseBinding::reconcile()` prunes that orphaned subscription and releases its device grant. Explicitly finished consumer streams are likewise no longer active device claims. This prevents an orphaned grant from blocking subsequent use of an otherwise-available device. Owner teardown remains a final cleanup path and cannot substitute for normal close handling.

**Thread and ordering contract:** PR #64 DeviceRegistry is single-runtime-task-owned. Device resolution, journal processing, lease binding and driver reads must occur on that owning task; do not access its registry from the generic stream scheduler. Serialize coordinator, binding and stream Registry operations under the SAME existing stream mutex. Hardware reads occur outside that mutex; the copied result is then submitted under the mutex. Before app/driver ELF unload: stop polling, revoke/disconnect the binding, release its subscriber device grants while preserving drainable records, then have the GPS driver release its source device lease and unload. Close remaining stream handles before their respective consumer ELF unloads. A new device generation never inherits previous subscribers.

The latter exercises the PR #64 acquire/getLease/release interface using a test double: wrong owner/device, independent subscriber grants, revoked consumer under backpressure, provider loss, stale replug, direct stream close, voluntary shutdown while queued samples drain, and cleanup. The host runner uses ASan/UBSan. Both firmware targets compile the GNSS adapters and lease template declarations. This is **not** an integrated test against PR #64's implementation and is not hardware acceptance.

## Still outstanding before live GNSS streaming

The installed `gps-nmea` driver ABI 1 synchronously reads UART on its claiming application task. This branch does **not** add a driver-owning background service, make the generic pipe scheduler call the driver, activate a provider from the Unified Device Registry, wire the binding to PR #64's actual lease and lifecycle journal, or expose an authenticated ELF `location.position` subscription getter. `LocationLeaseBinding` is implemented and host-tested against the interface, but its real PR #64 instantiation and board producer loop are pending. The old GPS app and `T5GpsApi` are unchanged. No new firmware-floor or release is asserted.

Integration and acceptance must cover start failures, no-fix and stale observations, full subscriber queues, owner exit, capability-loss journal and gap/resnapshot, identical-device hot-replug, UART/LoRa shared power, repeated driver install/unload and physical board runs. Do not call the architecture fully implemented merely because these foundation components pass host tests or compile on boards.
