# RiscRTE GNSS observation records and provider publication

## Authority and target

Read [RiscRTE Platform Specification](RISCRTE_PLATFORM_SPEC.md), [Platform Capability Roadmap](PLATFORM_CAPABILITY_ROADMAP.md), [Stream/Pipe Architecture](STREAM_PIPE_ARCHITECTURE.md), [typed record ABI](STREAM_RECORD_API_V2.md), [Application Execution Context Architecture](APPLICATION_EXECUTION_CONTEXT_ARCHITECTURE.md), and [GPS Driver](GPS_DRIVER.md). The target is an installable GNSS provider registered under `location.*` and resolved to a scoped, read-only typed record endpoint by RiscRTE. A producer and consumer must not retain a pointer into the other's ELF, and the runtime must reclaim streams and leases before either module is unloaded.

## Implemented on PR #65: safe data-plane boundary, not the provider service

`Registry::produceRecord(owner, handle, payload, length)` is **firmware-only**. It admits atomic writes into an owner-validated, READ-capable record queue without granting its ELF-facing handle public WRITE rights. It validates record kind, queue capacity, terminal state and ordinary backpressure, and participates in the same generation-safe registry and pipe scheduler. The embedding firmware bridge must hold its registry mutex around this call, as for other registry operations. This is NOT an exported ELF function and does not grant applications write access to sensor data.

`src/runtime/streams/GnssRecordAdapter.h` consumes a *copy* of an existing `t5_gps_state_t` on the driver's claiming task, validates fix status, fix-valid flag, age ≤ 5000 ms, finite latitude/longitude and coordinate bounds, then encodes exactly one `location.fix.v1` payload and submits it through the firmware-only publication entry point. It does not hold a driver callback or read the UART. A stale, unsupported, non-fix or invalid observation returns `AGAIN` and is not disguised as a position at (0,0). The adapter's `open()` creates an owner-bound READ-only record queue; `publish()` returns `AGAIN` under backpressure and does not silently drop the accepted record. Its caller retains responsibility for queue/driver lifecycle and for choosing whether to retry on full queues.

The C SDK `RiscRteLocationRecords.h` fixes the **52-byte, little-endian** `location.fix.v1` record. Fields at offsets: version u32 0, sample monotonic milliseconds u32 4, fix-time monotonic milliseconds u32 8, optional-field flags u32 12, latitude degrees binary64 16, longitude degrees binary64 24, altitude metres binary32 32, HDOP binary32 36, speed km/h binary32 40, heading degrees binary32 44, satellites u8 48, reserved zero bytes 49–51. `fix_ms = sample_ms - age_ms` uses a wrapping 32-bit clock; it is **not GNSS UTC**. Altitude, HDOP, speed and heading validity are individual flags; unknown optional values serialize as zero with their flag cleared. Consumers must decode fields by offset instead of casting an architecture-dependent C struct. Schema changes require a new `.vN` identity and an explicit transform for incompatible pipes.

`test/streams/gnss_record_adapter_test.cpp` exercises the production adapter with copied GNSS states and the actual shared registry: wire bytes and flags, invalid/stale/no-fix suppression, timestamp wrap, short-buffer atomicity, queue-full backpressure, v2 READ-only enforcement, firmware-only owner validation, transfer via a normal record pipe, and stale-handle cleanup. The runner builds and executes it with address/undefined-behavior sanitizers, and compiles the C wire header independently. CI results are only confirmed after GitHub reports them.

## Not implemented by this slice

The installed `gps-nmea` driver currently has a synchronous `read_state()` method that drains bounded UART data on its claiming application task. The runtime refuses use from a different task, and ABI 1 has no background worker. **Do not call this driver from the generic stream scheduler, keep a driver-ELF function pointer in a pipe, or claim autonomous sensor delivery based solely on this adapter.** There is not yet an application-facing semantic `location.position` subscription, a device-registry grant, a background producer loop, or a bridge that invokes this adapter on actual board fixes. The existing GPS app and legacy `T5GpsApi` remain unchanged.

The next integration step must add a runtime-owned provider worker/control plane with explicit driver-task ownership or evolve the driver ABI to support asynchronous emission safely; resolve `location.position` through the unified registry, allocate a READ-only stream with a capability lease, publish on the owning task, and stop/revoke the worker and stream before unloading the driver. Test startup failure, no-fix and stale data, slow consumers/backpressure, multiple consumer policy, hot-unplug, app termination, UART/LoRa shared rail and repeated install/reload on real hardware. Do not expose a global provider stream without per-context authority and independently specified fan-out semantics.
