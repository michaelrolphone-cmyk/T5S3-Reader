# RiscRTE GNSS observation records and provider publication

## Authority and target

Read [RiscRTE Platform Specification](RISCRTE_PLATFORM_SPEC.md), [Platform Capability Roadmap](PLATFORM_CAPABILITY_ROADMAP.md), [Stream/Pipe Architecture](STREAM_PIPE_ARCHITECTURE.md), [typed record ABI](STREAM_RECORD_API_V2.md), [Application Execution Context Architecture](APPLICATION_EXECUTION_CONTEXT_ARCHITECTURE.md), and [GPS Driver](GPS_DRIVER.md). The target is an installable GNSS provider registered under `location.*` and resolved to a scoped, read-only typed record endpoint by RiscRTE. A producer and consumer must not retain a pointer into the other's ELF, and the runtime must reclaim streams and leases before either module is unloaded.

## Implemented on PR #65: safe data-plane boundary

`Registry::produceRecord(owner, handle, payload, length)` is **firmware-only**. It admits atomic writes into an owner-validated, READ-capable record queue without granting its ELF-facing handle public WRITE rights. It validates record kind, queue capacity, terminal state and ordinary backpressure, and participates in the same generation-safe registry and pipe scheduler. The embedding firmware bridge must hold its registry mutex around this call, as for other registry operations. This is NOT an exported ELF function and does not grant applications write access to sensor data.

`src/runtime/streams/GnssRecordAdapter.h` consumes a *copy* of an existing `t5_gps_state_t` on the driver's claiming task, validates fix status, fix-valid flag, age ≤ 5000 ms, finite latitude/longitude and coordinate bounds, then encodes exactly one `location.fix.v1` payload and submits it through the firmware-only publication entry point. It does not hold a driver callback or read the UART. A stale, unsupported, non-fix or invalid observation returns `AGAIN` and is not disguised as a position at (0,0). Its `open()` creates an owner-bound READ-only record queue; `publish()` returns `AGAIN` under backpressure and does not silently drop an accepted record. Its caller retains responsibility for queue/driver lifecycle and for retrying the same copied observation if lossless publication is required.

**Optional-field provenance is mandatory.** Legacy `t5_gps_state_t` has no per-field presence mask: an RMC-only fix may have zero altitude even though altitude was never observed, and zero speed or heading is similarly ambiguous. `encode()` and `publish()` therefore accept an explicit `verifiedFields` mask that defaults to zero. They only assert a field's validity bit when the provider has explicitly verified its presence AND the number passes range/finiteness checks; unverified fields serialize as zero with the bit cleared. Unknown flag bits are invalid. A future GNSS provider must report real GGA/RMC field-presence metadata; do not infer observation from plausible numeric defaults or silently treat a guessed zero as measured data.

The C SDK `RiscRteLocationRecords.h` fixes the **52-byte, little-endian** `location.fix.v1` record. Fields at offsets: version u32 0, sample monotonic milliseconds u32 4, fix-time monotonic milliseconds u32 8, optional-field flags u32 12, latitude degrees binary64 16, longitude degrees binary64 24, altitude metres binary32 32, HDOP binary32 36, speed km/h binary32 40, heading degrees binary32 44, satellites u8 48, reserved zero bytes 49–51. `fix_ms = sample_ms - age_ms` uses a wrapping 32-bit clock; it is **not GNSS UTC**. Consumers must decode fields by offset instead of casting an architecture-dependent C struct. Schema changes require a new `.vN` identity and an explicit transform for incompatible pipes. The schema parser requires exactly one final `.vN` suffix with positive nonzero-leading version digits; extra earlier version segments and noncanonical segment characters are rejected.

### Bounded subscription and revocation coordinator

`src/runtime/streams/LocationPositionSubscriptions.h` is a **firmware-only**, allocation-bounded coordinator that uses the existing shared `StreamRuntime::Registry`; it does not create an alternate stream registry or export an unguarded application API. At most one source and four subscriber leases are active. Every subscriber owns a separate `location.fix.v1` READ-only stream in its execution context, and each stream uses the usual generation-safe handle and four-record queue. An opaque source token binds provider owner and monotonically advancing generation; the resolved physical device epoch is checked on every publication. Subscription leases have independent monotonically advancing generations and are checked against their owner on release. A disconnected source cannot be silently replaced while old subscriptions remain alive.

**Fanout policy for this initial slice is coupled `BLOCK_PRODUCER`, not lossy broadcast.** While holding the same runtime mutex used for every registry operation and pipe pump, publication first checks capacity at *all* live subscribers. If any queue is full, `AGAIN` is returned and nothing is sent to anyone; retrying the *same observation* cannot duplicate it for a fast consumer. Once every subscriber has room, each receives one complete record. A closed or explicitly finished subscriber is pruned, a foreign owner cannot release another owner's lease, and a stale handle cannot attach publication to a reused slot. The coordinator tracks accepted observations, record deliveries and backpressure events. No record dropping or independent-per-consumer policy is silently assumed.

**Observation identity:** legacy GNSS polling can return the same valid receiver fix many times while `sample_ms` and `age_ms` change. The coordinator compares the complete canonical 52-byte record except for `sample_ms`; `fix_ms`, position, validity flags, optional measurements, satellite count and reserved bytes must all match before classifying a read as an already accepted duplicate. Such a duplicate returns `AGAIN` and increments `duplicates`, not `backpressure`. Any changed measurement is a new observation even when the timestamp is unchanged. Only an entirely delivered observation is recorded as accepted; a backpressured observation must be retried unchanged. Attaching a new provider/device epoch resets observation identity. The counters distinguish accepted fixes, delivered copies, blocked publications and repeated cached fixes. No replay of the last fix is promised to a newly attached subscriber.

**Cooperative producer state:** `src/runtime/streams/CooperativeGnssProducer.h` provides bounded, firmware-only support for the existing synchronous driver ABI. Its `submit` accepts a copied observation and original sample time; if and only if the coordinator reports real backpressure, it stores that sample and returns `AGAIN`. The owning task MUST check `hasPending()` and call `retry()` under the shared stream mutex before polling a new receiver observation. While pending, `submit()` rejects new data with `BUSY` instead of overwriting the sample. Retry preserves the original sample timestamp, optional field provenance and payload, and clears pending state only on success, an already-accepted duplicate or terminal rejection. Explicit `clear()` is required on device lease loss and before driver unload. Neither the producer nor coordinator holds ELF function pointers, polls hardware, or creates an asynchronous task. This is a control-flow building block, not a claim that GPS is now autonomously streaming.

On provider disconnect, all subscriber streams are finished with `DISCONNECTED`, preserving already queued observations for draining; the source token is invalidated. `releaseOwner(owner)` must be called **before** `Registry::release(owner)` on invocation teardown, so subscriber handles are reclaimed and a provider-owner exit revokes its dependent streams. Once disconnected subscribers close, a new provider with a new epoch may attach. Calls to the coordinator, including publication, teardown and ordinary registry operations, must share the *same external registry mutex*. A provider polls hardware on its own claiming task *outside* that mutex, passes only a copied state to the coordinator, and never gives the pipe scheduler an ELF callback.

**Control-plane precondition:** the Unified Device Registry / resolver must authenticate the provider's semantic device claim and validate each application's `location.position` capability lease before firmware calls `attachProvider()` or `subscribe()`. Source tokens are firmware-internal; they are not permissions that ELFs may supply. The coordinator implements stream and subscription lifecycle, not device discovery, authorization or independently running driver tasks. PR #64 separately develops the parent registry and device event journal; these branches must be integrated without duplicating that implementation.

`test/streams/location_position_subscriptions_test.cpp` uses the production shared registry to exercise two-consumer all-or-nothing backpressure, repeated cached fixes, no duplicate deliveries after retry, READ-only access, foreign-owner denial, source/device epoch invalidation, draining then disconnect, stale subscription/stream handles, explicit unsubscribe, context release and provider replacement. `test/streams/cooperative_gnss_producer_test.cpp` tests pending-sample retention against two slow subscribers, retry ordering, duplicate/no-fix distinction and loss during a pending sample. The runner executes these and GNSS adapter tests under address/undefined-behavior sanitizers. `GnssRecordAdapter.cpp` includes the coordinator and cooperative producer so both board firmware builds compile their definitions. CI success is only claimed for a particular tested commit.

## Not yet implemented as live GNSS delivery

The installed `gps-nmea` driver currently has a synchronous `read_state()` method that drains bounded UART data on its claiming application task. The runtime refuses use from a different task, and ABI 1 has no background worker. **Do not call this driver from the generic stream scheduler, keep a driver-ELF function pointer in a pipe, or claim autonomous sensor delivery based solely on this adapter.** This slice implements subscription/data-plane lifecycle and cooperative pending-sample semantics but has not connected them to PR #64's device grants or the board's active GPS read loop. There is no application-facing `location.position` subscription API yet; the existing GPS app and legacy `T5GpsApi` are unchanged.

The integration must wire the Unified Device Registry authorization and capability-loss/removal journal to the coordinator; supply a driver-owning producer loop or a deliberately cooperative `poll` operation on the claiming task; publish copied observations under the stream mutex; stop/revoke the worker and stream before unloading the driver. The provider must not poll new data over a backpressured pending sample unless a documented, explicit loss policy applies. Test startup failure, no-fix/stale data, slow consumers, device loss, app termination, UART/LoRa shared rail and repeated install/reload on real hardware before claiming completion.
