# RiscRTE GNSS observation records and provider publication

## Authority and target

Read [RiscRTE Platform Specification](RISCRTE_PLATFORM_SPEC.md), [Platform Capability Roadmap](PLATFORM_CAPABILITY_ROADMAP.md), [Stream/Pipe Architecture](STREAM_PIPE_ARCHITECTURE.md), [typed record ABI](STREAM_RECORD_API_V2.md), [Application Execution Context Architecture](APPLICATION_EXECUTION_CONTEXT_ARCHITECTURE.md), [GPS Driver](GPS_DRIVER.md), and [GNSS registry integration](STREAM_GNSS_REGISTRY_INTEGRATION.md). The target is an installable GNSS provider registered under `location.*`, resolved to a capability-lease-protected, READ-only typed record endpoint. Neither producer nor consumer retains a pointer into the other's ELF. The firmware must reclaim streams and leases before unloading an ELF.

## Implemented on PR #65: data plane

`Registry::produceRecord(owner, handle, payload, length)` is firmware-only: an owner-validated atomic write to a READ-capable record queue without granting the ELF public WRITE rights. Kind, capacity, terminal state and bounded backpressure are enforced. The embedding bridge must hold its existing stream-registry mutex. Never export this privileged function to an ELF.

`src/runtime/streams/GnssRecordAdapter.h` accepts a **copy** of `t5_gps_state_t`, never a driver callback or UART handle. It requires fix status, valid fix flag, age <= 5000 ms, finite latitude/longitude and bounded coordinates. No-fix, stale, unsupported and malformed observations return `AGAIN`; they never become invented (0,0) fixes. Its `open()` creates an invocation-owned READ-only queue and `publish()` returns `AGAIN` for full buffers. The adapter does not poll hardware, launch a worker or manage driver ownership.

**Optional-field provenance:** legacy `t5_gps_state_t` lacks per-field presence flags. Zero altitude, speed or heading may mean *not observed*. `encode()`/`publish()` accept an explicit `verifiedFields` mask, default zero. The encoder marks altitude, HDOP, speed or heading valid only when source presence has been established independently and values pass range/finiteness checks; otherwise it writes zero and clears the validity bit. Unknown bits fail validation. A future driver must expose real GGA/RMC field-presence metadata; do not infer observation from plausible numeric defaults.

The C SDK `RiscRteLocationRecords.h` defines a **52-byte little-endian** `location.fix.v1` wire record: version u32 @0; sample monotonic ms u32 @4; fix monotonic ms u32 @8; verified-field flags u32 @12; latitude and longitude binary64 @16/@24; altitude, HDOP, speed and heading binary32 @32/@36/@40/@44; satellites u8 @48; three zero reserved bytes @49–51. `fix_ms = sample_ms - age_ms` uses wrapping u32 monotonic time, **not GNSS UTC**. Decode by offset, not a platform-specific C struct cast. A schema change requires a new `.vN` and a transform for incompatible pipes. Schema validation requires a single canonical final nonzero `.vN` suffix.

## Bounded subscription, backpressure and deduplication

`LocationPositionSubscriptions.h` uses the **existing** StreamRuntime registry: one source and at most four independent, generation-safe subscription tokens, each with a separate invocation-owned READ-only queue holding four complete records. The source token binds owner/generation, and publication checks the exact generation-safe physical-device handle. Foreign owners cannot release another subscriber; a stale stream cannot alias a replacement. Disconnected sources cannot be replaced while old subscriber streams remain open.

Initial fanout is coupled `BLOCK_PRODUCER`, not lossy independent broadcast. Under the same mutex protecting *all* registry reads, closes and pipe pumping, check every live subscriber's queue before any write. If one is full, return `AGAIN` without delivering to anyone. Retrying the same record is then all-or-nothing with no duplicate fast-consumer deliveries. Prune closed/finished subscribers; preserve already accepted records until a terminal `DISCONNECTED` is read. Accepted observations, delivered copies, backpressure and cached-fix duplicates have separate counters.

**Observation identity:** a synchronous driver can repeatedly report a cached fix while the sample timestamp and reported age change. Compare the complete canonical wire record except `sample_ms`; fixed observation time (`fix_ms`), coordinates, verified fields/measurements, satellite count and reserved bytes all contribute. Suppress only a *previously accepted* identical observation; a blocked observation remains retryable. Attaching a new source/device epoch resets identity. A newly subscribed reader is not promised replay of an earlier fix.

`CooperativeGnssProducer.h` retains exactly one copied sample **only** after real backpressure, including its original timestamp and verified-field provenance. The driver-owning task must retry pending data **before** polling another hardware observation; `submit()` returns `BUSY` while pending, and cannot overwrite it. Invalid readings and accepted duplicates never become stuck pending samples. Clear pending data on device loss or before driver unload. The producer neither calls into the driver ELF nor creates a worker task.

## Device capability authorization and lifetime

`LocationLeaseBinding.h` uses the **same production `RuntimeDevices::Registry` implementation** from PR #64 rather than an alternate inventory. `attach(owner, deviceHandle, providerGrant)` checks the real `location.position` lease, owner and exact physical device generation. It BORROWS the source grant, which the GPS driver alone releases after stream disconnect. Neither the device name nor a caller-supplied integer epoch is authority. `subscribe(owner)` acquires a separate SHARED `location.position` lease with preferred physical handle, checks its metadata, creates an owner-bound READ-only queue, and releases a failed acquisition. The eventual ELF-facing host must authenticate the currently running `ExecutionContext`; the firmware-only binding is not an unguarded application API.

`submit()` and `retry()` recheck the borrowed source grant, then publish a copied observation with the bound device handle. `reconcile()` checks both source and subscriber grants; individually revoked consumers are pruned without requiring another GPS fix. `deviceLost(exactHandle)` disconnects that generation, but a delayed event for a previous generation cannot disconnect its replacement. `releaseOwner()` reclaims the owner's streams and subscriber grants **before** the shared stream registry releases its handles, without releasing another context's borrowed source grant.

**Lease lifetime precedes drain lifetime:** on voluntary stop or device loss, `disconnect()` first finishes subscriber streams with `DISCONNECTED`, releases independent subscriber device grants immediately, and clears pending data. Accepted records and generation-safe subscription tokens remain until the owning consumer drains and closes. A new source cannot attach while old stream subscriptions remain active, although their physical claims are already released. Repeated disconnect/cleanup must not double-release grants.

**Direct-close cleanup:** an ELF can close a stream through ordinary v2 `close(handle)` instead of semantic unsubscribe. `LocationPositionSubscriptions::streamOpen(owner, token)` validates stream liveness and token owner; the next `LocationLeaseBinding::reconcile()` reclaims an orphaned device grant and token. A finished consumer is likewise no longer an active claim. Execution-context teardown remains the final cleanup path, not a substitute for explicit close handling.

**Concurrency and ordering:** the device registry is single-runtime-task-owned. Device resolution, lifecycle journal handling, lease binding and synchronous GPS reads stay on that owner task; the generic pipe scheduler must not call the GPS ELF or mutate the device registry. Serialize coordinator/binding/stream-registry operations under the SAME existing stream mutex. Poll hardware outside that mutex on the driver-owning task, then submit its copied data under the mutex. Before ELF unload: stop polling, disconnect/revoke stream binding, release consumer claims while preserving queued records, release the borrowed source lease from the GPS driver, unload the driver, and close any remaining consumer streams before their ELFs unload. A new device generation requires fresh leases and subscriptions.

## Verification and live-integration boundary

The host runner executes `record_queue_test.cpp`, `record_registry_test.cpp`, `bridge_test.cpp`, `gnss_record_adapter_test.cpp`, `location_position_subscriptions_test.cpp`, `cooperative_gnss_producer_test.cpp`, `location_lease_binding_test.cpp` and `location_production_registry_test.cpp` under ASan/UBSan. The focused lease test uses an interface-matching double for negative cases. The production-registry test instead uses the **identical `DeviceRegistry.h` Git blob** from PR #64 (`6947ec84591698dfab166f41c3c10c2b947f5603`): actual shared lease acquisition/revocation, event journal `CapabilityLost`, physical generation changes, draining and borrowed source ownership. `GnssRecordAdapter.cpp` explicitly instantiates `LocationLeaseBinding<RuntimeDevices::Registry, RuntimeDevices::LeaseInfo>` so both board builds check the concrete implementation. See [GNSS registry integration](STREAM_GNSS_REGISTRY_INTEGRATION.md) for exact source provenance and merge procedure. CI success applies only to the tested head, not physical GPS behavior.

**Still outstanding:** PR #64's active GPS driver lease/start/stop path, its common lifecycle journal and its separate *device observation* ELF SDK have NOT been merged or wired into PR #65's runtime. This branch does not start a driver-owning background service, expose an authenticated ELF position-data getter, activate a provider from the resolver, or call the synchronous driver on its claiming task for publication. Device observation alone does not grant hardware access. The old GPS app and `T5GpsApi` stay unchanged; no release or firmware floor is asserted.

End-to-end acceptance must cover startup failure, no-fix and stale records, full queues and retries, context termination, lifecycle event gap/resnapshot, identical-device replug, UART/LoRa shared power, driver install/unload and physical board runs. Passing isolated host tests or firmware compilation is not a claim of a live GNSS stream.
