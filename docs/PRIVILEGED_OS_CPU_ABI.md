# RiscRTE privileged OS/CPU ABI v1

**Authority:** [RiscRTE Platform](RISCRTE_PLATFORM_SPEC.md), [hardware-agnostic ownership](HARDWARE_AGNOSTIC_DRIVER_BOUNDARY.md) and [runtime drivers](RUNTIME_DRIVER_ARCHITECTURE.md). This document distinguishes the production contract from the experimental implementation in draft PR #78.

## 1. Hardware ownership and ABI

The CPU/OS port supplies generic interrupts, tasks, queues, synchronization, bounded allocation, logging, libc and low-level CPU pin-matrix primitives to *authorized* independently loaded ELFs. It MUST NOT supply USB/I²C implementations, enumeration, transfers, charger commands, hardware-specific managers or fallback. The core treats capability IDs as opaque; it never branches on `usb`, `i2c` or board identifiers. Each provider ELF owns its entire physical driver, callbacks and teardown and may consume other provider capabilities.

This privileged ABI is separate from the application ABI. Its exact 46-symbol compatibility inventory is `lib/elf_loader/include/private/privileged_os_cpu_symbols_v1.def`. Strong references turn a missing symbol into a firmware link failure. `esp_rom_gpio_*` are CPU pin/pad routing primitives, not firmware GPIO-device implementations. None of these privileges are added to ordinary application exports, customer tables or registered ELF symbols. A future ABI may consolidate the compatibility inventory into a versioned structured port API.

## 2. Import inventory, exact declarations and resolution

`esp_elf_relocate_privileged_verified_v1` validates the image structurally and calls `esp_elf_privileged_imports_valid_v1` **before** privileged scope or executable mapping. It examines undefined global/weak imports in **both** `.dynsym` and `.symtab`, including tables with no relocations. It checks symbol/string bounds, duplicate/missing dynamic tables, malformed names/offsets, REL format, invalid RELA links and out-of-range symbol indices. Imports must come from the fixed libc compatibility snapshot or the exact 46-symbol OS/CPU inventory. Peripheral, firmware `t5_*`, customer and cross-ELF external imports are rejected.

`esp_elf_privileged_manifest_imports_match_v1` requires a nonempty, strictly sorted, unique import declaration of at most 128 names, each 1–127 bytes. It checks exact set equality against all undefined imports in both symbol tables; missing, extra, duplicate, unsorted, malformed, forbidden and otherwise permitted but undeclared imports fail before mapping. `SpecV2 -> ModuleV2 -> esp_elf_relocate_privileged_verified_v1` carries the declaration and compares it with the digest-checked ELF snapshot. **Consistency of supplied declarations does not authenticate their source.** The graph's shape checks are not an authorization boundary.

**Global custom-resolver bypass closed:** `elf_find_sym()` directly invokes the private-scoped `elf_find_sym_default()` while the current task owns the scope, never the mutable global `current_resolver` hook. Only the fixed OS/CPU inventory and libc are visible, with no IDF/customer/registered/cross-ELF fallback. Other tasks preserve ordinary custom lookup. The regression compiles the actual production resolver body and tests a malicious custom provider for `usb_host_install`, including concurrent hook changes.

**Same-task nested relocation inheritance closed for the standard loader entry:** after a verified provider passes preflight and `esp_elf_init`, the private entry calls `esp_elf_privileged_os_cpu_authorize_relocation_v1(module)` with that exact `esp_elf_t *`. Every public `esp_elf_relocate()` invocation checks `esp_elf_privileged_os_cpu_relocation_enter_v1(elf)` before mapping; when its task owns a privileged scope, any unbound module or nested call, including reentering the same module, fails with `-EPERM`. The exact module consumes its grant once. The wrapper always calls `relocation_leave_v1` after its implementation returns, including error returns, and fails closed on a mismatched leave. `end_v1` will not release an active relocation; wrong-task scope operations fail. Ordinary relocations on other tasks are unaffected and ordinary loads outside any scope retain their existing behavior. This does not require a global lock around app loading or swapping a resolver pointer. Tests exercise the production scope C source, private relocation entry and the compiled production *public* relocation function body against nested/unauthorized loads, backend errors and failed leave.

This guard covers standard ELF loader entry points, not arbitrary functions a malicious firmware-native caller might invoke inside the same task or execution-time memory access. Native ELFs share firmware address space; loader namespace filtering is **not** an isolation sandbox. Authenticated manager-only admission remains mandatory.

## 3. Authenticated bytes and package-manager handoff

Separate draft [Unified Package Manager PR #76](https://github.com/michaelrolphone-cmyk/T5S3-Reader/pull/76) implements experimental RISC-PKG signed-prefix P-256 verification, entry SHA-256, firmware-owned signer policy and an NVS-backed security-version floor. These branches are unmerged; normal installers remain unsigned, no production signer provisioning or authenticated provider receipt is connected, and the signed package manifest does not yet declare the provider ABI and exact imports. Do not duplicate cryptographic formats in PR #78.

A trusted intake must bind signer/scope, security version, architecture, package/provider identity, ABI, exact import names, dependencies, executable length, expected 32-byte digest and execution-context/resource authorization into one immutable manager-owned receipt. Its strings and arrays must remain valid until no graph activation is possible; arbitrary application pointers, unsigned JSON, manifest shape and self-declared digests confer **no authority**. `SpecV2` stores the authenticated digest **by value**, while `ModuleV2::loadVerifiedBytes` copies candidate bytes privately, hashes *that same copy*, compares against the authenticated expected digest and relocates only the matching snapshot. SD replacement after trusted inspection is detected before mapping provided the digest itself came from a verified signer. An in-process malicious native task requires stronger memory isolation.

Installed, authenticated, admitted, mapped, activated and hardware-owned are distinct states. The experimental graph's privileged API must not become an unrestricted public intake surface.

## 4. Quiescence and exclusive physical ownership

Privileged providers must implement `quiesce()`. Failed start/teardown may leave IRQs, DMA, callbacks or hardware active: ELF remains mapped, new grants are denied and dependency providers stay pinned until quiescence. Successful quiescence must drain callbacks, stop DMA/tasks/timers, remove IRQs, disable its peripheral and prevent borrowed pointers into unmapped code. Graph claims alone cannot arbitrate against compiled legacy USB, charger or `Wire`. Exclusive controller/PHY/VBUS/I²C0 cutover and real electrical testing remain acceptance gates.
