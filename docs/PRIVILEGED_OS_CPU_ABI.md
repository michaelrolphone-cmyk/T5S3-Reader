# RiscRTE privileged OS/CPU ABI v1

**Authority:** [RiscRTE Platform](RISCRTE_PLATFORM_SPEC.md), [hardware-agnostic ownership](HARDWARE_AGNOSTIC_DRIVER_BOUNDARY.md) and [runtime drivers](RUNTIME_DRIVER_ARCHITECTURE.md). This document distinguishes the required production contract from the experimental implementation in draft PR #78.

## 1. Hardware ownership and ABI

The CPU/OS port supplies generic interrupt registration, task/queue/synchronization, bounded allocation, logging, libc and low-level CPU pin-matrix primitives to *authorized* independently loaded ELFs. It MUST NOT supply USB/I²C implementations, enumeration, transfers, charger commands, hardware-specific managers or fallback. The core treats advertised capability IDs as opaque data; it never branches on `usb`, `i2c` or board-specific identifiers. Each provider ELF owns its entire physical driver, callbacks and teardown, potentially consuming other independently installed provider capabilities.

The privileged ABI is not the application ABI. Its exact 46-symbol compatibility inventory lives in `lib/elf_loader/include/private/privileged_os_cpu_symbols_v1.def`. Strong references make missing port symbols a firmware **link failure**. The `esp_rom_gpio_*` names are CPU pin/pad routing primitives, not firmware GPIO-device implementations. The fixed compatibility names are transitional; later ABIs SHOULD consolidate them into a versioned structured port API. Nothing in this inventory is added to ordinary app exports, customer tables or globally registered ELF symbols.

## 2. Complete import inventory, signed declarations, and scoped resolution

`esp_elf_relocate_privileged_verified_v1` structurally validates its caller-authenticated input image and calls `esp_elf_privileged_imports_valid_v1` **before** acquiring privileged resolution scope or mapping executable code. That preflight examines undefined global/weak imports in **both** `.dynsym` (type 11 in the pinned loader) and `.symtab` (type 2), even when a table has no relocation references. It bounds string/symbol tables, rejects duplicate/missing dynamic tables, malformed names and offsets, unsupported REL, invalid RELA links, and out-of-range relocation indices. Imports must belong to the exact public-libc compatibility snapshot or the 46 OS/CPU names. Peripheral, firmware `t5_*`, customer or cross-ELF external imports are rejected.

**Implemented additional exact-declaration gate:** `esp_elf_privileged_manifest_imports_match_v1` requires a nonempty, strictly sorted, unique array of at most 128 names, each 1–127 bytes. It computes the set of *actual* undefined imports across both symbol tables, including duplicates appearing in both, and requires set equality with the supplied declaration: no missing, extra, duplicate, unsorted or unknown import. Thus even an ABI-wide permitted name cannot appear in a driver unless that *particular package's signed import list* declares it. The private relocation entry invokes both checks before acquiring its scope or mapping code. `SpecV2` and `ModuleV2` now require and propagate import declarations in addition to the expected SHA-256 and ABI version. The graph only performs basic declaration-shape checks; the loader checks exact image equality on the digest-checked snapshot. Tests compile both the exact matcher and the actual private relocation entry using mocked hardware/relocator to prove mismatches fail before scope/mapping.

**Crucial trust limitation:** the matcher checks supplied declarations for consistency, but cannot prove their source. The package format in separate PR #76 does not yet carry an authenticated OS/CPU ABI plus exact import list, and no production signer-to-graph handoff exists. An application-provided declaration, digest or `SpecV2` is never permission to relocate a privileged ELF. The caller MUST obtain the declarations, ABI, identity and executable digest from the **same verified signed package receipt**, authorize a particular execution context, and maintain stable manager-owned declaration storage until no graph activation can occur. No user-supplied manifest or mutable string pointer can substitute for this requirement. Current graph shape validation is NOT an authorization boundary; keep all experimental providers noninstallable.

During privileged relocation the default resolver may return only this task's OS/CPU inventory or the compiled libc table; it does not fall through to customer/IDF/registered or another loaded module's exports. Locally defined provider symbols use the relocator's in-image fallback. Concurrent ordinary ELF loads on other tasks retain their normal namespace. The scope denies nested, concurrent and wrong-task entry and is revoked on every exit.

**Unresolved custom-resolver bypass:** the pinned loader dispatches `elf_find_sym` through a process-global `current_resolver` pointer, which can bypass the safe default resolver. Before any production privileged admission, the privileged relocation path MUST bind directly to its private resolver (or add an equivalent module-specific resolver), never depend on the mutable global hook. Do not temporarily swap the global pointer: that would affect concurrent ordinary application loads. Native code is not memory-isolated and can still address shared RAM after execution.

## 3. Authenticated bytes and package-manager integration

Draft [Unified Package Manager PR #76](https://github.com/michaelrolphone-cmyk/T5S3-Reader/pull/76) implements RISC-PKG v1 signed-prefix P-256 verification, per-entry SHA-256 and firmware-owned signer policy scoped by package kind/ID and revocation. Do not duplicate those formats in PR #78. Both PRs are unmerged, normal installers remain unsigned, and no production keys or persistent rollback floors are provisioned. The signed manifest must be extended to represent the provider's exact ABI/import declaration and authenticated package identity; the trusted manager then needs to bind the signer, security version, architecture, authorized provider identity, requirements, imports, entry length, raw 32-byte digest and execution-context/resource grants into a private receipt. Its receipt-to-graph registration must not expose a public arbitrary-pointer admission method.

The private graph stores `authenticatedElfSha256[32]` **by value** and rejects missing digests or signed imports. `ModuleV2::loadVerifiedBytes` copies candidate bytes to temporary private memory (PSRAM preferred), hashes *that same copy*, compares it to the signed-entry digest, then invokes the private exact-import validator/relocator on only the matching snapshot. It does not reopen an SD path and frees the temporary image once relocation is complete. An SD-file substitution after package inspection is detected before mapping provided the expected digest was authenticated. A malicious in-process native task remains outside this protection and requires stronger isolation.

Installed, authenticated, admitted, mapped, activated and hardware-owned are distinct states. Neither a SHA-256 digest copied from unsigned JSON nor successful host relocation tests confer any privilege.

## 4. Quiescence and exclusive ownership

Privileged providers must implement `quiesce()`. Failed start/teardown can retain live IRQs, DMA, timers, tasks, or hardware ownership: the ELF remains mapped, new grants are denied and dependencies stay pinned until quiescence is demonstrated. Successful quiescence must drain callbacks, stop DMA/tasks/timers, remove IRQs, disable its peripheral, and ensure borrowed pointers no longer reach unmapped code. Only then can the runtime stop and unload the ELF. Graph claim bookkeeping alone cannot arbitrate against compiled legacy USB, charger, or `Wire` hardware owners. Exclusive controller/PHY/VBUS/I²C0 cutover and physical electrical testing are separate acceptance gates.

## 5. Verification status and acceptance (September 17, 2026)

[Experimental CI 35265970335](https://github.com/michaelrolphone-cmyk/T5S3-Reader/actions/runs/35265970335) passed host scope/digest tests, physical USB/I²C PIC ELF builds, strict relocation audits and the compiled C import preflight against actual binaries. [Firmware CI 35265970338](https://github.com/michaelrolphone-cmyk/T5S3-Reader/actions/runs/35265970338) passed both board builds and general host tests. These precede the exact-manifest-import changes. The first expanded host run exposed a test-fixture-only duplicate ELF type definition, corrected in the subsequent commit; the current-head CI must be separately checked. No actual T5S3 hardware activation has been performed. Experimental physical ELFs are diagnostic, unpublished and noninstallable; shipping USB/Serial Monitor, `Wire` and charger paths are unchanged.

Remaining production acceptance: finish process-global custom-resolver isolation; extend and authenticate PR #76's signed ABI/import format and trusted receipt-to-graph handoff; reject signer/identity/ABI/requirement/import/context/rollback mismatches; acquire exclusive physical resources; actually relocate/start/stop physical USB and I²C ELFs on T5S3; test electrical VBUS/backfeed/current, replug/hubs/duplex and fault-injected IRQ/DMA teardown with no hidden compiled hardware fallback. Host, hash, C import, firmware-link and PIC-build passes do not establish physical safety.
