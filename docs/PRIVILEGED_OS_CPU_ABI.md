# RiscRTE privileged OS/CPU ABI v1

**Authority:** [RiscRTE Platform](RISCRTE_PLATFORM_SPEC.md), [hardware-agnostic ownership](HARDWARE_AGNOSTIC_DRIVER_BOUNDARY.md) and [runtime drivers](RUNTIME_DRIVER_ARCHITECTURE.md). This document distinguishes the required production contract from the experimental implementation in PR #78.

## 1. Hardware boundary and ABI

The CPU/OS port supplies generic interrupt registration, task/queue/synchronization, bounded allocation, logging, libc and low-level CPU pin-matrix primitives to *authorized* independently loaded ELFs. It MUST NOT supply USB/I²C driver implementations, enumeration, transfers, charger commands, hardware-specific managers or fallback. The core treats every advertised capability ID as opaque data; it never branches on `usb`, `i2c` or a board-specific identifier. A provider ELF owns its complete physical driver, callbacks and teardown, potentially consuming other provider capabilities.

The privileged ABI is not the application ABI. Its current exact 46-symbol compatibility inventory lives in `lib/elf_loader/include/private/privileged_os_cpu_symbols_v1.def`. Strong references make missing port symbols a firmware **link failure**. The `esp_rom_gpio_*` names are CPU pin/pad routing primitives, not a firmware GPIO device implementation. The fixed compatibility symbols are transitional: later ABIs SHOULD consolidate them into a versioned structured port API. Nothing in this inventory is added to ordinary app exports, customer tables or globally registered ELF symbols.

## 2. Import preflight and symbol resolution

`esp_elf_relocate_privileged_verified_v1` first validates the exact input image structurally, then calls `esp_elf_privileged_imports_valid_v1`, **before** acquiring a privileged resolution scope or mapping executable code. The preflight checks every undefined global/weak import in both `.dynsym` (ELF section type 11, named `SHT_SYNSYM` in the pinned loader header) **and `.symtab` (type 2)**. A RELA section may reference either symbol table; each is validated independently against its own bounded string table. The preflight rejects duplicate/missing dynamic tables, malformed offsets and names, unsupported REL sections, invalid RELA table links and out-of-range relocation symbol indices. Only the fixed ordinary-libc compatibility snapshot and the 46 exact OS/CPU names are accepted; no peripheral, firmware `t5_*`, arbitrary customer or cross-ELF import is an acceptable external dependency. This is an import allowlist, not a signature verifier.

The default resolver is task-aware. During a privileged relocation it may return only that task's privileged port symbols or entries from the existing compiled libc table; it **cannot fall through** to the IDF/customer/global registration tables or symbols from previously loaded modules. Locally defined provider symbols continue to use the ELF relocator's in-image fallback. A concurrent ordinary ELF loaded on another task retains its normal namespace. The scope itself is non-reentrant and rejects nested, concurrent and wrong-task acquisition; ordinary applications do not obtain the privileged names.

**Resolver limitation:** the pinned loader also supports a process-global *custom* resolver. This PR does not change that legacy global hook. Privileged admission MUST ensure the default resolver is the active resolver, or extend the loader with a module-specific callback before permitting privileged production loads. Task-scoped lookup is neither a sandbox nor a defense against native code guessing addresses after execution.

## 3. Authenticated-byte lifetime and PR #76 integration

Privileged package authorization needs an authenticated signer, signed package identity, declared ABI, exact signed import policy, execution-context grant, dependency/resource claims and one specific executable entry. A SHA-256 digest copied from an untrusted manifest, a signed assertion without verified payload bytes, or a caller-supplied image pointer cannot grant privilege.

PR #76 ([Unified Package Manager](https://github.com/michaelrolphone-cmyk/T5S3-Reader/pull/76)) already implements an experimental RISC-PKG v1 P-256 signed-prefix verifier, per-entry SHA-256 verification and a firmware-owned signer policy with kind/ID scope and revocation. **Do not duplicate those cryptographic formats in PR #78.** The two branches are unmerged and the existing normal installers are unsigned; no production signer keys or persistent anti-rollback store are provisioned. The package format still needs a signed OS/CPU ABI/import-declaration contract and a trusted handoff to the generic provider graph. In particular, the package receipt should pin the authenticated `Provider` identity, architecture, ABI version, signer scope, security version, exact import set, executable length and raw 32-byte SHA-256 from the signed entry.

A private `SpecV2` carries the authenticated entry digest **by value** in `authenticatedElfSha256[32]`. Ordinary path loads forbid a digest or privileged byte fields. Privileged specs require ABI v1, a bounded candidate buffer and a nonzero expected digest, but shape validation does NOT authenticate their caller. At activation `ModuleV2::loadVerifiedBytes` copies candidate bytes into its own temporary buffer (PSRAM when available), SHA-256 hashes *that copy*, compares it to the pinned signed-entry digest and relocates only the same matching copy. It never reopens a file by path and frees the temporary image after relocation. A removable-storage replacement between archive inspection and activation therefore fails its digest check before mapping; this does not prevent malicious firmware/native tasks from modifying shared RAM, which requires stronger isolation.

The trusted P-256 verifier/policy must be integrated with package intake, an authorized provider executor and exclusive-resource grants before the graph's private privileged admission can be used in production. Do not enable privileged access merely because a file passes the generic shape/digest checks. Installed, verified, mapped, activated and hardware-owned are separate states.

## 4. Failure and safe unload

A provider requiring privileged imports must expose `quiesce()`. Start failure may leave interrupts, DMA, tasks or hardware active: unsuccessful quiesce keeps the ELF mapped, prevents new grants and retains every dependent provider pin. Successful quiesce must prove IRQ callbacks drained, DMA stopped, tasks/timers/queues terminated, peripheral disabled and borrowed callbacks unable to reach unmapped code. Only then may the generic runtime call stop and release memory/dependencies. No generic graph claim can exclude compiled legacy USB or `Wire`; exclusive controller/PHY/VBUS/I²C0 ownership remains a separate physical cutover requirement.

## 5. Evidence and acceptance status (September 17, 2026)

Before the latest digest-snapshot changes, [experimental CI 35264689941](https://github.com/michaelrolphone-cmyk/T5S3-Reader/actions/runs/35264689941) passed the `.symtab`/`.dynsym` regression suite, both physical PIC ELF builds, strict relocation audits and compiled C preflight against the real USB/I²C/clock binaries. [Firmware CI 35261889542](https://github.com/michaelrolphone-cmyk/T5S3-Reader/actions/runs/35261889542) passed both board firmware builds and the general host suite before this turn's changes. The current-head firmware/snapshot validation must be checked independently. Physical ELFs remain **diagnostic, unpublished, non-installable**. Shipping USB/Serial Monitor, `Wire` and charger are unchanged.

Remaining acceptance: complete signed PR #76 package-to-graph handoff and resolver hook hardening; test signed identity/ABI/import mismatch, changed candidate bytes and context denial; relocate/start/stop the physical USB and I²C ELFs on real T5S3; arbitrate exclusive ownership against legacy drivers; verify power/backfeed/current, USB attach/hubs/replug and duplex, fault-injected IRQ/DMA teardown and absence of compiled firmware hardware fallback. Host, linker, import and hash tests alone do not establish hardware acceptance.
