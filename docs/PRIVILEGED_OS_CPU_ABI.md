# RiscRTE privileged OS/CPU ABI v1

**Authority:** [RiscRTE Platform](RISCRTE_PLATFORM_SPEC.md), [hardware-agnostic ownership](HARDWARE_AGNOSTIC_DRIVER_BOUNDARY.md) and [runtime drivers](RUNTIME_DRIVER_ARCHITECTURE.md). This document distinguishes the production contract from the experimental implementation in draft PR #78.

## 1. Hardware ownership and ABI

The CPU/OS port supplies generic interrupts, tasks, queues, synchronization, bounded allocation, logging, libc and low-level CPU pin-matrix primitives to *authorized* independently loaded ELFs. It MUST NOT supply USB/I²C implementations, enumeration, transfers, charger commands, hardware-specific managers or fallback. The core treats capability IDs as opaque; it never branches on `usb`, `i2c` or board identifiers. Each provider ELF owns its entire physical driver, callbacks and teardown and may consume other provider capabilities.

This privileged ABI is separate from the application ABI. Its exact 46-symbol compatibility inventory is `lib/elf_loader/include/private/privileged_os_cpu_symbols_v1.def`. Strong references turn a missing symbol into a firmware link failure. `esp_rom_gpio_*` are CPU pin/pad routing primitives, not firmware GPIO-device implementations. None of these privileges are added to ordinary application exports, customer tables or registered ELF symbols. A future ABI may consolidate the compatibility inventory into a versioned structured port API.

## 2. Import inventory, exact declarations and resolution

`esp_elf_relocate_privileged_verified_v1` validates the image structurally, then calls `esp_elf_privileged_imports_valid_v1` **before** privileged scope or executable mapping. It examines undefined global/weak imports in **both** `.dynsym` (type 11 in the pinned loader) and `.symtab` (type 2), including tables with no relocations. It checks symbol/string bounds and rejects duplicate/missing dynamic tables, malformed names/offsets, REL format, invalid RELA links and out-of-range relocation symbol indices. Imports must come from the fixed libc compatibility snapshot or the exact 46-symbol OS/CPU inventory. Peripheral, firmware `t5_*`, customer and cross-ELF external imports are rejected.

`esp_elf_privileged_manifest_imports_match_v1` additionally requires a nonempty, strictly sorted, unique import declaration of at most 128 names, each 1–127 bytes. It checks *set equality* with all undefined imports across both symbol tables, rejecting undeclared but ABI-wide permitted names as well as missing, extra, duplicate, unsorted, malformed or forbidden names. `SpecV2 -> ModuleV2 -> esp_elf_relocate_privileged_verified_v1` carries this declaration; the private relocation entry enforces it on the digest-checked snapshot before scope/mapping. Host tests compile the actual C entry with a mocked relocator and verify denial before any mapping. **This is consistency checking of supplied declarations, not proof they were signed.** The graph's basic shape checks are not an authorization boundary.

**Process-global custom resolver bypass closed in PR #78:** `elf_find_sym()` now checks whether the current task owns the privileged relocation scope and, if it does, calls the restricted `elf_find_sym_default()` *directly*. It never consults `current_resolver` on that path. The fixed resolver returns only scoped generic OS/CPU or libc symbols, never IDF/customer/global registration or another loaded ELF's exports. On other tasks `elf_find_sym()` retains ordinary custom-resolver behavior and snapshots `current_resolver` under its existing lock. It does not globally swap resolver pointers or lock while invoking them. The regression extracts the **actual production `elf_find_sym()` function**, compiles it with simulated scope/custom callbacks and demonstrates that an installed malicious resolver cannot return `usb_host_install` during privilege, including after a resolver change; ordinary/non-owner lookup remains unchanged. No Xtensa ELF was executed by this host regression.

**Remaining module-context limitation:** privilege is currently scoped to the owning FreeRTOS *task*, not cryptographically to a particular ELF relocation invocation. A reentrant ordinary relocation on the same task could inherit scoped visibility unless the private loader prevents such nesting or introduces an explicit module-local resolver. Privileged scope itself disallows nested privileged acquisition, concurrent acquisition and wrong-task acquisition; this is not a native-code sandbox, and unrelated native code sharing firmware memory can still address pointers after execution. Close same-task reentrancy/serialization as part of authorized executor admission.

## 3. Authenticated bytes and package-manager handoff

Separate draft [Unified Package Manager PR #76](https://github.com/michaelrolphone-cmyk/T5S3-Reader/pull/76) implements experimental RISC-PKG signed-prefix P-256 verification, entry SHA-256, firmware-owned signer policy and an NVS-backed security-version floor. These branches are unmerged; normal installers remain unsigned, no production signer provisioning or authenticated provider receipt is connected, and the signed package manifest does not yet declare the provider ABI and exact imports. Do not duplicate cryptographic formats in PR #78.

A trusted intake must bind signer/scope, security version, architecture, package/provider identity, ABI, exact import names, dependencies, executable length, expected 32-byte digest and execution-context/resource authorization into one immutable manager-owned receipt. Its strings and arrays must remain valid until no graph activation is possible; arbitrary application pointers, unsigned JSON, manifest shape and self-declared digests confer **no authority**. `SpecV2` stores the authenticated digest **by value**, while `ModuleV2::loadVerifiedBytes` copies candidate bytes privately, hashes *that same copy*, compares against the authenticated expected digest and relocates only the matching snapshot. An SD replacement after trusted inspection is detected before mapping provided the digest itself came from a verified signer. An in-process malicious native task requires stronger memory isolation.

Installed, authenticated, admitted, mapped, activated and hardware-owned are distinct states. The experimental graph's privileged API must not become an unrestricted public intake surface.

## 4. Quiescence and exclusive physical ownership

Privileged providers must implement `quiesce()`. Failed start/teardown may leave IRQs, DMA, callbacks or hardware active: ELF remains mapped, new grants are denied and dependency providers stay pinned until quiescence. Successful quiescence must drain callbacks, stop DMA/tasks/timers, remove IRQs, disable its peripheral and prevent borrowed pointers into unmapped code. Graph claims alone cannot arbitrate against compiled legacy USB, charger or `Wire`. Exclusive controller/PHY/VBUS/I²C0 cutover and real electrical testing remain acceptance gates.

## 5. Verification and remaining acceptance (September 17, 2026)

[Experimental run 35267725026](https://github.com/michaelrolphone-cmyk/T5S3-Reader/actions/runs/35267725026) passed the exact-declaration tests, actual private relocation-entry host regression and physical USB/I²C PIC ELF builds/import audits. [Firmware run 35267724960](https://github.com/michaelrolphone-cmyk/T5S3-Reader/actions/runs/35267724960) passed both board builds and the general host suite **before** the latest custom-resolver edit. [One-time resolver run 35269205951](https://github.com/michaelrolphone-cmyk/T5S3-Reader/actions/runs/35269205951) patched the reviewed C source and passed the targeted real-function host test. Its temporary write-enabled workflow and patch script were deleted; the regression is now part of the permanent experimental test runner. Check the latest firmware and experimental workflows independently before claiming full current-head validation.

Still required: signed PR #76 ABI/import fields and immutable authenticated receipt-to-graph handoff; signer/identity/requirements/context/rollback mismatch tests; module-local privilege or same-task reentrancy denial; real physical USB/I²C ELF relocation/start/stop on a T5S3; exclusive legacy-owner cutover and VBUS/backfeed/current/role/rail tests; hub/replug/duplex and injected ISR/DMA teardown. Physical ELFs remain diagnostic, unpublished and noninstallable. Shipping USB/Serial Monitor, `Wire` and charger paths remain unchanged. A host/firmware build does not establish physical safety.
