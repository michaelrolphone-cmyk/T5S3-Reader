# U3 — T5 Pro hardware driver migration, bus cutover and UI-optional boot

**THIRD MILESTONE; SPECIFICATION ONLY.** Begins after accepted U2 and explicit owner direction, on one new implementation PR. Owner controls merge, release, flash and physical qualification. Governing documents: [four-milestone order](FOUR_MILESTONE_STREAM_FIRST_EXECUTION_ORDER.md), [I²C bus ELF cutover](I2C_BOOTSTRAP_CUTOVER.md), [SPI/UART ELF cutover](SPI_UART_ELF_BOOTSTRAP_CUTOVER.md), [UI-optional boundary](HEADLESS_RUNTIME_AND_CAMERA_SERVICE_BOUNDARY.md), [hardware boundary](HARDWARE_AGNOSTIC_DRIVER_BOUNDARY.md), [streams](STREAM_PIPE_MILESTONE_ALLOCATION.md), [driver architecture](RUNTIME_DRIVER_ARCHITECTURE.md), [U1](NEXT_HARDWARE_TEST_MILESTONE.md), [U2](NEXT_MILESTONE_INDEPENDENT_PACKAGE_ECOSYSTEM.md) and [U4](NEXT_MILESTONE_PROVISIONING_AND_ESP32_S3_CAM.md). Inspect real accepted firmware, Pro board revision/BOM/schematic, linked code and CAM flash/PSRAM/boot facts before determining fitted parts. Pin definitions alone are not hardware inventory.

## Required outcomes and exclusions

U3 must (1) migrate every verified T5 Pro board-added peripheral into a functional installed device/provider ELF, including both GPS apps off firmware-specific GPS bridges; (2) switch the **existing U1 I²C bus ELF's private backend** to exclusive native ELF controller ownership, and establish **SPI and physical UART bus ELFs with stable public interfaces before moving their device consumers**, then switch those bus ELFs' private backends to native ownership once clients are migrated; remove all three normal-runtime firmware bus APIs/imports without rewriting already-migrated peripheral interfaces; (3) leave graphical UI compiled into firmware but optional at runtime while boot, scheduler, manager and services work headlessly; (4) produce a compatible firmware image that boots the actual ESP32-S3-CAM driverless into stable observable recoverable idle. Camera provisioning/image capture are U4, not U3. Headless serial here means basic one-way diagnostic/recovery output, not an interactive shell.

CPU, integrated Wi-Fi/BLE, flash/PSRAM substrate, ROM and minimal on-chip boot/port primitives are excluded from *board-added peripheral* conversion. USB extraction belongs to U1. A verified boot module-store or ROM/recovery port path may remain isolated; it does not publish a normal bus capability, provide firmware fallback or contend with an ELF-owned controller. Do not implement new hardware families, a GUI ELF, provisioning or CAM sensor drivers.

## Actual fitted device inventory

At kickoff classify each source/schematic candidate `PRESENT`, `VARIANT-DEPENDENT`, `ABSENT` or `UNCONFIRMED`, then record verified ELF owner, bus dependency, profile/pin/power, consumer, safe absence and evidence. Evaluate ED047TC1 e-paper (`display.*`, scan/waveforms/full/partial refresh, SPI/parallel/pin/power and bounded frames); TPS65185 and PCA9535 (power/expander ELFs via `i2c.bus`, HV/VCOM/rail safety); GT911 touch (`input.touch` via `i2c.bus`, IRQ/calibration/records); SX1262 LoRa (`radio.lora` via `spi.bus` where fitted, IRQ/BUSY/reset/atomic packets/no TX on boot); GNSS receiver (`location.*` via `uart.port` and applicable power); BQ25896/BQ27220 charger/gauge (`i2c.bus`, safe defaults and telemetry); PCF85063 RTC (`i2c.bus`, alarm/wake); PCA9535 buttons/controls (single register owner); SD media (`spi.bus` where verified, runtime storage ELF with separate minimal module-store bootstrap); other demonstrably fitted hardware only. Candidate I²C addresses from `lib/Board_T5S3/pin.hpp`: GT911 `0x5D`, PCF85063 `0x51`, TPS65185 `0x68`, PCA9535 `0x20`, BQ25896 `0x6B`, BQ27220 `0x55`. Validate board revision, shared SD/LoRa/EPD pad mux, rail/pin/clock dependencies, IRQ and DMA. SPI mutex alone does not solve shared pad ownership.

Device ELFs own device register/protocol I/O, probe/matching, power policy, hardware operation and teardown. **Only bus ELFs** own public bus mediation and may temporarily delegate bounded raw controller work to their matching firmware port APIs; power, LoRa, display, SD, GNSS, touch and other peripheral ELFs cannot import those private APIs. When a bus ELF or device ELF is absent, its capabilities disappear; no compiled fallback. On uncertain quiescence pin/quarantine code rather than call unmapped handlers. Preserve one `.rte.zip` per package and U2 identity/version/source/role rules; Pro `system-core` packages are not universally required on CAM.

Consumers use U1 generic bounded data paths: atomic LoRa packet records, GNSS byte/position records, touch events, battery telemetry, SD byte streams, and display surface/frame API with bounded chunks or owned DMA-safe buffers. Do not force a full e-paper frame into a 512-byte record or retain DMA/ELF pointers beyond ownership. Follow [bounded cooperative operations](COOPERATIVE_BOUNDED_OPERATIONS.md): finite I/O/retry/time/queue/memory limits, real yields, progress and recovery. No optional transforms except genuine dependencies.

## Bus migration: stable provider interfaces, private backend replacement

Follow [I²C](I2C_BOOTSTRAP_CUTOVER.md) and [SPI/UART](SPI_UART_ELF_BOOTSTRAP_CUTOVER.md). Inventory physical controllers, consumers, bus boot power, clock, pins, shared SD module-store, and diagnostic UART/ROM console ownership. The U1-installed I²C ELF already publishes `i2c.bus`, alone imports temporary firmware I²C and supplies power/expander/USB. **Do not migrate these consumers a second time.** Move remaining I²C device ELFs to that unchanged capability. Before converting display/LoRa/SD and GNSS/other UART devices, install separately managed SPI and hardware-UART bus/provider ELFs exposing versioned `spi.bus`/`uart.port` (or compatible existing contracts); peripheral ELFs depend on their provider capability rather than `SPI`, `HardwareSerial`, firmware GPS I/O or raw temporary symbols. Their ELFs may initially import limited firmware controller setup/transfers privately. USB CDC `serial.port` is distinct from MCU hardware UART. If applicable controller already natively owned in an ELF, preserve it rather than add a needless proxy.

Check for dependency cycles before activating a bus: a bus ELF must not require a power/expander device that itself cannot start without that bus, absent an independent verified bootstrap. I²C, SPI and UART providers must own client admission/rights, per-instance arbitration, bounded transactions and lifecycle even during delegation. SPI provider mediates clock/mode/order/CS, atomic transactions, pad mux and DMA. UART provider mediates actual hardware port instance, RX/TX streams, baud/framing/flow control where supported, buffered errors and safe close. A minimal ROM/boot serial diagnostic may be reserved only with explicitly exclusive pins/controller or released before normal ELF operation; it is not a production `uart.port` fallback.

**Per physical controller handoff:** block new admissions, quiesce consumers, drain/cancel bounded I/O, revoke old-generation handles, set safe pins/rails, release and deinitialize the temporary firmware backend, and exclusively initialize the **same bus ELF's internal native backend** for controller setup/transfer/arbitration/recovery/teardown using appropriate CPU/RTOS primitives. Rebind clients through the **unchanged public capability** with fresh handles; use additive versioned API evolution only when necessary. Never run two owners concurrently or silently restart the firmware adapter after ELF failure. Remove normal-runtime firmware bus implementations, imports and permission grants after cutover, auditing linked firmware and every ELF dependency. A strictly necessary isolated boot-module-store/ROM/recovery path must not service installed drivers or retain the same hardware while ELF owns it. **U3 Work Complete requires native controller ownership for all three normal-runtime bus families actually used, no transitional firmware entry points/imports, and earlier peripheral ELF compatibility without a second interface rewrite.** Check separate controller instances individually; report any unavailable physical evidence honestly.

## GNSS: complete driver-to-app conversion

**Verified master baseline at September 18, 2026:** `Drivers/gps_nmea/driver.c` implements NMEA/fix/baud but imports `t5_kernel_io_v1` for UART/power; its manifest requires `kernel.serial`, `kernel.power`, `kernel.clock` and provides `position.gnss`. `GpsKernelIo.cpp` directly controls T5 board-specific GPS UART/pins/`RadioPower`; `GpsDriverRuntime.cpp` names `gps-nmea`, starts/polls and publishes `location.fix.v1` through native GNSS bridges; `NativeGpsBridge.cpp` exposes `T5GpsApi`, `NativeLocationBridge.cpp` calls the runtime. `Apps/gps.c` calls `t5_gps_get_api()`/start/read/stop; `Apps/gnss_stream_diagnostic.c` reads location records but hard-codes `gps-nmea`/UART and `location->poll`. These are real existing components, not evidence that the ELF or streams are absent.

Move GNSS receiver protocol, UART/receiver configuration, GPS pins and shared GPS/LoRa rail handling to actual driver/provider ELFs using the installed hardware-UART bus ELF and separate applicable power capability. Reuse NMEA/parser/record schema. GNSS ELF publishes semantic `location.position` and versioned `location.fix.v1` via U1's common registry/permissioned streams, driven by bounded resident provider work independent of app UI or forced poll. Convert **both** GPS and diagnostic apps to resolve location by semantic capability, authorize/subscribe/read streams, render fixes and diagnostics, preserve denial/revocation/backpressure, and bump each modified app version. No updated app may hard-code `gps-nmea`, call `T5GpsApi` or force `location->poll`. Remove/reduce `GpsKernelIo.cpp`, `GpsDriverRuntime.cpp`, `NativeGpsBridge.cpp`, `NativeLocationBridge.cpp` and GNSS-specific stream bridge to genuinely generic port/registry/ABI functionality. No firmware GPS UART/power/source startup/poll/fix publication or silent fallback; strictly versioned adapter only for unrelated legacy app compatibility, never a hardware owner. Test absent/uninstalled provider, two contexts where supported, denied/revoked rights, stream loss/backpressure, update/unload, safe rail/UART release and compatible alternative location provider. Hardware evidence belongs to owner qualification.

**GNSS acceptance:** both apps consume real observations from installed GNSS ELF through authorized semantic streams and bus/power providers, no firmware GPS dispatch, provider-ID coupling or app-driven receiver polling.

## UI optional, not a GUI ELF

Boot CPU/port and minimal recovery/module store → inventory/profile → generic scheduler/providers/services → GUI initialization **only if** profile requests and usable `display.*` exists. Scenes/navigation/render/Settings may remain in firmware as consumers of driver display/input capabilities, not owners of panel/touch. Missing display, touch, fonts or UI cannot prevent boot, services, recovery, idle, sleep or diagnostics. Headless profiles allocate no EPD framebuffer/fonts, do not poll render/ActivityManager and need no interactive console. Pro retains a working GUI; scheduler progress is independent of foreground app polling.

## Driverless ESP32-S3-CAM

Actual CAM boots compatible firmware with zero Pro/CAM peripheral packages, no screen/touch/Pro power/LoRa/RTC/gauge/optional SD/GUI/camera/provisioning. Missing capabilities fail safely rather than crash, watchdog loop or retry nonexistent SD forever. Preserve minimal boot/recovery without claiming normal storage. One-way ROM/port serial status suffices where supported, with no production UART bus fallback or concurrent UART ownership. Stable idle and recovery are success. Validate bootloader/partition/flash/PSRAM/pins; prefer same binary if feasible or minimal documented port differences with identical hardware-blind runtime. Do not initialize retired T5 I²C/SPI/UART temporary runtime adapters on CAM.
