## Required outcomes and exclusions

U3 must (1) migrate verified T5 Pro board-added peripherals into functional installed ELFs and both GPS apps off GPS-specific firmware bridges, with single register/rail owners; (2) switch U1 I²C bus ELF's private backend to exclusive native controller ownership, install stable SPI and physical UART bus ELFs before consumers, switch to native backends, and retire normal firmware I²C/SPI/UART APIs without rewriting consumers; (3) audit and migrate **active SoC-integrated Wi-Fi hardware and connection policy** still in compiled `Esp32NetworkProvider.cpp` to provider-owned implementation, with only narrowly justified minimal CPU/OS/boot-recovery port primitives remaining, preserving U1 network/package behavior; (4) keep compiled GUI optional while generic boot/scheduler/manager/services operate headlessly; (5) provide CAM-compatible firmware booting driverless into recoverable idle. CAM provisioning/capture are U4. One-way headless serial means diagnostics, not a required shell.

CPU, flash/PSRAM substrate, ROM and minimal on-chip CPU/OS/boot/port primitives remain outside board-added conversion. **Integrated Wi-Fi/BLE are not board-added devices; nevertheless an *active* Wi-Fi hardware driver/policy implementation does not qualify as hardware-blind framework simply because the radio is integrated. Its U3 boundary audit and provider cutover are explicit work.** Do not invent unused BLE hardware work; classify only used hardware. Any genuinely unavoidable firmware port operations must be bounded, generic, documented and isolated from normal Wi-Fi/device policy; do not label an entire Wi-Fi driver a port primitive. USB extraction is U1. Verified boot module-store/ROM/recovery paths stay isolated and cannot publish a normal bus capability, serve as fallback or contend with ELF-owned hardware. No new hardware families, GUI ELF, provisioning, interactive shell or CAM sensor drivers.

## Shared-chip, power and rail graph — completion requirement

Follow [shared ownership](SHARED_CHIP_AND_RAIL_OWNERSHIP.md). One PCA owner claims `0x20`, maintains both-bank shadows/configuration and interrupt fan-out, performs atomic masked output changes and grants disjoint output masks or read/event rights. EPD control cannot overwrite IO00, button direction or another pin. Bad writes, colliding masks and failed unload fail safe. U1 BQ owner continues OTG/charger arbitration; no U3 replacement BQ chip owner or firmware writer.

One TPS ELF claims `0x68` and owns all register/fault/HV/VCOM behavior. One EPD power sequencer owns ordering/timing/shutdown using scoped TPS and PCA grants; display leases sequence, never accesses registers directly. Source-derived wiring and measured safe timing are prerequisites for exact profile. BQ VBUS and TPS EPD-HV share `i2c.bus` but do not depend on each other without schematic evidence; do not pull TPS/EPD into U1 merely because USB uses BQ.

GNSS/LoRa shared rail: one policy owner (or PCA owner with separately leased capability) exclusively holds IO00. First lease enables verified rail, further leases retain it, and one client release cannot shut off the other. Last release powers down only after safe quiescence; uncertain state retains ownership/quarantine and emits fault, never claims OFF. Owner loss revokes clients. Test both activation orders, concurrent clients, missing rail, one crash and failed shutdown. Rail power never authorizes LoRa transmission. Verify separate resets/domains.

Draw `bus → chip owners → rail/EPD sequencers → GNSS/LoRa/display → apps` and `I²C → BQ VBUS → USB host`, with no dependency cycle or silent firmware chip fallback. Prevent removal/update of a shared owner with live or uncertain dependents. Generic core manages opaque grants/generations/pins, never board register maps.

## Bus migration: stable interfaces, private backend replacement

Follow [I²C](I2C_BOOTSTRAP_CUTOVER.md) and [SPI/UART](SPI_UART_ELF_BOOTSTRAP_CUTOVER.md). Inventory physical instances, power, pins, module store, console and DMA. U1's installed `i2c.bus` ELF alone imports firmware I²C and supplies the BQ VBUS branch and any verified U1 PCA prerequisite; **do not re-migrate U1 chip owners**, add consumers to their established capabilities. Before display/LoRa/SD or GNSS conversion, install stable `spi.bus` and `uart.port` provider ELFs; temporary raw firmware backend may be private to matching bus ELF only. USB CDC `serial.port` is not physical UART.

Ensure noncyclic startup; bus ELFs manage rights/arbitration/bounds/lifetime. SPI mediates mode/CS/pad mux/DMA; UART RX/TX, framing, errors and safe close. ROM/boot console requires exclusive resource or verified release/handoff and is not production `uart.port` fallback. At takeover: block admissions, quiesce, drain/cancel, revoke generations, safe-state pins/rails, release/deinitialize firmware backend, initialize **same bus ELF's** native backend exclusively, rebind via unchanged public ABI. No overlapping controllers or silent fallback. Remove normal-runtime I²C/SPI/UART firmware imports after cutover and isolate only proven boot/recovery. U3 Work Complete requires native controllers for used normal bus families, earlier-client compatibility and multi-client chip/rail arbitration.

Use U1 bounded paths: atomic LoRa packets, GNSS bytes/position, touch events, telemetry, SD streams and display owned frames/chunks (not a full frame in a 512-byte record). No retained stale DMA/ELF pointers; time/retry/queue/memory limits and real yield per [bounded operations](COOPERATIVE_BOUNDED_OPERATIONS.md). Preserve ZIP/identity/U2 sources/profile roles. Pro core packages are not universal CAM dependencies.

## GNSS: driver-to-app conversion

**Source baseline September 18, 2026:** `Drivers/gps_nmea/driver.c` implements NMEA but imports `t5_kernel_io_v1` for UART/power; `GpsKernelIo.cpp` directly opens board UART/pins/`RadioPower`, `GpsDriverRuntime.cpp` selects `gps-nmea` and polls/publishes, `NativeGpsBridge.cpp` exposes `T5GpsApi`, `NativeLocationBridge.cpp` calls runtime. `Apps/gps.c` calls GPS compatibility API; `Apps/gnss_stream_diagnostic.c` hard-codes `gps-nmea`/UART and triggers `location->poll`. Recheck current U3 baseline; this is a historical migration inventory, not proof no one has modified it.

GNSS ELF consumes installed physical UART plus `board.power.radio` (no direct `RadioPower`), owns receiver commands/parser and publishes semantic `location.position`/versioned `location.fix.v1` on resident bounded work without app polling. Both apps resolve semantic capabilities, authorize/subscribe/read and render, preserve denial/revocation/backpressure and bump versions. Remove `gps-nmea` ID hard-codes, `T5GpsApi` in updated apps and poll-driven source. Retire/reduce `GpsKernelIo.cpp`, `GpsDriverRuntime.cpp`, `NativeGpsBridge.cpp`, `NativeLocationBridge.cpp` and GNSS-specific firmware streams to genuinely generic/strict legacy compatibility with no firmware hardware owner. Test missing/alternate provider, two contexts, denial/revocation, backpressure, update/unload and LoRa-active GNSS rail release. Owner qualifies physical hardware separately.
