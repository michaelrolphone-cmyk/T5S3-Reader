# USB ELF migration: implementation status and acceptance

**Authority:** [RiscRTE master specification](RISCRTE_PLATFORM_SPEC.md), [hardware-agnostic driver boundary](HARDWARE_AGNOSTIC_DRIVER_BOUNDARY.md), [runtime driver architecture](RUNTIME_DRIVER_ARCHITECTURE.md), and [USB architecture](USB_OTG_HOST_ARCHITECTURE.md). This is an implementation snapshot, NOT a waiver of hardware acceptance. **Shipping firmware still operates legacy USB, Wire and charger control; none of the experimental ELFs is installable or published.**

## Independently implemented provider chain

```text
CDC ACM / CP210x ELFs -> serial.port@1 -> USB host ELF
USB host ELF -> requires usb.controller@1 -> ESP32-S3 USB controller ELF
USB controller -> requires board.power.vbus@1 -> T5S3 BQ25896 power ELF
Board power -> requires i2c.bus@1 -> ESP32-S3 physical I2C controller ELF
           `-> requires platform.clock@1 -> generic clock provider ELF
```

The compiled RiscRTE core has not acquired USB or I2C forwarding functions. All device-specific behaviors shown here are implemented in independent ELFs; the provider graph and loader are not integrated with production signed package verification, execution-context authorization or the running application path. No driver is being loaded or installed on a physical T5S3.

`Drivers/usb_cdc_v2` implements CDC IAD/union/alternate descriptor matching, claims, line coding, DTR/RTS, bulk I/O and stale-session rejection; its open API does not support qualified selection of ambiguous CDC composite functions. `Drivers/usb_cp210x_v2` implements chipset UART enable, baud, line/modem controls and bulk paths; vendor VID-only matching needs real PID/profile qualification. Both are independent `serial.port@1` ELFs consuming `usb.host@1`.

`Drivers/usb_host_v2` is a separate provider consuming `usb.controller@1`, owning discovery, generation-qualified device/claim handles, exclusive interface/alternate/endpoint verification and fail-closed disconnect/teardown. Its discovery observations are not yet forwarded through a serialized provider executor into the transport-neutral Unified Device Registry.

`Drivers/usb_controller_esp32s3/driver.cpp` is a **physical USB/OTG driver**, performing actual IDF client, device, interface, PHY, interrupt, control/bulk/DMA and teardown operations. `scripts/probe_usb_controller_esp32s3.py` compiles pinned ESP-IDF v4.4.7 USB/PHY/HAL/SoC code as PIC and links it INSIDE the controller ELF. SoC MMIO, GPIO mux and dedicated internal PHY pad drive are provider-owned, not firmware USB proxies. This ELF still fails actual loader import compatibility and awaits physical DMA/role/teardown verification.

`Drivers/board_power_t5s3_v2/driver.c` actually programs BQ25896 charger/boost registers through an exclusive I2C 7-bit address claim (0x6B) and a generic `platform.clock@1` dependency. Its preflight rejects external VBUS and OTG conflicts, bounds the requested current at 500 mA, snapshots REG02/03/0A, enables voltage ADC, checks OTG status/rail voltage/faults, restores original ADC/charger/boost configuration and retains its lease if source-off or readback cannot be verified. BQ25896 REG11 `VBUS_GD` can read zero during successful OTG; the implementation uses measured voltage instead. **Clock failure is a fail-closed condition:** startup rejects a nonfunctional monotonic clock before writing power registers; source and shutdown deadlines reject the `UINT64_MAX` clock-failure sentinel, retaining the lease and blocking unload if shutdown cannot be verified. The clock-loss/recovery tests exercise this behavior. Host fault tests cannot verify board thermal, actual rail sourcing or reverse-current protection.

**`Drivers/i2c_esp32s3_v2/driver.c` implements actual physical I2C0, not a proxy to compiled `Wire`:** ESP32-S3 pins SDA39/SCL40, IDF install/configure, atomic repeated-START reads, independent write/read, bounded timeouts/data, exclusive claims per 7-bit address, never-reused claim tokens and hardware-backed `i2c_driver_delete` at quiescence. `scripts/probe_i2c_esp32s3_v2.py` compiles IDF I2C driver, GPIO, peripheral controller, I2C HAL, ISR-only `i2c_hal_iram.c`, GPIO HAL and pinned SoC data as PIC within this ELF. Per-function/data section elimination discards unrelated RTC GPIO code; a pinned MMIO map and import audit fail on remaining resident I2C/GPIO/RTC driver implementation. This provider cannot start while resident firmware `Wire` owns the same I2C0 registers. Internal address claims alone cannot arbitrate against compiled hardware owners.

**`Drivers/platform_clock_v1/driver.c` is a real independent `platform.clock@1` provider ELF.** It uses only the existing native ELF libc imports `clock_gettime(CLOCK_MONOTONIC)` and `usleep`, implements bounded scheduler-backed sleep, startup checks and a `UINT64_MAX` clock failure sentinel. It has no hardware-specific firmware proxy and requires no other provider. Its separate Xtensa build checks exactly those two existing libc imports and the generic `t5_driver_get` export. Xtensa binutils 2.35 initially appended two trailing `R_XTENSA_NONE` records and caused the unchanged native structural validator to reject the ELF. `scripts/normalize_xtensa_relocations.py` fails closed on unexpected layouts and excludes only trailing all-zero no-op relocation slots by adjusting `.rela.dyn` section size and matching `DT_RELASZ`, without rewriting real relocations or relaxing the validator. The post-normalization audit and native structural tests passed [experimental CI 35254356715](https://github.com/michaelrolphone-cmyk/T5S3-Reader/actions/runs/35254356715). Clock quiescence still depends on a serialized provider executor and its actual native `dlopen` activation is not integrated.

Generic `ProviderModuleV2`/`ProviderGraphV2` handle identity/version/dependency verification against caller-prevalidated specs, competing provider resolution, cycle detection, pins, quiescence and fail-closed unloading. `test/run_vbus_provider_chain_v2_test.sh` uses this REAL graph and three independent Linux shared objects: actual clock ELF source, actual BQ25896 source, and **test-only simulated** I2C registers. The test covers dependency startup, source lease, invalid release, teardown and missing clock/I2C fail-closed activation. It does NOT exercise electrical hardware or actual Xtensa loader invocation. **Provider lifecycle recovery is implemented:** if start acquires resources but fails, the failed ELF and its dependency providers remain pinned; subsequent generic shutdown retries quiescence before stopping and unmapping. If an active ELF fails teardown, its capability is withdrawn, new grants are refused, and its code and dependencies stay pinned until verified quiescence. Tests use actual host `dlopen`/`dlclose`, repeated failed recovery, repair, stale-grant rejection, and state reset after reload. Production trusted manifests, invocation rights/consent, provider executor, registry, streams and package lifecycle are NOT integrated.

## Verified implementation tests versus hardware acceptance

Host tests exercise CDC/CP210x and host algorithms through test-only simulated hardware, plus real generic provider graph lifetimes and 3-ELF power composition. Power tests fault-inject BQ25896 late NACK, source rise failure, current/power conflicts, restore/readback errors, clock loss and teardown retries. I2C tests execute actual provider source with instrumented IDF calls and check repeated START, bounds, exclusive address claims, stale-generation token rejection, transaction errors and failed hardware delete retry. Clock tests inject OS time failure, invalid timestamps and verify bounded sleeps. None proves actual board current/voltage correctness.

[Experimental CI 35257460352](https://github.com/michaelrolphone-cmyk/T5S3-Reader/actions/runs/35257460352) **passed the expanded failed-start/failed-teardown recovery tests, three-ELF integration, both PIC physical-controller builds, independent Xtensa ELF builds, and loader structural checks**. USB controller: 590 supported relocations, zero unsupported/text relocations, no unauthorized USB or firmware imports, but **36 OS/CPU/RTOS/interrupt/memory/log/ROM symbols absent from the actual loader export set**. I2C controller: **216 supported relocations, zero unsupported/text relocations or unexpected exports, no hardware peripheral imports, but 29 missing OS/CPU imports**. Both remain `loader-abi-blocked` and non-installable. Exact JSON reports are retained in inspection-only CI artifacts, never public releases or the catalog. The full firmware CI for the code change was still running when this status was written.

## Required before production migration

1. Build a narrow, versioned, verified-provider-only **generic OS/CPU ABI**; resolve 36 USB plus 29 I2C unavailable symbols through authorized loader scopes, not unrestricted RTOS/interrupt symbol exports to ordinary apps. Prove actual dynamic symbol binding, ISR/task/DMA callback lifetimes, bounded drain and recovery. Do not put USB or I2C implementations back in compiled firmware.
2. Prove physical ownership: exclusive I2C0 vs existing `Wire`, charger vs existing board logic, OTG/PHY vs existing firmware debug/host usage. Implement and verify generic resource arbitration and actual legacy-to-provider cutover; an ELF's internal claim bookkeeping cannot exclude resident hardware drivers. Verify board power, VBUS/backfeed/thermal constraints, cancellation and teardown.
3. Integrate signed verified manifests, execution-context grants, serialized provider executor, generic device publication/observation, bounded streams, install/remove, qualified chipset selection and remaining CH34x. Keep experimental artifacts out of the install catalog.
4. On actual T5S3, verify cold boot, attach/hubs/multiple devices/replug, unplug during transfers, CDC/CP210x line settings and sustained duplex, charger boost and role safety, DMA/interrupt/callback teardown and no hidden firmware fallback. Only AFTER parity switch Serial Monitor and remove normal-runtime `NativeUsbBridge`, `UsbCdcDriverRuntime`, chipset code and USB-specific projections; recovery bootstrap is separately isolated.

**Status:** Draft PR #78 contains physical USB and I2C, BQ25896 power, generic clock, host, CDC and CP210x provider ELFs and recoverable generic provider lifetime management. Generic privileged port/loading, exclusive hardware ownership and physical acceptance remain incomplete. Shipping behavior is unchanged.
