# USB migration: implementation status and acceptance

**Authority:** [RiscRTE master specification](RISCRTE_PLATFORM_SPEC.md), [hardware-agnostic driver boundary](HARDWARE_AGNOSTIC_DRIVER_BOUNDARY.md), [runtime driver architecture](RUNTIME_DRIVER_ARCHITECTURE.md), and [USB architecture](USB_OTG_HOST_ARCHITECTURE.md). This file records implementation state; target contracts take precedence.

## Implemented experimental code — not shipped

`Drivers/usb_cdc_v2/driver.c` is an independently built ELF containing actual CDC class behavior rather than a descriptor-only firmware proxy. Its ABI-v2 manifest requires `usb.host@1` and provides `serial.port@1`. Within the ELF it parses descriptors, claims/releases host-provider interfaces, configures line coding/DTR/RTS, performs bulk RX/TX, manages bounded sessions and rejects stale session tokens. It accesses hardware only through the `usb.host` interface supplied by another ELF. No firmware USB bridge or `kernel.usb.host` is imported.

`RiscProviderV2.h` defines a hardware-blind root ABI and generic dependency interface; `RiscUsbProviderV1.h` defines USB-specific operations for provider ELFs only. `ProviderModuleV2` loads a preverified ELF, validates exported identity/capability/version, injects supplied dependencies, pins consumers, invokes stop before unload and refuses unload while pinned.

**Continuation in this PR:** `ProviderGraphV2.{h,cpp}` now accepts bounded, externally validated provider manifest descriptors, resolves their exact capability/API dependencies recursively, detects missing providers and cycles, loads dependencies before consumers, pins provider modules for their dependents, rolls back failed activation, refuses ambiguous duplicate capability/version offers, and uses generation-qualified consumer grants. Releasing the last consumer unloads the provider and then its orphaned dependencies in reverse order. An unsuccessful ELF unmap retains dependent pins rather than leaving borrowed interface tables dangling. This is generic code containing no USB-specific provider branches. This graph is not yet wired into the production manifest scanner, authorization framework, or unified registry; the descriptors are currently passed directly by tests. The caller must separately validate manifest integrity, trust, paths and consumer rights, and serialize provider operations.

`test/run_provider_graph_v2_test.sh` exercises real dynamically loaded generic fixture ELFs for dependency ordering, shared-provider lifetime, cycle/missing/version rejection, stale grants, bounded consumer slots and rollback. `test/run_usb_provider_stack_v2_test.sh` loads **two separate ELFs** through the same generic graph: the real CDC provider and a *mock* `usb.host` ELF. It verifies CDC class transactions, RX/TX and host dependency lifetime. This mock is a host-test fixture only; it does not implement the ESP32 USB peripheral and must never be published as a driver. Both tests run from `test/run_usb_cdc_v2_test.sh`, which is included in existing CI and the dedicated experimental workflow. `scripts/build_usb_cdc_v2.py` separately builds/validates an Xtensa ELF under `dist/experimental/` without publishing it or changing normal firmware. CI results must be evaluated at the final commit; host passing is not board validation.

## Blocking work before this driver can run on a board

1. Implement an actual installable **`usb.host` controller ELF** owning ESP32 controller/OTG and board-power dependencies, host initialization/teardown, enumeration/hub/topology, device-generation state, interface claims, transfers, callbacks, hotplug and recovery. It cannot just call the existing compiled `NativeUsbBridge`, a privileged firmware USB proxy or a built-in USB manager. ESP-IDF USB host code and its dependencies must be evaluated for relocation into the ELF and correct DMA/ISR/task lifetime before enabling on hardware.
2. Wire the generic provider graph to independently verified installed manifests, package trust, the shared hardware-blind registry, provider-originated discovery and invocation-scoped authorization. Pin lower providers for all active sessions and revoke grants before unloading. Resolve by manifest `requires`/`provides` without type-specific core switches. The current graph is a tested module-lifetime building block, not the complete production integration.
3. Connect existing `serial.port` consumers and bounded byte streams to the CDC ELF, with exact caller consent, serialized I/O, loss/replug generation changes and safe cancellation. Once functional parity and physical acceptance are established, remove `NativeUsbBridge`, `UsbCdcDriverRuntime`, `UsbSerialProjection`, compiled USB enumeration, chipset branches and silent resident CDC/CP210x/CH34x fallback from normal firmware.
4. Extend CDC parsing for composite devices with multiple functions, IAD/union associations and nonzero data alternates. Specify fault-aware, verifiable hardware quiescence: an unload cannot assume that a void stop or unchecked interface release proves DMA, callbacks, tasks and VBUS are safe. Test failure injection, stale claims and disconnect while transfer is active.
5. Validate install/uninstall capability disappearance, no resident fallback, hub/multiple devices, first boot, VBUS, detach/replug, multiple line codings, sustained duplex, cancellation and cleanup on real T5S3 hardware. Host tests and firmware builds alone cannot meet these acceptance gates.

**Do not advertise this PR as fixing current USB hardware or completing USB modularity.** Shipping USB firmware and Serial Monitor remain unchanged. The real host-controller ELF, full runtime integration and physical tests are outstanding.
