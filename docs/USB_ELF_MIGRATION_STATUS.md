# USB ELF migration: implementation status and acceptance

**Authority:** [RiscRTE master specification](RISCRTE_PLATFORM_SPEC.md), [hardware-agnostic driver boundary](HARDWARE_AGNOSTIC_DRIVER_BOUNDARY.md), [runtime driver architecture](RUNTIME_DRIVER_ARCHITECTURE.md), and [USB architecture](USB_OTG_HOST_ARCHITECTURE.md). Implementation snapshot, not relaxed acceptance criteria. **Shipping firmware still owns the legacy USB path. Do not install experimental ELFs on a board.**

## Independently implemented experimental provider stack

```text
CDC ACM / CP210x ELFs ----serial.port@1--> USB host ELF
USB host ELF -------------usb.controller@1-> ESP32-S3 controller ELF
ESP32-S3 controller ELF --board.power.vbus@1-> T5S3 BQ25896 power ELF
T5S3 power ELF ----------i2c.bus@1-------> independently installed I2C bus ELF (NOT YET IMPLEMENTED)
              `----------platform.clock@1-> generic clock/RTOS port (NOT YET INTEGRATED)
```

- `Drivers/usb_cdc_v2` implements CDC descriptor matching (IAD/union and alternate settings), control/data claims, baud/line coding, DTR/RTS, bulk I/O, session and teardown handling. Selection among ambiguous multiple CDC functions is not implemented by its existing `open(device)` interface.
- `Drivers/usb_cp210x_v2` implements chip-specific UART enable/disable, baud, format, modem controls and bulk I/O; its VID-only matching must be narrowed to validated PID/profiles. Each class exposes its own `serial.port@1` provider and consumes `usb.host@1` from a separate ELF.
- `Drivers/usb_host_v2` implements device discovery and generation-qualified tokens, exclusive interface claims, alternate/endpoint descriptor validation, endpoint direction checks, stale-detach rejection, fail-closed release and quiescence. It requires `usb.controller@1`; `poll()`/`devices()` are provider-level facilities, not yet published into the generic Unified Device Registry or scheduled by the provider executor.
- `Drivers/usb_controller_esp32s3/driver.cpp` contains **actual ESP32-S3 USB host hardware implementation** calling ESP-IDF host/client/device/claim/control/bulk/DMA functions. `scripts/probe_usb_controller_esp32s3.py` compiles pinned IDF v4.4.7 USB/PHY/HAL/SoC source as PIC and links those implementations INSIDE the controller ELF. Physical MMIO addresses and GPIO mux definitions are resolved within the driver; `phy_gpio.c` implements only USB-pad drive strength. No added compiled firmware USB forwarding entry points.
- **`Drivers/board_power_t5s3_v2/driver.c` now contains an actual independent BQ25896 charger/VBUS driver ELF source**, not a proxy for `BoardT5S3`, `Wire` or compiled `NativeUsbBridge`. It requires independently supplied exclusive `i2c.bus@1` and hardware-neutral `platform.clock@1` capabilities (`RiscI2cBusV1.h`, `RiscPlatformClockV1.h`). It claims the board's BQ25896 at address 0x6b, refuses external VBUS/OTG or requests over 500 mA, saves charger/ADC/boost configuration, programs 500 mA OTG boost, enables ADC sampling, verifies OTG mode, measured VBUS >=4.4 V and no boost fault, and restores registers on release. A failed I2C write may have applied: rollback is verified and any uncertain rail state retains a lease and prevents unmapping. Quiescence releases the I2C device claim before unload and retains the module when bus release fails. The generic graph must pin both lower dependencies during all operations. This is implementation code, **not hardware-tested or installable yet**.

  Important chip detail: [TI's BQ25896 support discussion](https://e2e.ti.com/support/power-management-group/power-management/f/power-management-forum/749326/bq25896-detect-usb-source-with-otg-enabled) reports that REG11 `VBUS_GD` can remain zero while sourcing in OTG. The power ELF correctly relies on REG0B OTG mode, an enabled REG11 voltage ADC and REG0C boost-fault state to confirm sourcing, rather than requiring `VBUS_GD=1`. It restores the original ADC enable state on release. Actual current capability, battery/thermal behavior, board VBUS topology, and backfeed safety still require on-board verification.

`RiscProviderV2.h`, `ProviderModuleV2` and `ProviderGraphV2` implement generic preverified identities, exact versioned dependency resolution, competing provider choice, consumer pins and fail-closed quiescence. They are not yet production-wired to signature/manifest validation, installer/catalog, execution contexts, rights/consent, registry, streams or serialized provider execution. Current tests serialize calls and supply trusted, immutable manifest metadata.

## Verification and limitations

CDC/CP210x/host tests cover descriptors, class requests, bulk paths, device generations, duplicate claims, stale sessions and graph quiescence. `test/run_usb_three_elf_stack_v2_test.sh` loads the REAL host and CDC ELFs plus a TEST-ONLY simulated controller: this checks capability interfaces but cannot prove physical USB functionality. The simulated controller never enters a release package.

The ESP32-S3 controller's PIC cross-link, structural ELF validation, relocation and symbol audit passed [experimental CI run 35247590112](https://github.com/michaelrolphone-cmyk/T5S3-Reader/actions/runs/35247590112). All 590 examined relocations were allowed; zero unsupported/text relocations or forbidden USB/firmware API imports were found. Its `controller-loader-audit.json` still records **36 imports absent from the shipping firmware's loader export table**, after 43 initially, then 37 with SoC MMIO/mux included, then 36 with USB pad drive included. These imports concern generic FreeRTOS/CPU, interrupt, allocator, ROM GPIO, log and assertion functions. The controller ELF is therefore **not loadable under the current firmware ABI**, irrespective of compile/link success.

`test/run_board_power_t5s3_v2_test.sh` exercises the actual power-driver C source against an instrumented register-accurate *I2C mock*, including external VBUS conflict, 500 mA limit, ADC-off-to-on sequencing (with VBUS_GD remaining zero in OTG), charger state restoration, fault/voltage timeout, late-NACK rollback, stale leases, failed I2C release and retry. `scripts/build_board_power_t5s3_v2.py` cross-builds an unpublished Xtensa ELF and checks actual current loader imports and native ELF structure. Check the exact HEAD's CI results before reporting verification; host I2C mocks cannot establish electrical safety. `dist/experimental` packages are inspection-only and must not be installed or included in the release catalog.

## Remaining implementation and migration work

1. **Generic OS/CPU port and loader:** resolve all 36 controller imports with a small versioned *hardware-agnostic* kernel port and, when appropriate, driver-owned SoC definitions. Validate actual firmware symbol registration/loader, serialized execution and ISR/task/callback lifetimes. Never add firmware `usb.*` forwarding exports. Complete failed-start recovery, cancellation and bounded transfer drain.
2. **Independent lower providers and electrical arbitration:** build installable `i2c.bus@1` controller ELF and generic monotonic clock port, ensuring the new board-power provider is the EXCLUSIVE charger/address owner; implement a board/role arbiter so the legacy firmware cannot concurrently use the charger, OTG PHY or I2C bus. Validate actual connector VBUS sensing, battery/thermal constraints, hub loading, charger register readback and safe power-off, including externally powered hubs. An I2C claim in a separate experimental graph does NOT currently prevent the legacy compiled `Wire`/charger from accessing the hardware.
3. **Generic production wiring:** integrate verified manifests, contextual rights and generic leases, serializer, registry publication, bounded streams and install/remove lifecycle, and implement missing CH34x/other classes with qualified matching. Do not expose incomplete experimental builds to the user-installable catalog.
4. **Physical acceptance and cutover:** board test cold boot, external power conflict, host/device role, repeated attach/replug, hubs, unplug in flight, sustained duplex, line control, timeout/cancellation, callback/DMA teardown, power rollback and ability to remove an ELF without any firmware fallback. Only after parity convert Serial Monitor and remove compiled `NativeUsbBridge`, `UsbCdcDriverRuntime`, USB device projections and chip-specific firmware paths. Keep recovery bootstrap separate.

**Status:** Draft PR #78 has physical USB controller and board VBUS *driver implementations* plus independent host/CDC/CP210x ELFs. It still lacks the compatible OS port, I2C/clock providers, production runtime integration and physical device validation. Shipping USB and Serial Monitor are unchanged; migration is not complete.
