# USB migration: implementation status and acceptance

**Authority:** [RiscRTE master specification](RISCRTE_PLATFORM_SPEC.md), [hardware-agnostic driver boundary](HARDWARE_AGNOSTIC_DRIVER_BOUNDARY.md), [runtime driver architecture](RUNTIME_DRIVER_ARCHITECTURE.md), and [USB architecture](USB_OTG_HOST_ARCHITECTURE.md). This is an implementation snapshot, not a replacement for the normative target contracts.

## Implemented experimental code — not shipped

`Drivers/usb_cdc_v2/driver.c` is an independently built ELF with real CDC class behavior rather than a descriptor-only firmware proxy. ABI-v2 manifest: requires `usb.host@1`, provides `serial.port@1`. The ELF selects a single unambiguous ACM control/data pair, follows a CDC union and IAD when present, accepts unrelated vendor interfaces, locates bulk endpoints on a valid nonzero data alternate, rejects missing/wrong union targets and ambiguous selections, and owns interface claim/release, CDC line coding/DTR/RTS requests, bounded bulk RX/TX, sessions and stale-token rejection. The existing `open(device)` ABI has no CDC-function selector: multiple ACM functions or multiple valid data alternates deliberately reject rather than bind an arbitrary function. CDC descriptor parsing remains subject to real-device validation and future explicit function selection.

`RiscProviderV2.h` defines a generic, hardware-blind ABI and dependency injection; USB protocol tables live only in driver SDK `RiscUsbProviderV1.h`. `ProviderModuleV2` validates a preverified ELF's identity/capability/version and pins active consumers. Its optional ABI-v2 quiesce callback prevents unloading a provider with live CDC sessions, and a failed quiesce or failed unmap retains the ELF and dependency pins rather than assuming hardware shutdown. This is an ELF-lifetime guard, not proven controller/DMA quiescence. The current ABI-v2 module is not yet used by released firmware.

`ProviderGraphV2` resolves bounded externally verified provider descriptors recursively by exact capability/version, rejects missing/ambiguous offers and cycles, activates dependencies before consumers, pins lower ELFs, rolls back failures, and uses generation-qualified grants. The code is transport-neutral. **It is not connected to production manifest discovery, signature/hash validation, execution-context permissions, provider publication, or serialized dispatch**; tests inject descriptors after assuming independent validation. Hardware authority and physical teardown remain the providing ELFs' responsibility.

Host tests exercise dynamically loaded fixture ELFs, the actual CDC ELF composing with a separate **mock host ELF**, dependency lifetime, stale grants, quiescence rejection, control and bulk callbacks, and a new composite-descriptor matrix. `test/run_usb_cdc_v2_test.sh` runs these tests in CI. `scripts/build_usb_cdc_v2.py` builds and validates an Xtensa ELF under `dist/experimental/`. The host ELF in tests is a simulated fixture, not a controller driver. The experimental package is not installed, catalog-published or passed to Serial Monitor. **CI must be checked for the exact final commit; no device-level validation has occurred.**

## Blocking work before this driver can run on a board

1. Implement the real installable `usb.host` controller ELF owning ESP32 USB controller/OTG, safe VBUS through an independent board-power ELF as needed, host event/client workers, enumeration/hub topology and generation-safe device handles, interface claims, physical transfer buffers and completions, hotplug, cancellation and safe shutdown. The existing `RiscUsbProviderV1.h` operations need provider-owned device discovery/publication and lifecycle semantics, not just a call table. **Do not add USB-specific firmware exports, proxy back to `NativeUsbBridge`, or treat the mock host ELF as hardware.** The current firmware ELF loader exports application APIs and libc; ESP-IDF USB host and OS support must be correctly linked into the provider ELF or reached through genuinely generic CPU/RTOS port primitives. Verify relocations, DMA/ISR/task lifetime, PHY ownership and physical safety before activation.
2. Connect the generic graph to independently verified installed manifests/packages, the hardware-blind registry, provider-originated discovery, invocation-owned consent/authorization, generic streams and serialized calls. Revocation must stop new I/O, drain/cancel outstanding operations and wait for the provider's safe-quiescence acknowledgement before code unmapping. Installing/removing an ELF must add/remove its capability with no resident firmware fallback.
3. Migrate CP210x/CH34x and other chipset-specific protocols to independent ELFs; connect `serial.port` and Serial Monitor to generic capability selection, error propagation and bounded duplex streams. Remove firmware `NativeUsbBridge`, `UsbCdcDriverRuntime`, `UsbSerialProjection`, USB enumeration and chipset-specific logic only after real-device parity is demonstrated. Do not mistake keeping the compatibility implementation temporarily for a compliant new production path.
4. Add explicit function selection for multi-ACM composite devices and handle provider-originated device loss while CDC sessions/transfers are active. Test malformed descriptors, failed claims, stale device/claim generations, control timeout, disconnect/replug, duplicate sessions and provable callback/DMA drain. Current descriptor support and quiesce tests cover only the scenarios exercised in host CI.
5. Verify physical first boot, electrical VBUS/charger protection, role conflict, hub/multiple devices, attach/replug, multiple baud/line codings, sustained full duplex, unplug during transfer, uninstall/capability disappearance, crash/quarantine and zero fallback on actual T5S3 hardware. A firmware build, Xtensa ELF build and mock-host test cannot satisfy this gate.

**Status:** Work committed in draft PR #78. Existing shipping USB firmware and Serial Monitor remain unchanged; the hardware host-controller ELF, production integration, removal of legacy code and real-device acceptance are not done.
