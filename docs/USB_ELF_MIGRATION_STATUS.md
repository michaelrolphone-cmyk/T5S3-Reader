# USB migration: implementation status and acceptance

**Authority:** [RiscRTE master specification](RISCRTE_PLATFORM_SPEC.md), [hardware-agnostic driver boundary](HARDWARE_AGNOSTIC_DRIVER_BOUNDARY.md), [runtime driver architecture](RUNTIME_DRIVER_ARCHITECTURE.md), and [USB architecture](USB_OTG_HOST_ARCHITECTURE.md). This is an implementation snapshot, not a replacement for normative requirements.

## Experimental provider stack (not installed or shipped)

The three-layer model is now expressed in separate independently loadable ELFs and driver-only SDK contracts:

```text
CDC ACM ELF / CP210x ELF --requires usb.host@1--> USB host ELF
USB host ELF -------------requires usb.controller@1--> PHYSICAL CONTROLLER ELF (NOT IMPLEMENTED)
```

- `Drivers/usb_cdc_v2` implements real CDC class operations (descriptor matching including IAD/union and unambiguous nonzero alternates, control/data claims, line coding, DTR/RTS, bulk I/O and stale session rejection). Multi-function selection remains unsupported by the current `open(device)` API; ambiguous descriptors reject.
- `Drivers/usb_cp210x_v2` implements CP210x-specific UART enable/disable, baud, line format, modem controls, vendor-class matching, bounded sessions and bulk I/O through the host API. Its VID-only matching is experimental; PID/profile coverage and actual device validation remain outstanding. Both class ELFs provide `serial.port@1` independently.
- **New `Drivers/usb_host_v2` ELF** implements host-side device-list publication via a driver-owned discovery extension (`risc_usb_host_discovery_v1`), generation-qualified device and interface-claim tokens, interface/alternate and endpoint-descriptor checking, exclusive claims, endpoint-direction gating, stale-device transfer rejection on disconnect, and fail-closed claim release and quiescence. It consumes **`usb.controller@1` from a DIFFERENT ELF** via `sdk/driver/RiscUsbControllerV1.h`. That lower provider must actually own IDF/OTG/PHY, VBUS and power protection, enumeration/physical device handles, hub event handling, transfer queues, DMA, interrupts, callbacks, cancellation and safe teardown. There is no such production lower provider yet; this host ELF alone cannot access hardware or make the shipping serial app work. `poll()` is explicitly serialized by a future provider executor and must not be called concurrently with I/O; published device records are not yet forwarded to the generic Unified Device Registry.

The generic `RiscProviderV2.h`, `ProviderModuleV2` and `ProviderGraphV2` validate root identities against preverified specs, resolve exact versioned dependencies, pin lower-provider ELF lifetimes and reject cycles. They enforce optional quiescence prior to unload and quarantine failed teardown. Multiple verified providers can publish the same semantic capability, but unqualified resolution refuses ambiguity; a trusted caller may identify a verified provider using `acquireFrom`. The graph does not contain USB-specific routing. It is **NOT** yet connected to production package verification, manifest discovery, execution-context authorization, permission policy, registry publication or stream dispatch. It assumes serialized calls and caller-owned immutable validated manifest strings.

## Tests and build scope

Host tests cover class requests and bulk paths, CDC composites, CP210x controls, generic dependency and quiescence handling, host attach/detach generation invalidation, exclusive claims, endpoint authorization, stale handles and failure-to-release quarantine. `test/run_usb_three_elf_stack_v2_test.sh` separately loads a **test-only simulated controller ELF**, the actual host ELF, and the actual CDC ELF into the same generic graph, then exercises provider-discovered device tokens, session operations, dependency lifetime and fail-closed behavior with a missing controller. The test mock implements no ESP32 hardware and is never a release artifact. The standalone script `scripts/build_usb_host_v2.py` cross-builds the host ELF with import/export and architecture validation alongside the existing CDC and CP210x experimental builds; `dist/experimental/` artifacts are inspection-only and not ABI-v1 installable. Check the exact final CI commit; firmware builds do not constitute physical acceptance.

## Critical outstanding work

1. **Create a real installable `usb.controller@1` ELF** with direct ESP32 USB peripheral ownership, correctly relocated ESP-IDF or equivalent host-controller implementation, safe electrical profile/VBUS, hotplug/hub event worker, DMA-capable transfer allocation and completion, cancellation and hardware-backed quiescence. It must not delegate USB behavior to compiled `NativeUsbBridge` or introduce new firmware USB exports. USB controller dependencies on generic OS/CPU primitives or independent power ELFs must be validated against actual exported ABI, toolchain relocations and hardware. Once this exists, validate controller and host responsibility division, duplicate/lost-event recovery, hub support, backpressure and concurrent transfer safety on a board.
2. Extend the provider-owned discovery path into the transport-blind registry; connect verified manifests, signatures/hashes, context-scoped consent, generic leasing, serialized provider executor, cancellation and bounded streams. Current host `poll()`/`devices()` are provider-only interfaces, not system-wide hardware discovery. Future discovery must treat event-queue overflow as a recoverable fault with provable full hardware reset rather than resetting token counters unsafely.
3. Implement remaining CH34x and other chipset providers and qualified device selection. Migrate Serial Monitor and related apps to the generic `serial.port` path only after the real host/controller stack passes on-device tests. Then remove all normal-runtime compiled USB host/class/chipset code, USB-specific registry projections, hardcoded loader and silent fallback; keep recovery bootstrap isolated.
4. Verify actual T5S3 first boot, VBUS/charger safety, USB role conflicts, hub/multiple devices, attach/replug and transfer during unplug, serial line codings, sustained duplex, retry/cancellation, drain of callbacks/DMA, package install/remove capability disappearance and zero resident fallback. No current host-test fixture or firmware/ELF build satisfies these physical acceptance gates.

**Status:** Draft PR #78 contains experimental CDC, CP210x and host discovery/claim ELFs plus generic dependency machinery. The hardware-owning USB controller ELF, production integration, legacy removal and real-device acceptance remain incomplete. Shipping USB and Serial Monitor are unchanged.
