# USB migration: implementation status and acceptance

**Authority:** [RiscRTE master specification](RISCRTE_PLATFORM_SPEC.md), [hardware-agnostic driver boundary](HARDWARE_AGNOSTIC_DRIVER_BOUNDARY.md), [runtime driver architecture](RUNTIME_DRIVER_ARCHITECTURE.md), and [USB architecture](USB_OTG_HOST_ARCHITECTURE.md). This file records implementation state. It does not supersede those contracts.

## New implementation slice (experimental, not shipped)

`Drivers/usb_cdc_v2/driver.c` is a separately compilable ELF provider with an actual CDC serial-session implementation, not the legacy descriptor/request-encoder proxy. Its manifest declares `requires: usb.host@1`, `provides: serial.port@1`, `driver_abi: 2`. It performs descriptor parsing, interface claims and release, CDC line-coding and DTR/RTS control transactions, bidirectional bulk transfers, session allocation, stale-handle rejection and stop-time cleanup *within the ELF*. It calls only a `usb.host` interface table supplied by a different provider ELF. It does not import `usb_host_*`, call a firmware USB bridge, or acquire physical hardware through the runtime.

`RiscProviderV2.h` defines a transport-neutral versioned root ABI and dependency list. `RiscUsbProviderV1.h` is a **driver-only** typed USB-host/CDC contract; do not include it in RiscRTE core files. `ProviderModuleV2` checks a previously validated module's ID, capability and version against expected manifest values, starts it with generic dependencies, refuses unload while consumers are pinned and stops before unmapping. The caller remains responsible for manifest integrity/trust, resolving and pinning the dependency providers, serializing module calls, granting consumer rights, and revoking downstream grants before provider unload. The v2 module loader is a reusable building block, **not** a complete dependency resolver or security boundary.

`test/run_usb_cdc_v2_test.sh` builds a host DSO, invokes the actual provider against a fake `usb.host` implementation, checks real class control and bulk callbacks, failed claims and cleanup, stale handles, identity/version rejection and pin/unload behavior. `scripts/build_usb_cdc_v2.py` builds an Xtensa ELF into `dist/experimental/` and checks its single exported symbol, imports, architecture, hash and ABI-v2 manifest. It intentionally does not publish a package, put an asset into the release catalog or modify normal firmware. The existing compatibility driver and shipping USB behavior are unchanged.

## Blocking work before this driver can run on a board

1. Implement a **real `usb.host` controller ELF** containing all ESP-IDF/native controller and OTG logic: VBUS via a separate board-power ELF or direct driver-owned control; host initialization/teardown; enumeration, hub/topology, USB device generation; interface claims, control/bulk transfers, async callbacks, power and physical recovery. Its interface table must implement the driver-only host ABI or a separately versioned successor. Do not build a new firmware USB host proxy.
2. Make the generic provider resolver read validated driver manifests, resolve `requires`/`provides`, pin dependencies, load both ELFs with ABI v2, bind their interfaces, and register/revoke the resulting capabilities in the hardware-blind registry. It must not special-case strings such as `usb`, `serial.port` or chipset names. Define actual provider discovery/publication and physical rights delegated to providers.
3. Connect `serial.port` consumers and generic byte streams to the CDC ELF's exported API, using invocation-bound authorization, generational device/session handles, terminal disconnect, bounded I/O, provider serialization and cancellation. Remove the firmware `NativeUsbBridge`, `UsbCdcDriverRuntime`, `UsbSerialProjection`, firmware USB enumeration, chipset branches, USB-specific resource reservations and resident CDC/CP210x/CH34x fallback **only after the ELF paths demonstrably replace them**. Chipset-specific drivers must be installable independently.
4. Extend CDC descriptor selection to support multiple CDC functions, IAD/union descriptors and nonzero data alternates; the initial driver intentionally accepts only one unambiguous single-function CDC configuration. Add per-claim/device revocation callbacks, teardown completion and hot-unplug tests. A provider's negative I/O response is an error, not an automatic retry on a different physical device.
5. Validate packaging/ABI compatibility, install/uninstall capability disappearance, no resident fallback, hub/multiple devices, first boot, VBUS, detach/replug, 115200 and other line codings, sustained duplex, cancellation and cleanup on actual T5S3 hardware. Host tests and firmware compilation alone cannot meet this gate.

**Do not advertise this branch as fixing the current USB hardware or making USB modular.** It adds the first real class-driver I/O implementation and a reusable generic loader, while the core host implementation remains legacy firmware code and no `usb.host` ELF exists yet.
