# USB ELF migration: implementation status and acceptance

**Authority:** [RiscRTE master specification](RISCRTE_PLATFORM_SPEC.md), [hardware-agnostic driver boundary](HARDWARE_AGNOSTIC_DRIVER_BOUNDARY.md), [runtime driver architecture](RUNTIME_DRIVER_ARCHITECTURE.md), and [USB architecture](USB_OTG_HOST_ARCHITECTURE.md). This is an implementation snapshot, not relaxed acceptance criteria. **Shipping firmware still runs the legacy compiled USB and Wire paths; do not install experimental ELFs on the board.**

## Independently implemented experimental provider chain

```text
CDC ACM / CP210x ELFs --serial.port@1--> USB host ELF
USB host ELF -------requires usb.controller@1--> ESP32-S3 USB controller ELF
USB controller ELF --requires board.power.vbus@1--> T5S3 BQ25896 power ELF
T5S3 power ELF ----requires i2c.bus@1---------> ESP32-S3 I2C controller ELF
               `--requires platform.clock@1--> generic OS clock port (NOT INTEGRATED)
```

Every device-specific operation in the depicted chain is implemented in driver source. The compiled core has not been modified to forward USB, I2C, or charger operations. The provider graph, package verification, generic platform port and installed consumer routing are not yet the production pathway.

- `Drivers/usb_cdc_v2`: CDC class parsing, IAD/union/nonzero alternate validation, interface claims, line coding, DTR/RTS, bulk I/O, stale-session rejection and teardown. Ambiguous multi-function selection still needs a qualified-open API.
- `Drivers/usb_cp210x_v2`: CP210x vendor control, UART enable/disable, baud, line format, modem controls, bulk I/O and teardown. VID-only device matching requires tested PID/profile qualification.
- `Drivers/usb_host_v2`: separate `usb.host@1` provider consuming `usb.controller@1`; generation-qualified discovery and claims, exclusive interface ownership, endpoint/alternate verification, stale-detach rejection and fail-closed quiescence. Its discovery extension still requires a serialized executor and transport-blind registry publication.
- `Drivers/usb_controller_esp32s3/driver.cpp`: real USB OTG/host, client/device, PHY/interrupt, control/bulk/DMA and teardown operations. `scripts/probe_usb_controller_esp32s3.py` compiles pinned ESP-IDF v4.4.7 USB/PHY/HAL/SoC code as PIC INTO the ELF, links MMIO bases and GPIO mux data there, and includes provider-owned PHY pad drive. This is not a compiled firmware USB proxy. The controller is not loadable under the currently registered kernel symbols; its teardown/role/physical correctness remains unvalidated.
- `Drivers/board_power_t5s3_v2/driver.c`: real BQ25896 charger/boost register operations using exclusive address 0x6B from a separate `i2c.bus@1` provider plus `platform.clock@1`. Source request bounded at 500 mA. Preflight rejects conflicting external VBUS/OTG; it saves REG02/03/0A, enables voltage sampling, programs boost, verifies OTG status/voltage/faults, and restores the charger, boost and ADC configuration on release. Failed writes may already have taken effect, so unsuccessful source-off/readback or I2C-claim release retains a lease and blocks ELF unmapping. REG11 `VBUS_GD` can be zero while OTG sourcing; the implementation checks measured voltage and OTG state instead. This logic has mock-backed fault tests, NOT on-board electrical acceptance.
- **`Drivers/i2c_esp32s3_v2/driver.c`: real physical ESP32-S3 I2C0 implementation, not a Wire forwarding shim.** It initializes I2C0 on T5S3 pins SDA39/SCL40, uses real IDF `i2c_driver_install`, atomic repeated-START `i2c_master_write_read_device`, read/write, exclusive 7-bit address claims, bounded transactions/timeouts, monotonic generation tokens and `i2c_driver_delete` at quiescence. `scripts/probe_i2c_esp32s3_v2.py` cross-builds pinned ESP-IDF I2C driver, GPIO, peripheral clock, I2C HAL, dedicated interrupt-safe `i2c_hal_iram.c` and SoC data as PIC **inside this ELF**; it reads MMIO bases from the pinned SoC map, and fails on any unresolved peripheral implementation symbol. It is experimental and cannot activate concurrently with current compiled firmware `Wire` on the same controller. Linker garbage-collection work removes unused GPIO/RTC code rather than requiring another peripheral driver merely to satisfy dead code. Exact linker/import status must be checked against the final CI commit.

`RiscProviderV2.h`, `ProviderModuleV2`, and `ProviderGraphV2` implement generic identity/dependency validation, competing-provider choice, dependency lifetime pins, cycle rejection and failure-to-quiesce quarantine. They do NOT yet connect installed verified packages to context-specific permissions, a serialized provider executor, the Unified Device Registry, streams or the shipping app path.

## Actual verification

Independent CDC, CP210x, host and generic provider-graph tests exercise descriptors, requests, claims, stale generations and teardown. The three-ELF integration test includes a clearly labeled **simulated controller ONLY as a host test fixture**. `test/run_board_power_t5s3_v2_test.sh` injects I2C failures and simulated charger faults, including late write NACK, source rise timeout, fault and retry. `test/run_i2c_esp32s3_v2_test.sh` compiles the actual I2C provider source with instrumented IDF functions and verifies real IDF entry calls, repeated START, address exclusivity, stale claims, transaction bounds/failure and delete retry.

[Experimental CI run 35251317623](https://github.com/michaelrolphone-cmyk/T5S3-Reader/actions/runs/35251317623) passed **all host tests, USB controller PIC link/structural audit, full physical I2C PIC link including interrupt HAL and static peripheral-import rejection, and all experimental Xtensa class/host/power provider builds**. All outputs remain inspection-only artifacts; CI never publishes these ELFs to the package catalog. The USB controller loader audit still reports 590 supported relocations and **36 kernel/OS/CPU imports missing from actual firmware symbol tables**, so it is not installable. The first physical I2C link succeeded without unresolved `i2c_*` or `gpio_*` hardware functions, but its audit disclosed eight extraneous RTC GPIO imports and 38 remaining generic/OS imports; a subsequent PIC dead-code elimination and precise structural/loader-import audit is in progress. Do not assume their results from an earlier successful run.

## Completion and release blockers

1. **Privileged, generic OS/CPU ABI and actual loader compatibility.** Resolve the controller's 36 unavailable interrupt, allocator, task/queue, ROM GPIO/log/assert imports and the I2C provider's remaining relevant OS imports without exposing unrestricted privileged kernel functions to every application ELF. Version, authorize and scope the platform port to verified providers. Verify all ELF relocations/imports and ensure ISR/task callback lifetimes cannot outlive code mappings; integrate the generic `platform.clock@1` service. No USB- or I2C-specific compiled firmware proxies.
2. **Exclusive hardware ownership and full driver lifecycle.** The new I2C ELF's claim table excludes only its own clients; it cannot stop the shipping firmware `Wire` from independently programming the very same I2C0 registers. Implement a generic CPU/SoC resource grant and actual Wire-to-provider cutover or otherwise prove exclusive ownership before activation. Likewise prevent legacy firmware OTG/PHY/charger conflicts. Verify power rail source-current, reverse current, backfeed, battery/thermal and board wiring; prove explicit cancellation, transfer/ISR/DMA drain, lost-event recovery and fail-closed uninstall on the actual board.
3. **Generic production route.** Connect cryptographically verified manifests and package lifecycle, context-owned grants/consent, provider graph, serialized executor, device-publication registry, cancellable bounded streams and semantic serial consumers. Additional classes such as CH34x and qualified device selection remain outstanding. No catalog exposure before the acceptance gates.
4. **Physical parity and cutover.** Verify T5S3 boot, attach, hubs/multiple devices, replug/unplug during transfers, CDC and CP210x line coding, sustained duplex, fault handling, USB role/VBUS safety, callback and power drain, removal and no normal-runtime firmware fallback. Only then migrate Serial Monitor and remove resident `NativeUsbBridge`, `UsbCdcDriverRuntime`, firmware USB projections and hardcoded dispatch; any recovery bootstrap remains separately isolated.

**Status:** Draft PR #78 contains actual experimental ESP32-S3 USB and I2C controller ELFs, BQ25896 power, USB host, CDC and CP210x implementations. A PIC build or mock test proves neither loader compatibility nor electrical safety. Shipping USB and Wire behavior remains unchanged until proven cutover.
