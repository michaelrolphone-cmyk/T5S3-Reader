# SPI and UART bus-provider ELF bootstrap and cutover

**Normative U1–U4 dependency contract; specifications only.** Apply the established [I²C bus ELF pattern](I2C_BOOTSTRAP_CUTOVER.md) to normal-runtime SPI and hardware UART. This is an expressly limited extension of [Hardware-Agnostic Driver Boundary](HARDWARE_AGNOSTIC_DRIVER_BOUNDARY.md): one installable bus/provider ELF exposes the stable public interface while, temporarily, only that ELF delegates low-level controller operations to bounded firmware port primitives. Do not copy a firmware transport dependency into each peripheral driver, invent a new milestone or mistake this text for implemented code. Audit the actual linked implementations and board power/pin topology before choosing concrete ABI, driver identities and cutover sequence.

## Stable public provider boundary

```text
LoRa / display / SD device ELFs --requires--> SPI bus ELF --private U3 transition--> firmware SPI port
GNSS / UART-device ELFs -------requires--> UART bus ELF --private U3 transition--> firmware UART port
                                                same public capability   --> native ELF controller
```

Each bus ELF is independently package-managed, versioned, lifecycle-controlled and discoverable by a generic provider-published capability (`spi.bus`, `uart.port`, or a compatible existing versioned contract). Keep the **same provider identity, public capability, interface and consumer manifest dependency** before and after backend replacement. Peripheral ELFs implement their own device matching, register/protocol sequences, framing, command/state, power policy and recovery; they must not import the private firmware SPI/UART symbols, `SPI`/`HardwareSerial` globals or board-specific firmware device bridges. The generic RiscRTE core interprets neither bus identifier nor protocol. An absent/broken/uninstalled bus ELF means no production capability and no firmware fallback. A temporary *bus-level* proxy is permitted; a peripheral-specific thin proxy is not.

Only the corresponding bus ELF may import its own explicitly allowlisted, versioned transitional controller API. Such APIs live in isolated CPU/board port compatibility modules, not the package manager, registry, stream router, UI, native USB bridge, GPS runtime or a generic firmware bus provider. Limit to controller setup/teardown and **bounded raw I/O**, with bus-instance/resource tokens, scoped rights, finite transfer sizes and timeouts, errors, cancellation, single-owner arbitration and generation-safe handles. No device register interpretation, sensor protocol, LoRa packet framing, GNSS NMEA parsing, USB class selection, power-chip policy or transparent fallback in firmware. No second controller may initialize or access the same peripheral concurrently.

### SPI-specific contract

The provider must mediate bus instance, device-select/session scope, clock/mode/order configuration, atomic transactions and exclusive use across multiple clients. Pins, chip select and power prerequisites come from verified board profiles and resource grants, not global `SPI` calls from every device ELF. Explicitly account for shared SD/LoRa/EPD pins, pad mux, interrupt/DMA and PSRAM/cache rules. A synchronous firmware transaction may be used only inside the temporary SPI bus ELF backend; client streams and frame/packet buffers remain bounded and lifecycle-safe. The final SPI ELF must own controller setup, transfers, arbitration and teardown, with DMA-safe buffers and IRQ cleanup where applicable.

### UART-specific contract

The UART bus/provider ELF mediates actual hardware UART instances and ownership, RX/TX byte streams, speed/framing/configuration and optional supported flow control, buffers, errors and safe close/reopen. The GNSS ELF consumes this provider and owns its receiver commands, NMEA parsing and semantic location streams; its consumers request `location.position`, not a UART driver ID. **USB CDC `serial.port` is a semantic USB-provided serial capability, not proof that a physical UART bus was migrated.** Preserve separately identified ROM/bootloader and minimal one-way diagnostic console output if required for headless boot/recovery; they are port/recovery functions, not production `uart.port` providers or fallback routes for absent driver ELFs. Ensure any shared UART pins/controller are handed off or explicitly reserved; never have console and UART ELF simultaneously own one peripheral.

## Noncyclic startup and cutover

For each actual controller, map power/clock, expander, boot media, shared pins and downstream device dependencies. A bus ELF cannot require an unstarted device ELF that requires that same bus, absent a truly independent safe bootstrap primitive. U1 generic resolver/streams/lifecycle must support these provider graphs; don't hard-code SPI/UART cases in core. At cutover, stop admissions, quiesce clients, drain/cancel pending I/O, revoke generation-bound handles, release and deinitialize the firmware controller, then start the **same bus ELF package's native backend** as exclusive owner. Restart/rebind clients with fresh leases without changing the public API. Failed takeover fails closed or enters isolated recovery; never run competing controllers or silently resume a production firmware backend. Remove privileged transitional imports and normal-runtime firmware call paths only after the relevant bus and consumers are migrated. Document separate controller instances if some have legitimate distinct boot/recovery ownership.

## Milestone allocation and acceptance

**U1:** Finish generic ELF provider/capability, cross-context stream and lifetime infrastructure. Define versioned reusable SPI/UART provider contracts and import restrictions when needed for compatibility, but **do not require full SPI/UART driver migration or manufacture unused bus ELFs solely for U1**. If any U1 driver truly needs SPI/UART, first publish the corresponding bus ELF capability and isolate its temporary firmware backend within that ELF. USB host/class/CDC still belong to USB ELFs; temporary SPI/UART imports are not an excuse to keep USB device behavior in firmware. Record real dependencies and later owner.

**U2:** Preserve package identity, public ABI, manifests and generic independent publishing. No direct per-device firmware SPI/UART imports and no automatic native-controller cutover requirement.

**U3:** Before migrating actual T5 Pro display/LoRa/SD SPI users and GNSS/other hardware-UART users, establish functional installed SPI/UART provider ELFs with stable public interfaces, using temporary firmware raw backends only if required. Convert consumers to those bus capabilities, then replace each bus ELF's *internal* backend with native controller ownership and retire its production firmware primitives by **U3 Work Complete**. Check each actual controller independently, including SD module-store/bootstrap separation and UART console/recovery isolation; do not turn minimal boot I/O into a normal provider. U3 also retires the I²C transition per its own contract.

**U4:** Camera provisioning/capture must use installed providers and genuine minimal port bootstrap; do not depend on residual T5 Pro transitional SPI/UART/I²C adapters or add a mandatory streaming/interactive-shell milestone.

**Acceptance:** before bus cutover, app/device ELFs link only against a real installed bus provider; one bus ELF alone imports the matching private firmware port functions; disabling it removes capabilities. After cutover, native ELF exclusively owns normal controller operations, old normal-runtime port symbols are unreachable/removed, upstream driver packages operate through their preexisting public ABI, missing providers fail closed, and boot/recovery exceptions do not leak into production. Test bounds, conflict, cancellation, unplug/failure, provider unload and no fallback at the appropriate milestone. Hardware results remain owner qualification only.
