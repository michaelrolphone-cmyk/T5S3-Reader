## Unfinished U1 acceptance — implementation order

1. **Provider-originated USB:** host/class ELFs must discover/probe/bind/publish arrivals, revocations and semantic `serial.port` registry/streams, then retire firmware `NativeUsbBridge` polling, config reads, device/class selection and USB-specific projections/fallbacks; preserve monitor/programmer DTR/RTS, partial I/O, reconnect, and fourth class with no firmware edits.
2. **Exclusive USB PHY/console:** real CPU/board-port handoff with one exclusive controller lease, safe console release/restore and pinned failed teardown. Physical controller manifest remains experimental and its target build/link unverified.
3. **BQ integration validation:** current target linkage and driver host/source checks; charge, OTG exclusion, unavailable/corrupt package, fault/recovery and both sleep paths. No more competing charger writers and no repetitive owner hardware-test demands during implementation.
4. **Distribution/diagnostics cleanup:** structured provider errors instead of parsing `USBREF`/`USBCTRL`/`VBUSREF`; old CDC loader reachability; canonical `usb-cdc-acm` identity migration; signing/P-256/floor purge while preserving SHA/TLS/ABI/import/rollback; nested package resources and unknown user data.
5. **Performance/evidence:** generation-bound ELF validation receipts to avoid redundant whole-file rehash; actual current firmware, ELF, app and host builds, package/import/catalog audits and later owner-controlled physical qualification. Native I²C/SPI/UART controllers, unrelated board peripherals and Wi-Fi are U3; CAM provisioning is U4.

**Next production action:** move discovery/class orchestration and semantic port publication out of firmware while fixing build/link findings as they arise. Keep this PR open, without claiming U1 completion or release qualification.
