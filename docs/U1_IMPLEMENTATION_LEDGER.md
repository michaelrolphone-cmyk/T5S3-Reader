## Streams, provider lifecycle and USB foundation

- Generic ELF byte/record streams, context-owned rights, grants/revocation and bounded partial RX/TX with provider I/O outside the stream mutex. `open_usb` is unsupported; the target is semantic `serial.port`. `ClassStreamSession` and `NativeStreamBridge` retain chunks through backpressure, partial/zero writes and reconnect. Installed USB class binding retains mapped ELF/package state on uncertain physical close and avoids duplicate early attachment.
- Installed I²C bus ELF is the only authorized temporary importer of bounded `risc_fw_i2c_transact_v1`. BQ power, USB controller, host and class implementation live in separate installed ELFs. Native I²C controller takeover is U3; USB controller, host, discovery and class ownership **must** finish in U1.
- `50e01d0`, `4919e21`, `c9c1196`: graph/installed-provider enumeration yields verified identities for semantic capability/minimum API without activation or grants. `a2caac3`, `3249d61`, `f4c73f9`: active host/class lookup no longer hardcodes CDC/CP210x/host IDs or VID order. Host must be unambiguous, class ELF independently checks descriptors when opened. Firmware **still** polls USB, reads configurations, selects physical devices/classes, manages session and retains legacy `T5UsbApi`: not yet provider-originated discovery.
- `23b3869`, `aafb8e1`, `670f175`, `5e0f0b7`: distinguish class no-match from activation/teardown failure; pin uncertain grants; stop selecting other candidates after failure, avoid double-probing. `3364cea`, `4ea0db2`, `2d1e6d5`: graph failed-release generations stay pending, non-usable and retryable, without premature unpin. Metadata/grant regressions are committed but not observed green at this head.

## BQ25896 physical ownership — current implementation

- `5335420`, `0f6acf2`, `6b3f31f`, `cf8c7d2`, `b8d6573`: append-only telemetry API in **the existing `board.power.vbus` ELF**, not a competing chip provider. Its I²C bus address claim copies an all-or-nothing raw charger snapshot, omitting side-effectful REG0C fault history and refusing partial results. Board-power snapshot host regression committed and wired; original version 0.1.3 -> 0.1.4.
- `221f768`, `d2add58`, `a35c6fa`, `88f3e20`, `61456ac`, `5885106`, `2bd3e3f`: the ELF implements board-qualified 1000mA input / 512mA charge / 64mA precharge+termination / 4208mV regulation / 3300mV system minimum, continuous ADC and disabled watchdog. Pre-reads, bit-masked writes and readback reject active OTG/wrong device. Uncertain configuration pins/chip-quarantines until verified retry. Profile host regression wired; version 0.1.5.
- `f6c8211`, `923d709`, `06d2e14`, `da4d24a`, `f57b3b5`, `615076d`: ELF-owned one-way BATFET shutdown rejects active source/external input/uncertain config, verifies charge disable first and permanently pins after BATFET command may have taken effect—even after NACK, never pretending ACK proves power-off. ACK/NACK regression wired; version 0.1.6; existing VBUS ABI prefix unchanged.
- **This continuation's actual consumer cutover:** `ff173dd`, `ea032d3`, `951a2c2`, `e779be1`, `dbb3e2a`, `7e18713`, `9fe93cb`, `9dfb843`, `17695f6`: `BoardT5S3.cpp` no longer includes the resident BQ25896 HAL, initializes/resets the PMIC, performs raw chip reads, or directly commands shutdown. Existing raw register compatibility entry now returns false; charger configure/read/external-power/shutdown forward to `BoardPowerPort` and a board-specific native adapter using verified `board.power.vbus` leases, without a hardcoded provider package ID or second I²C address claim. The independent BQ27220 gauge, touch and expander retain their preexisting transitional board paths; unrelated hardware migration belongs to U3.
- Early `HalGPIO::begin()` runs before SD mount, so `readyForActivation()` prevents premature ELF load. `isUsbConnected()` performs a bounded post-mount charger configuration attempt (30s retry only when unconfigured), caches UI/poll presence for 1s rather than loading an ELF and reading eleven registers each GPIO cycle; the chip ELF always performs fresh safety checks for actual shutdown. The old battery app API still goes through `NativeBatteryBridge`, but its board backend now delegates BQ calls exclusively to the installed provider.
- `HalDisplay::deepSleep()` calls `Board::deinitForSleep()` before the later hard-power-off request; that hook reserves and pins the verified ELF **before SD_CS is disabled**. A failed first reservation is remembered and cannot trigger a new SD-backed load after bus deinitialization. The BATFET command retains its original provider grant through the one-way transition; failed quiescence quarantines instead of unloading an uncertain chip. `e2b341d`, `41a47d6`, `437e241`: source regression guards no resident BQ accesses, post-mount init, one-second UI cache, shutdown reservation order and failure gating, and runs in the existing board-power host runner. **None of the new target source, source regression or host driver tests has been observed passing on this head.**
- **Remaining BQ qualification/finishing:** ensure linked firmware/ELF builds, source/host regression results, actual charge/OTG/sleep behavior, and correct lifecycle with USB host activity. The copied telemetry ABI does not carry REG12 charger ADC current; compatibility reports zero rather than inventing a measurement. The temporary firmware-level board adapter still decodes the raw snapshot for legacy UI; a normalized provider-owned measurement ABI is preferable for eventual architecture cleanup. There is no registered backup charger writer when the ELF/package is unavailable. Do not describe this as hardware proven or the entire U1 accepted.
