## Generic runtime and installed hardware ownership

- Generic ELF byte/record streams, context-owned grants/revocation, partial bounded RX/TX/backpressure, verified provider discovery and API-aware dependency checks exist. USB stop (`3515ee0`–`a2035d4`) releases its own class/host grants rather than shutting down the global graph; unsafe releases retain exact module generations.
- Installed `i2c.bus` ELF alone may import temporary bounded firmware raw I²C. BQ25896 charger/USB power, actual IDF USB controller, host, CDC, CP210x and CH34x protocols live in their own installable ELFs. The app's generic target is `serial.port`, not `open_usb`.
- Checked-release host/class API (`02ff428`–`fd94430`) appends `release_checked` without altering the host ABI prefix. Failed physical release keeps a closing claim, blocks transfers, preserves exact class sessions and retries failed-open orphan claims. Host/CDC/CP210x tests wired, not observed green at the current head.
- Physical controller (`ca2c26f`–`5d9b5b5`) retains `ClaimReleasePolicy.h` for two-stage interface/device-close recovery: a failed detached-device close cannot repeat an already-successful interface release. Unclaimed detached handles are reaped in a bounded table. One isolated reconstructed C++17 ASan/UBSan release-policy exercise passed earlier, not the repo suite.
- **Selective master #105 integration (`db75070`–`6b7b41b`):** controller ELF bounds bulk timeout to 500-ms halt/flush/callback drain, verifies ownership before interface release, and drains DMA before freeing memory, uninstalling the IDF host or releasing VBUS. It retains failed-cleanup stages, consumes IDF's NO_CLIENTS event and can quiesce a faulted controller only when physically safe. Controller manifest 0.1.5, source regression wired, **not verified by present-head target build or voltage measurement**.
- **Selective master #103 CH34x integration (`d534030`–`f63c2f8`):** chipset VID/PID, descriptor parsing, WCH vendor control/framing/baud, DTR/RTS, bulk RX/TX belong in independent installed `serial.port` ELF. Added checked host release, retained sessions and orphan retries, rejects unsafe old host ABI. Version 0.1.1; generic manifest exporter, runner and experimental CI include it. Tests committed but unverified. CH34x is a distinct chipset driver, not a duplicate CDC package lineage.
- **CP210x confirmed-detach cleanup (`5eaa653`, `b47ee80`, `9d81322`):** class ELF now requires host-owned `poll`, `devices` and checked release. It refreshes the host's generation-bound device inventory before UART disable. Confirmed unplug skips impossible vendor I/O and releases its exact claim; unknown state, still-attached command failure and physical release failure pin/retry the session. Failed-open orphans recover on verified detach. `usb-cp210x-v2` 0.1.2. Updated production-ELF mock-host test exercises absent discovery, unknown state, attached NACK, unplug, release failure, orphan recovery and stale tokens in existing CP210x runner. No run result yet.
- **Host device-control ownership and fault recovery (`e4c6739`, `4451fa3`, `9318bba`, `cd8dc9a`):** `usb.host` ELF now requires an active, nonclosing physical-interface claim on the addressed device before forwarding device-recipient vendor requests (including CH34x); interface-recipient controls also require a matching claimed interface. All other USB recipients fail closed. An event fault continues to block new discovery/I/O, but no longer permanently strands the host if all claims are gone and the actual controller independently proves DMA, callbacks and interfaces quiescent. Only *after* verified physical quiescence does `stop()` clear fault and device slots; failure preserves the graph/dependency lease. `usb-host-v2` package 0.1.1 → **0.1.2**. New `usb_host_control_claim_test.c` dynamically exercises the production host ELF with a mock controller: no preclaim vendor/class commands, authorized requests, recipient/interface rejection, event-fault denial, claim-release retries, failed controller quiescence and post-quiescence restart. Wired into `test/run_usb_host_v2_test.sh`. **Not executed/CI-verified**. The legacy host API still accepts a device token rather than a class-specific claim token, so this is a live-claim gate, not complete cross-class isolation; full independent binding remains U1 work.
