## Committed production implementation

- **Streams and capabilities:** generic ELF byte/record streams, context-owned grants and revocation, bounded partial I/O/backpressure, pinned uncertain provider generations, semantic provider enumeration and versioned dependency checks. Ordinary serial apps consume `serial.port`; `open_usb` is not a generic app capability. `3515ee0`–`a2035d4` made serial teardown release its own class/host grants without shutting down unrelated provider graph nodes.
- **USB host and classes:** installed physical IDF controller ELF owns controller, callbacks, DMA and VBUS dependency; host ELF owns enumeration/device tokens/interface claims; class ELFs own descriptor matching and protocol I/O. `02ff428`–`fd94430` added append-only checked claim release and retries, preserves CDC/CP210x sessions and quarantines ambiguous hardware close. Existing host/class tests are wired, but not observed green on this branch.
- **Physical controller claim recovery:** `ca2c26f`–`5d9b5b5` introduced controller-private `ClaimReleasePolicy.h`: after interface release succeeds but closing a detached device fails, the exact claim and stage marker survive, and a retry cannot double-release the interface. Unclaimed detached devices are reaped through a bounded table, with failed closes retained for later retries. The isolated policy was previously reconstructed and passed one strict C++17 ASan/UBSan smoke; this was **not** the full repository runner.
- **This continuation, master fix ported without discarding PR-specific recovery:** `db75070` integrates a bounded 500-ms IDF bulk-IN halt/flush/callback drain into `Drivers/usb_controller_esp32s3/driver.cpp`. A synchronous USB read timeout no longer knowingly leaves an uncancelled asynchronous bulk transfer; interface release first verifies the pending transfer belongs to that interface, drains it and *then* invokes the two-stage release policy. Quiescence drains pending bulk DMA before freeing transfers, uninstalling the host or releasing VBUS; failures remain pinned. An in-flight control transfer or unverified endpoint ownership fails closed. Retained faulted controllers can attempt verified cleanup instead of treating a discovery fault alone as evidence that VBUS can never be released. The later master IDF `NO_CLIENTS` final-event pump is also preserved before uninstall. This is source implementation, **not confirmed firmware, ELF or hardware behavior**.
- **Regression and distribution wiring:** `e74ef8c`, `acdcbd9` add/wire structural source checks for bounded drain, same-interface release, two-stage claim ownership and VBUS ordering in the existing USB host runner. `6b7b41b` replaces a stale test that mistakenly required global graph shutdown with assertions for scoped class/host release. Manifest `usb-controller-esp32s3` is 0.1.5; no package or firmware release occurred.
- **Board power:** the sole installed `board.power.vbus` ELF owns BQ25896 telemetry, charger profile, OTG and one-way BATFET command with readback and uncertain-write quarantine. `ff173dd`–`17695f6` removed the board resident BQ HAL writer and routed UI/charger/shutdown via verified provider leases; the independent BQ27220 gauge stays. Configuration waits until SD mount with bounded retries; pre-sleep ELF reservation occurs before SD pins are disabled, with no unsafe fallback loading afterward. Charge/profile/shutdown/source regressions are wired, not observed passing on this head.
- **Four-kind package engine:** ordinary application/driver/service/provider per-ID transactions with recoverable stage, offline ZIP bootstrap, generic immutable-release catalog pinned to hashes, and unified App Store/Package Manager/Driver Manager install API. Runtime identity bounds and discovered manifest-based package export replace the fixed seven-driver allowlist. `f24c02c`–`484a46c` provide a shared cross-TU package mutation gate covering retained stage recovery; its isolated two-translation-unit ASan/UBSan smoke previously passed. No full build is claimed.
