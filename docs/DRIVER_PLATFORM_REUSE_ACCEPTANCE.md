# U1 driver-platform reuse acceptance: USB is the proof, not the architecture

**Status:** Normative addition to [U1: next hardware-test milestone](NEXT_HARDWARE_TEST_MILESTONE.md), September 18, 2026. Read [RiscRTE platform specification](RISCRTE_PLATFORM_SPEC.md), [hardware-agnostic driver boundary](HARDWARE_AGNOSTIC_DRIVER_BOUNDARY.md), [temporary I²C bootstrap/cutover](I2C_BOOTSTRAP_CUTOVER.md), [runtime driver architecture](RUNTIME_DRIVER_ARCHITECTURE.md), [package scope contract](PACKAGE_MANAGER_SCOPE_CONTRACT.md) and U1 first. This specification strengthens U1's *foundation acceptance*, not its mandate to fully migrate every peripheral. The current user objective is that USB establish the common route for later display, touchscreen, networking, LoRa, GPS and other drivers, so each successive migration is primarily driver code and consumer adaptation rather than a new runtime architecture project.

## Outcome / non-negotiable rule

After U1, adding a new driver for hardware supported by the existing CPU/OS port and versioned primitive ABI SHALL involve only a driver/provider ELF, ordinary package manifest and payload, board/profile data, optional independently versioned capability SDK contract, and migrations of its consumers. It SHALL NOT require editing, recompiling or reflashing generic RiscRTE firmware, a new framework-side per-device bridge/manager/registry, a new package type or USB-specific catalog entry, a hard-coded provider ID, a special privileged-import exception by device name, or custom installation/release code. Installed capability registration and selection SHALL be driven by manifests, driver probe/publication and neutral policy, not identifier-specific branches in core.

A driver can be a bus/controller provider, chip-specific provider, protocol/class provider, or composite provider and can consume other providers. Generic software leases are NOT hardware ownership. Drivers own and safely stop their own *device* work. **Time-limited exception:** the U1 platform port may temporarily own the I²C bus controller and expose only the bounded authorized bus primitive needed to bootstrap power/expander drivers, without owning their device behavior. The final I²C controller ELF cutover and removal of this API are U3 gates, not U1 gates. Do not expand this carve-out to USB host, class logic, hardware-specific firmware services or additional buses. Existing RiscRTE application/driver/service/provider package kinds are unchanged. Do not reintroduce package signing or cryptographic trust infrastructure under this gate.

This guarantee is **within a compatible CPU architecture, ELF/runtime ABI and platform port**. A different ESP family/ISA may require a distinct port, ELF build and independently reviewed generic primitive backend. It SHALL NOT require reimplementing the package manager, resolver, registry or lifecycle per board. Neither USB completion nor an ESP32-S3 build proves universal cross-chip binary compatibility.

## Platform interfaces that must be *real and reusable*, not USB-shaped

Verify in the *production firmware and independently built ELFs*, documenting API version and example caller for each:

1. **Distribution:** driver template/build invocation discovers source manifest, produces actual PIC ELF and ordinary package, audits imports and generates generic all-kind catalog assets from produced packages; no hard-coded seven-driver list, `usb-provider-catalog.json`, fixed four-file list or device-specific release script edits. Locally installed packages are visible/usable with no network/catalog.
2. **Admission:** architecture/ABI, bounds, exact executable bytes, declared content hash, permitted OS/CPU imports and runtime policy are independently checked; unsigned packages use normal policy, do not obtain privileged access from manifest text/hash, and do not need package-signature machinery. Generic loader, provider executor, dependency resolver and activation make no USB/GPS/display/LoRa-specific decisions.
3. **Composition:** arbitrary manifest-declared requires/provides and capability API versions; dependency sorting, cycles, ambiguity, missing dependency, conflict and loss; provider-to-provider calls use versioned contracts, immutable/owned metadata and generation-safe handles. Each driver can publish multiple capabilities or device instances. No central list of known device kinds. Include an actual power/expander/I²C graph with no bootstrap dependency cycle.
4. **Hardware resource mediation:** the CPU/OS port exposes only necessary *generic* interrupt registration/removal, ISR-safe notification, task/synchronization/time, allocation and executable/PSRAM access, DMA-safe memory/cache handling where supported, and opaque platform resource primitives. Bus ownership and SPI/I²C/UART/GPIO transactions, pin usage, radio/display control and DMA/IRQ/device policy ultimately live in provider ELFs. **Precisely during U1–early U3, the transitional platform I²C bus API may own and serialize controller-level transactions for authorized driver ELFs; device register semantics, probing, power policy and other bus/device implementations remain in ELFs.** A missing generic primitive is identified and added once to a versioned port ABI with ordinary-import isolation and tests, NOT implemented as a named hardware service inside firmware. Keep IRQ/DMA/task cleanup and failure quarantine safe across module lifetime. Log temporary I²C callers and U3 removal criteria; do not misreport the bus as extracted at U1.
5. **Hardware configuration:** bounded installed board/device profiles provide applicable pin, bus, chip-select, address, IRQ, rail, clock and compatibility data to eligible providers; the generic core transports but never interprets these fields as USB, SPI, etc. Conflicting use of a physical resource is mediated by its owner provider or opaque resource policy, with single-controller ownership in the transitional I²C adapter until exclusive ELF handoff. Profile updates/new board variations do not add a core device switch.
6. **Publication and consumption:** providers, not firmware ticks, probe and publish generic device/capability records and lifecycle events; registry identity, generation, notification, GAP/resnapshot, owner permissions and lease revocation work for any family. Apps resolve semantic capability plus optional instance/binding, not concrete driver filename. A provider can expose versioned control/command APIs, bounded streams/records/events or frames; the core routes opaque data but implements no device-specific transactions. Transitional I²C does not publish a replacement normal runtime bus or device capability.
7. **Failure and recovery:** dependencies start/stop in correct order; absence, corrupt package and failed activation do not crash boot or create a hidden compiled fallback; in-use replacement is refused; cancellation/draining/unload/quarantine retains mappings and lower-provider pins until physical quiescence is known. Recovery-only boot/module-store I/O is explicitly isolated from normal provider registration. A removable display/touch/network driver must not make recovery *impossible*: supply a documented recovery path not dependent on the failed ordinary provider. Transitional I²C transfer timeouts, power failure and exclusive bus ownership must fail safely.
8. **Developer workflow:** one documented `Drivers/<name>/` template with manifest/API version, dependency/profile example, ELF build/import audit, ordinary packaging, local SD/online installation, provider registration, generic device/stream example, test fixture and exact cleanup/recovery procedure. A new driver can be added without modifying package-manager source, exporter/release enumeration, firmware tables or platform build flags. Build/release automation must discover it from existing manifests/declared build metadata rather than requiring an agent to add its name to a script.

## Required cross-family gap ledger (complete BEFORE marking U1 software ready)

Inspect the present *linked* firmware, privileged import inventory, provider SDK, ELF builds, package tooling, registry, stream and bootstrap behavior. For each future migration below identify: hardware ownership now in firmware; required lower-provider capability; currently supported generic ABI/primitive; missing API/profile/build mechanism; boot/recovery dependency; consumer migration target; and acceptance proof. Mark each item `READY`, `GENERIC-ABI-GAP` (with a precise reusable contract and U1 repair), `TEMP-I2C-CUTOVER` (documented temporary bus ABI, real dependents and U3 removal), or `FAMILY-IMPLEMENTATION` (driver/consumer work for its later milestone). Unknown is not READY. `TEMP-I2C-CUTOVER` is a truthful allowed transitional state, never equivalent to a fully extracted I²C bus.

| Family | Capability/dependency path to account for | Distinct architectural pressure to assess |
| --- | --- | --- |
| Display / e-paper | `display.*` -> display controller ELF -> SPI/parallel/GPIO/power/clock providers as applicable | boot/recovery visibility, frame buffers/PSRAM, DMA/cache, timing, refresh and UI host as consumer rather than firmware display ownership |
| Touchscreen | `input.touch` -> touch ELF -> I²C/SPI/GPIO/IRQ/power as applicable | ISR publication, coordinate/orientation calibration, sharing display bus and revocation; eventual I²C ELF consumer |
| Networking | `network.interface` -> radio/link ELF -> applicable CPU/radio primitives; protocol services above it | Wi-Fi firmware ownership, credentials and reconnect policy, bootstrapping package download without a circular dependency |
| LoRa | `radio.lora` or versioned packet capability -> transceiver ELF -> SPI/GPIO/IRQ/clock/power | ISR/DMA, radio state, bus arbitration, packet streams and frequency/configuration confined to provider |
| GPS / GNSS | `location.*` -> GNSS ELF -> UART/power/clock provider | firmware UART/rail extraction, NMEA/receiver state, source-independent semantic publication and records |
| Other buses/peripherals | arbitrary installed capabilities -> independently installed bus/controller/child ELFs | no per-transport resolver, resource ownership, registry or packaging changes; I²C bootstrap cycle eliminated in U3 |

Resolve any **cross-family blocker in the generic loader/resolver/registry/lifecycle/stream/build/package/port-primitive path** during U1. Do NOT implement all these product drivers, broad new capability APIs, a second OS or a multi-ISA loader merely to fill the matrix; leave family-specific algorithms and consumer migrations as explicitly mapped subsequent milestones. **Do not treat full I²C controller ELF takeover as a U1 generic-platform blocker:** the authorized transitional port API is the bridge to U3's explicitly defined cutover. Where hardware inspection is unavailable, use bounded source/link evidence and tests and mark physical verification pending, not passed.

## Mandatory independent witness: prove it isn't just a USB framework

Before U1 software handoff, produce **one minimal non-USB driver/provider ELF that does not depend on the USB provider graph**, using the documented template, current generic OS/CPU import rules, a safe existing or explicitly installed board profile, generic loader/dependency graph, generic provider publication, and ordinary manager/catalog. Prefer a small GPIO input/output or I²C device path if a verified conflict-free resource exists; choose based on actual board source/hardware constraints, not an invented pin or sensor. This is a *path witness*, not an authorization to migrate the entire display/network/GNSS stack. A virtual echo-only module or ELF that forwards to firmware **device-specific hardware code** does not satisfy physical-driver ownership, although it can be an additional generic test fixture. An I²C witness ELF that genuinely performs its own peripheral probe/register logic through the documented temporary bus primitive is acceptable, but demonstrate the bus dependency honestly and record its U3 conversion; the witness must not simply proxy an existing firmware device driver.

Demonstrate at the same commit: (a) build and package the new witness with no edits to generic firmware, package-manager source, catalog/export enumeration or USB-specific scripts; (b) discover it in the generic release index; (c) install it from SD with no index and online using the common engine; (d) load/probe and publish a non-USB capability through the generic registry, use its real hardware-facing ELF path where available, and expose a minimal versioned read/write/command or event interface; (e) refuse conflicting grants, report missing/corrupt driver and remove/reinstall without fallback; (f) safely quiesce and unload or quarantine on uncertainty. Host/production-link tests establish software readiness; any physical verification joins the **same one owner hardware session** and remains PENDING until the owner runs it.

If the witness needs new `core.knows_gpio`/`core.knows_i2c`-style logic, a new hard-coded provider ID, USB catalog edits, special firmware **device** bridge, or separate installer, U1 is NOT DONE. The sole allowed exception is the already-scoped temporary I²C bus API; do not expand its surface for the witness unless the existing bounded primitive demonstrably lacks a necessary generic bus operation and the change remains minimal. Correct the general mechanism once and rerun both USB and witness regressions. A new versioned *generic* CPU/OS primitive is permissible only if demonstrably needed by multiple potential drivers; document its permissions and negative import tests and do not expose it to ordinary apps by default.

## Final U1 gates and handoff

U1 may say **DRIVER FOUNDATION SOFTWARE COMPLETE / READY FOR ONE HARDWARE TEST** only when all original U1 conditions **as modified by the owner-authorized temporary I²C exception** AND the interface inventory, complete cross-family gap ledger, template/build workflow, and independent non-USB witness above are satisfied on the same commit. The full I²C controller ELF handoff is deferred to U3, not a U1 blocker; no firmware USB device/host/class functionality is deferred. Add witness installation/activation/absence/teardown and transitional I²C single-owner failure checks to the existing *single* owner test sheet. No repeated owner tests between code units; no blocking CI wait before subsequent independent implementation; do not merge/release/flash automatically. Report software test evidence and pending hardware verification separately.

After owner hardware acceptance, each subsequent family becomes a bounded migration unit: extract its full real implementation to ELF(s), adapt consumers to semantic capabilities, supply profile/build/packaging/tests, delete its firmware hardware code and fallback, and hand off one coherent hardware test. U3 also retires the temporary I²C bus API. New generic ABI versions are allowed where hardware truly needs a new **transport-neutral** primitive, but a recurring need to edit RiscRTE for each hardware family is evidence the U1 foundation was incomplete and must be addressed as a platform defect, not normalized as device-specific migration work.
