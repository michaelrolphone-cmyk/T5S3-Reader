# Unified Package Manager — scope correction and disposition

**Historical correction from September 17, updated September 18, 2026.** The user requested one package manager, not a signed-package ecosystem. This file records why earlier PR #76 signing work was out of scope. The active normative contracts are [RISCRTE_PLATFORM_SPEC.md](RISCRTE_PLATFORM_SPEC.md), [PACKAGE_MANAGER_SCOPE_CONTRACT.md](PACKAGE_MANAGER_SCOPE_CONTRACT.md), [UNIFIED_PACKAGE_MANAGER_MVP.md](UNIFIED_PACKAGE_MANAGER_MVP.md), [RISC_PACKAGE_FORMAT.md](RISC_PACKAGE_FORMAT.md) and the [U1 completed-software milestone](NEXT_HARDWARE_TEST_MILESTONE.md). They supersede this document wherever it described PR #76 as a draft, the apps as not migrated, or an optional archive/retained experimental signature implementation.

## Original intent and delivered foundation

The objective is a source-independent ordinary package identity/format and shared inspect/install/update/uninstall/inventory/recovery system for application, driver, service and provider packages. Online and SD inputs use one engine. Bounds, path safety, explicit compatibility and version checks, SHA-256 content-integrity checks, transaction recovery and mapped-package refusal remain required. Package installation does not activate hardware or grant imports; the loader has independent generic OS/CPU symbol and execution-context permissions. Merged PRs #76/#78/#79 substantially implemented the normal engine, physical provider executor and App Store/Driver Manager integration. Full four-kind online/catalog/UI coverage and firmware USB extraction still require U1 completion.

## Explicit owner-directed disposition

Mandatory P-256/signatures, trusted publisher identities, key provisioning/revocation, signed provenance/receipts, NVS cryptographic floors, anti-rollback and signed-only load/release gates were never the requested MVP. The owner has now explicitly requested **purging their implementation from the active repo**. After auditing callers and extracting independently useful ordinary parsing, exact-file verification, staging, transactions and recovery, delete the signing-specific code, scripts, fixtures, tests, special workflow gates and experimental signed-format documentation. Git history is sufficient to retain its historical record; do not merely archive/disable the experiment or install a renamed alternative. Do not delete unrelated TLS/crypto or ordinary integrity and loader safety. Previously installed user data is preserved/read-only on unsupported signed-only input, not silently removed.

## U1 execution and acceptance

Remove special `usb-provider-catalog.json` generation/export/fetch and four-file canonical download assumptions in favor of a generic manifest-derived catalog and ordinary source adapter for all four kinds. Preserve catalog-free local inventory/activation and SD installation. Finish online/inventory/update/uninstall parity. Remove all USB-specific selection, discovery, sessions, direct stream and hardware code from compiled normal firmware and use functional installed ELFs and generic `serial.port`. Deliver the **entire** software change with builds/static and host tests and a single physical test procedure; no interim owner hardware testing or CI idle waiting. No automatic merge, publication or flash. See [U1](NEXT_HARDWARE_TEST_MILESTONE.md) for exact acceptance and source paths.

Any future expansion (especially package cryptographic authentication, incompatible format, special hardware core path or new release gate) requires a new explicit request and change contract; a roadmap idea or historic source file is not authorization.
